# 梱包ペナ ラベル・風袋計算（Python Web 版）

テスラ向けコイル梱包の **出荷ラベル発行** と **風袋（梱包資材）重量計算** を行う
ライン端末用アプリ。Excel VBA 版（.xlsm）からの移植。

---

## 1. 使い方（利用者向け）

1. **`Start.vbs`** をダブルクリックする
2. 待機画面が出たあと、ブラウザーでアプリ画面が開く
3. 終わるときは **`stop.bat`** を実行する

起動しないときは **`start.bat`**（診断起動）を実行し、表示されるメッセージを確認する。

> `Start.vbs` と `start.bat` は最終的に同じ `start_app.py` を呼ぶ。
> 違いは「コンソールを隠すか、出したままにするか」だけ。

## 5.1 Access への接続

ライン PC の Python に追加ライブラリを入れられないため、
Access へは **cscript.exe + VBScript + ADODB(COM) + ACE OLEDB** 経由で接続する。

```
Python
  └─ subprocess → cscript.exe
                    └─ VBScript (app/repositories/vbs/query_accdb.vbs)
                         └─ ADODB.Connection
                              └─ Microsoft ACE OLE DB 12.0
                                   └─ 梱包資材マスタ.accdb / テーブル 資材重量
```

接続文字列・カーソル種別は VBA と同じ
（`Provider=Microsoft.ACE.OLEDB.12.0` / `adOpenStatic` + `adLockReadOnly`）。

**設定が必要な項目**（`config/app.json`）

```json
"aim_ref_path": "\\\\サーバー名\\共有\\...",   ← 梱包資材マスタ.accdb の親フォルダ
```

これは VBA の定数 `PATH_AIM_参照` に相当する。
VBA 本体にはこの定数の定義が無く（別の共通モジュール由来）、
**実値は現場から提供を受ける必要がある**（docs/01_VBA解析書.md 13章 #9）。

未設定 / 到達不可のときは `data/資材重量.csv` へフォールバックし、
画面上部に「**CSV（検証用）**」と表示される。
CSV の値は検証用サンプルであり業務値ではない。

## 6. 設定

**画面（`/settings`）から変更できる。** 参照先フォルダー・マスタの差し替え・
出力先・動作・ポートなど。VBA ではコード内の定数に埋まっていたものを外へ出した。

設定は 2 層になっている。

| 層 | 場所 | 誰が編集するか |
|---|---|---|
| 同梱の既定 | アプリ本体側 `config/app.json` | 管理者がファイルを編集 |
| **この端末** | `%LOCALAPPDATA%\<AppId>\config\local.json` | **設定画面が書き込む** |

アプリ本体を共有フォルダーへ置いても、設定画面の保存はローカル領域だけに書くため
他の利用者へ影響しない。各項目には「どの層で決まっているか」を表示する。

**配布設定**: 1 台で決めた設定（印刷位置の補正を含む）を設定画面の「配布設定」で
書き出すと、アプリの直下に `配布設定\` ができる。フォルダーごと配ると、
配った先は起動時に**その端末に無い項目だけ**読み込む
（python-web-tools の配布設定と同じ流れ）。
同じ面の「**配布用フォルダを作る**」（または `scripts\make_dist.bat`）で、配るものだけを
新しいフォルダへ写し、配布設定と `配布メモ.txt` を入れる（python-web-tools の make_dist と同じ）。

詳細は `docs/05_設定ガイド.md`。

`config/app.json`

| キー | 意味 |
|---|---|
| `app_id` | アプリID（ローカル領域のフォルダ名・多重起動判定・health の識別子） |
| `port` | 使用ポート（既定 8731） |
| `aim_ref_path` | 梱包資材マスタ.accdb の親フォルダ（VBA `PATH_AIM_参照`） |
| `debug_print_path` | 共有ログ出力先（VBA `PATH_梱包_日報DebugPrint`） |
| `prefer_access` | `true`=Access 優先（本番） / `false`=常に CSV |
| `quick_height_width_override` | 積み高さクイック計算だけ巾を変える場合 |
| `material_refresh_sec` | 資材マスタの鮮度チェック間隔（秒）。`0` で毎回 |
| `db_idle_close_sec` | 無操作でこの秒数が過ぎたら状態DBの接続を閉じる。`0` で閉じない |
| `db_busy_timeout_ms` | 状態DBのロック待ち時間（ミリ秒） |
| `material_db_file` | 梱包資材マスタ（SQLite）。設定すると Access より優先 |
| `size_master_file` / `material_csv_file` / `kataban_csv_file` | マスタの差し替え（空欄で同梱を使用） |
| `export_dir_path` | 帳票の保存先（空欄でローカル領域の work/export） |

サイズを追加するときは **`data/size_master.json` に 1 ブロック足すだけ**。
VBA では `GetSizeConfig` / `GetCBtoPair` / `DetectSelectedOB` / 各 Click イベント /
`SetCoilDimensions` など 9 か所を直す必要があったが、移植版ではコード変更は不要。

## 7. 起動の流れ

```
Start.vbs ─┐
start.bat ─┴→ start_app.py
                ├ 1. Python バージョン確認
                ├ 2. %LOCALAPPDATA% 配下を作成、__pycache__ を退避
                ├ 3. ログ初期化
                ├ 4. 排他ロック（runtime/instance.lock）を取る
                │     取れない → もう 1 台が起動中／起動処理中
                │                応答を待って既存画面を開く（新規起動しない）
                ├ 5. 多重起動判定（launch_guard）
                │     running  → 既存画面を開くだけ（新規起動しない）
                │     starting → 応答を待つ
                │     conflict → ポートが別アプリに使われている旨を表示
                │     stale    → 残骸を掃除して続行
                ├ 6. loading.html をブラウザーで開く
                └ 7. server.py 起動 → /api/health の実応答で完了判定
```

**秒数経過だけで完了扱いにしない。**
`loading.html` は `/api/health` を叩き、`appId` が一致してから画面へ遷移する。

### 7.1 多重起動をどう防いでいるか

**3 段 + OS の最後の砦**で守っている。1 つでも抜けると 2 台目が立ち上がる。

| 段 | しくみ | これで防げること |
|---|---|---|
| 1 | `runtime/instance.lock` の **OS ファイルロック**<br>（Windows `msvcrt.locking` / POSIX `fcntl.flock`） | 判定してからポートを掴むまでの**隙間**。Start.vbs を続けて 2 回叩いても 2 台目はここで止まる。**強制終了されても OS が必ず外す**ので後始末が要らない |
| 2 | `runtime/instance.json`（PID・接続先の記録） | 状態表示と、停止時に「本当に自分のプロセスか」の確認 |
| 3 | `/api/health` の **appId 照合** | ポートが開いているだけで「自分が起動中」と誤認すること |
| 砦 | **ポートを二重に掴めない bind**（`server.ExclusiveHTTPServer`） | 判定に取りこぼしがあっても、2 台目は OS に bind を拒否される |

**Windows の `SO_REUSEADDR` に注意。**
`http.server.ThreadingHTTPServer` は既定で `allow_reuse_address = 1` になっている。
POSIX ではこれで問題ないが、**Windows の `SO_REUSEADDR` は「使用中のポートでも奪える」**
という別の意味になり、待ち受け中のポートに 2 台目が bind できてしまう。
ライン端末は Windows なので、この既定のままでは多重起動防止が成立しない。
そこで OS で振り分けている。

```
Windows … SO_REUSEADDR を使わず SO_EXCLUSIVEADDRUSE を付ける
POSIX  … SO_REUSEADDR のまま（奪えないうえ、外すと停止直後の再起動が TIME_WAIT で弾かれる）
```

いま防げているかは **診断画面（`/diag`）の「多重起動の防止」** で確認できる。
別アプリが同じポートを使っていた場合は成功と判定しない。

### 7.2 画面（タブ）の多重起動 ― **入力画面は同時に 1 つだけ**

7.1 はプロセスの話。**プロセスが 1 つでも、タブを 2 枚開けば別の事故が起きる。**

作業状態（検査番号・重量・本数・計算結果）は
**サーバー側に 1 組しか無い**（状態DB の `form_state`）。
そのため入力画面を 2 枚開くと、両方が同じ 1 組を書き換える。

```
タブA: 検番 A111111 / 11本 で計算   → 画面には A111111
タブB: 検番 B999999 / 20本 で計算   → サーバーの状態は B999999
タブA で印刷                        → B999999 の内容が刷られる
```

画面に出ている検査番号と、刷られる検査番号が食い違う。
コイルに別の検査番号のラベルが貼られるということなので、
**2 枚目を開くこと自体を断る**（`app/services/screen_guard.py`）。

| 画面 | 何枚開けるか |
|---|---|
| 指定サイズ `/` ・全サイズ `/all-size` ・設定 `/settings` | **1 つだけ。**2 枚目は覆いが出て操作できない |
| 風袋計算 `/tare` ・羅列 `/list` ・ラベル台紙 `/labels` ・計算内訳 `/breakdown` ・各印刷ビュー | **何枚でも。**状態を書き換えないため（印刷ビューは元から別タブで開く） |

しくみ

- タブごとの画面IDを `sessionStorage` に持つ（`localStorage` はタブ間で
  共有されてしまうので使わない）。
- 画面を開いたら使用権を求める。取れなければ**覆いを出したまま**にする。
- 5 秒ごとに生存を知らせる。20 秒途切れたら「閉じられた」とみなして次に譲る
  （ブラウザーが落ちても数秒で次が使える）。
- **裏に回ったタブは例外。**ブラウザーは裏のタブのタイマーを間引くため、
  裏に回る瞬間に `sendBeacon` で知らせ、その画面は 12 時間まで空きにしない。
  表に戻る・凍結から戻る・スリープから戻ると、タイマーを待たずに知らせ直す
  （`docs/04_DB運用と同時実行の確認事項.md` の ④）。
- サーバーのプロセスは心拍が途切れても止まらない（自動で止める仕組みは持たない）。
- タブを閉じるときは `sendBeacon` で即座に手放す。
- **画面側の作りに頼らない。**使用権を持たない画面からの書き換えは
  サーバーが `409` で断る。

閉じ忘れ・固まったときのために「**この画面で使う**」で引き継げる。
引き継がれた側は「この画面は使用中ではなくなりました」に変わり、操作できなくなる。

使用状況は **診断画面（`/diag`）の「入力画面」** で確認できる。

## 7.3 Windows 側のファイルで注意すること

現場で実際に起きた 3 件。Linux の自動テストでは気づけないので
`tests/test_launcher_files.py` で固定してある。

**① バッチ / VBS の文字コードは CP932 + CRLF**

`cmd.exe` と WSH は `chcp` のコードページでファイルのバイト列を解釈する。
UTF-8 のまま `chcp 932` で読ませると、日本語が化けるだけでなく
**壊れたバイト列がコマンドとして実行される**。

```
'ho' は、内部コマンドまたは外部コマンド、
操作可能なプログラムまたはバッチ ファイルとして認識されていません。
```

改行も LF 単独では `cmd` が誤動作する。
`.gitattributes` で `*.bat` `*.cmd` `*.vbs` を `-text` にし、
git に変換させないようにしてある。

**② アプリ配置フォルダーをカレントにしない**

Windows は**プロセスのカレントフォルダーを削除・改名できない**。
アプリ配置をカレントにすると、動いている間（および停止し損ねて
残っている間）フォルダーを消せず、配布の入れ替えもできない。

```
別のプログラムがこのフォルダーまたはファイルを開いているので、
操作を完了できません。
```

`Start.vbs` は `%TEMP%` を、`start_app.py` はローカル領域をカレントにする。
参照は全て自分の場所からの絶対パスなので影響しない。

**③ 起動待機画面は `file://` なので CORS が要る**

`loading.html` はサーバーが立つ前に開くので `file://` で表示する。
ブラウザーから見ると**オリジンが `null`** になり、
`Access-Control-Allow-Origin` が無いと `/api/health` の読み取りが
CORS で止められ、**待機画面が「起動完了」まで進まず固まる**。
許可を付けるのは起動確認APIだけで、業務APIには付けない。

## 7.4 起動も停止もできない、という状態を作らない

現場で「起動もしないし停止もできない」が発生した。

```
INFO    別のプロセスが起動中です（排他ロックを取得できません）
...
状態: conflict
ポート 8731 を別のアプリが使用しています。停止しません。
```

原因は 2 つ重なっていた。

**① 自分自身への接続がプロキシへ回されていた**

`urllib.request.urlopen` は Windows のプロキシ設定（IE / レジストリ）を読む。
社内 PC で除外リストに `127.0.0.1` が入っていないと、
**自分自身への `/api/health` までプロキシへ投げて失敗する**。
動いているのに「応答なし」に見え、`conflict` と誤判定されていた。

→ ループバックへは `launch_guard.local_open()` で
`ProxyHandler({})` を付けた opener を使い、必ず直接つなぐ。

**② `conflict` のとき停止が何もせずに終わっていた**

`stop` が「別のアプリが使用しています。停止しません。」で返しており、
そこから先へ進む手段が無かった。

→ `stop` は次の順に手を尽くす。

| 順 | 対象 | 確認していること |
|---|---|---|
| 1 | 正常終了の要求 | `/api/health` が自分のアプリとして応答するか |
| 2 | `instance.json` の PID | アプリID・アプリ配置・PID が生きているか |
| 3 | `instance.lock` の保持者 | ロックを**実際に取ってみて**掴まれているか確認（PID は鵜呑みにしない） |
| 4 | `stop.bat --force` | そのポートを**待ち受けている Python だけ** |

4 は `netstat -ano`（POSIX は `lsof`）で待ち受け中の PID を出し、
`tasklist` で実行ファイル名を確認してから止める。
**`python.exe` をプロセス名で一括終了することはしない。**

そして**どの経路でも最後に必ず次の一手を出す**。

```
次の手:
  ・stop.bat --force
    ポート 8731 を待ち受けている Python だけを終了します
  ・タスクマネージャーで python.exe / pythonw.exe を終了する
  ・config/app.json の "port" を空いている番号（例 8732）に変えて起動し直す
```

`start.bat` / `Start.vbs` 側も、止まったときは同じ手順を表示する。

## 7.5 起動条件の一覧（2026.09 見直し）

起動が通らない件が続いたので、入口から順に条件を洗い直した。

| # | 条件 | 満たさないとき | 利用者に見えるか |
|---|---|---|---|
| 1 | Python 3.8 以上がある | 起動中止 | **ダイアログ**（start.bat ならコンソール） |
| 2 | `%LOCALAPPDATA%` に書ける | 起動中止 | 同上 |
| 3 | カレントをローカル領域へ移せる | 警告のみ・続行 | ログ |
| 4 | 排他ロックを取れる（`instance.lock`） | 既存を待って既存画面へ。20 秒で諦め | ダイアログ＋案内 |
| 5 | `/api/health` が自分の appId で応答する | `conflict` として案内 | ダイアログ＋案内 |
| 6 | ポートを排他的に bind できる | 3 秒まで再試行 → 案内 | ダイアログ＋案内 |
| 7 | 資材マスタを読める | **CSV へ退避して続行** | ヘッダーのバッジ（赤・「古い内容」） |

**1〜6 を満たさないときは必ず止まり、必ず理由が出る。**
7 だけは止めずに続ける（ラインを止めないため）が、画面で分かるようにしてある。

### ここが一番の落とし穴だった ― 無言の失敗

`Start.vbs` は `pythonw.exe` をウィンドウ無しで起動する。このとき
`sys.stdout` / `sys.stderr` は `None` になり、

```python
print("起動できません")      # 例外も出さずに、どこにも出ない
```

**失敗が完全に無言**になる。利用者からは「ダブルクリックしても何も起きない」
としか見えない。

→ コンソールが無いときは `MessageBoxW`（ctypes、標準ライブラリのみ）で出す。
どの失敗も必ずログにも残す。

### 待機画面

- 応答待ちの上限を 90 秒 → **35 秒**。
- 12 秒で「少し時間がかかっています／`start.bat` で原因が出ます」を表示。
- `file://` の URL は `Path.as_uri()` で組み立てる
  （配置フォルダーに空白・日本語・記号が入っても壊れない）。

### 資材マスタ（ACE）

ACE は **32bit と 64bit が別物**で、`cscript.exe` のビット数が合わないと
`Provider が見つかりません` になる。Office が 32bit の端末は多い。

- 既定の `cscript.exe` で駄目なら `SysWOW64` / `Sysnative` も試す。
- プロバイダーは VBA と同じ **12.0 を先に**、駄目なら 16.0。
- 全部駄目なら、**試した経路すべての理由**を並べて出す。

## 8. 停止

`stop.bat` → `process_manager.py`

1. まずアプリ自身へ `/api/shutdown` で正常終了を要求する
2. 応答しない場合だけ、記録した PID を使う
3. 強制終了の前に、その PID が **このアプリのものか**（appId とアプリ配置パス）を確認する
4. `python.exe` をプロセス名で一括終了することはしない

## 8.5 DB の持ち方

| | 中身 | 形式 | 置き場所 | 読み書き |
|---|---|---|---|---|
| 資材マスタ | 単位質量・係数 | Access `.accdb` | 共有フォルダー | **読取専用** |
| アプリ状態 | 台紙セル・風袋結果・入力状態 | SQLite `.sqlite3` | `%LOCALAPPDATA%`（PCごと） | 読み書き |

**SQLite は共有フォルダーに置かない。** 状態は PC ごとのローカルに閉じているため、
複数 PC の書込競合は原理的に発生しない。

長時間起動したままでも問題が出ないよう、次を入れている。

- 接続は**プロセス全体で 1 本**（以前はスレッドごとに作られ積み上がっていた）
- **無操作 120 秒で接続を自動的に閉じ**、DB ファイルのハンドルを解放する
- `journal_mode=DELETE`（`-wal` / `-shm` を作らない。ネットワーク FS でも壊れにくい）
- 資材マスタは**更新日時・サイズが変われば自動で読み直す**（放置中の更新に追従）
- 取得元へ一時的に到達できないときは**直前の内容で継続**し、`/diag` に表示する

詳細と、Access→SQLite へ置き換える場合の判断材料は
`docs/04_DB運用と同時実行の確認事項.md` を参照。
