# 変更履歴(ペナラベル)

版は `app/config.py` の `APP_VERSION` ただ1つが出どころです(移植元のまま。
`config/app.json` には書きません)。

**統合版(コイル梱包ツール)では版が2つあります。** この機能の版(ここ)と、
統合ツールの版(統合アプリの `config/app.json`)です。この機能の中身(画面・計算・
印刷・DB)を変えたら**この機能の版を上げ、統合ツールの版も上げます**(配る単位は
統合ツールのため)。画面の帯の版を押すと、両方の版が並んで出ます。

## 版の上げ方

1. `app/config.py` の `APP_VERSION` を上げる
2. このファイルに1行足す(何を直したか)
3. 統合ツールの版(統合アプリの `config/app.json`)も上げる

## 1.5.8 — 失敗にエラーの番号と記録を付ける(コイル梱包ツール 1.0.12)

現場の指摘: エラー等の後追いが現状できない。なぜなぜで分析できるようにしてほしい。

1. 処理の失敗(「処理に失敗しました: …」)と画面の生成の失敗に、**エラー番号**を付けました。
   同じ番号で**エラーの記録**(何が起きたか・止まった場所・エラーまでの流れ・なぜなぜの記入欄)が
   残ります。上の帯の「ログ」で中身を見られます
2. 失敗の画面に出す文言を、伏せ字にしてから埋めるようにしました(例外の文字に送られた値が
   混ざりうるため)

## 1.5.7 — マスタ管理で列名を押すと並べ替える(コイル梱包ツール 1.0.11)

現場の指摘: マスタ管理で列名(見出し)を押して並べ替えたい。

1. 設定 → マスタ管理の表の**見出しを押すと、その列で並べ替えます。** 小さい順(▲)、
   もう一度押すと大きい順(▼)。梱包明細・資材計算のマスタ管理と同じ使い方です
2. **サーバで並べ替えます。** 出していない行(200件より後)も含めた並びです。絞り込みと
   一緒に使えます。行を直した・消したあとも並びはそのまま。表を切り替えると外れます
3. **数字は数の大きさで並べ、空はいちばん後ろ**(資材マスタは数字も文字で持つことがあり、
   文字の並びだと 10 が 9 より前へ来るため。3機能で同じ決まり)
4. 列名は実在する列だけを使います(無い列を指したら、取り込み元の並びに戻します)

## 1.5.6 — 設定の保存先を「このPC／共有」に分けて明記(コイル梱包ツール 1.0.10)

現場の指摘: このPCで引き継いで使うものと、複数のPCで共有するものは違う。設定部にそういうファイルが
あることを明記してほしい。

1. 設定(パス設定)の **「設定の保存先」** を、3機能で同じ形にしました
   - このPCに保存(このPCで引き継ぐ): この端末の設定 `local.json`(パス設定・印刷位置の補正と倍率)、
     状態DB `state.sqlite3`(指定サイズの台紙・風袋計算・50までリスト)、ログ
   - 全ラインで共有: 資材マスタ(マスタ管理の書き先)、旧 Access の資材マスタ(参照先を入れているとき・読むだけ)、
     共有ログ
   - アプリのフォルダ: 同梱の既定 `config/app.json`、配布設定
2. 設定のカードごとに札を付けました(パス設定の各カードは「このPCに保存」、マスタ管理の書き先は
   「全ラインで共有」、配布設定は「アプリのフォルダ」)
3. ラベル位置合わせの画面に、値は**このPCの設定(local.json)に保存され、次に起動したときも引き継ぐ**
   (ほかのPCは変わらない)と書きました

## 1.5.3 — HTTP の約束を移植元に戻した(コイル梱包ツール 1.0.4)

Flask へ載せ替えたときに抜けていた、移植元(`http.server` の `Handler`)の約束を戻しました。

1. **画面の経路への POST は JSON の 404**(「不明なエンドポイントです」)。以前は画面をそのまま
   返していました。本文の確かめ(大きすぎ・JSON でない)は先に行います
2. **本文の上限 1MB を、長さを名乗らない送り方(chunked)でも守ります。** 以前は `Content-Length`
   だけを見ていたので、名乗らない要求は上限なしで読んでいました
3. 静的ファイルが無いときは、案内つきの HTML の 404(「ファイルが見つかりません。」)。以前は
   統合アプリの JSON が返っていました
4. **要求を1行ずつログに残します**(移植元の `log_message`)。画面の心拍・接続確認は数秒ごとに
   来るので DEBUG に落とします。ふだんのログは移植元と同じ INFO まで(以前は DEBUG まで残して
   いた)。`start.bat --diagnostic` で DEBUG まで残ります
5. 止めるときに状態DB を閉じます(移植元の `serve()` と同じ)
6. この機能の HTTP の試験を、統合アプリに `/pena` とトークン付きで載せた形でも流します

## 1.5.1 — 印刷が見切れていたのを直した(コイル梱包ツール 1.0.1)

プリンターは紙の縁 約 4mm に刷れません。**文字・罫線・バー・目盛りを紙の端から 5mm 以上
内側に置く**決まりが、ラベル台紙では守られていましたが、次の紙面では守られていませんでした。

1. **風袋計算・羅列・全サイズ(印刷ビューと「このまま印刷」)が紙の端から刷られていた。**
   `app.css` に印刷用の `@page` が 2 つあり、後ろのラベル台紙用の「余白 0」が前の「余白 8mm」を
   打ち消していました(移植元のまま)。距離を `@page` ではなく紙の中で取るようにしました
   (梱包明細・資材計算と同じ決まり)。印刷ダイアログが「デフォルト」でも「余白なし」でも、
   紙の端から約 8mm の所に刷られます。2 枚目以降の紙の上端も同じだけ空きます
2. **位置合わせの試し刷りの文字・目盛りが紙の縁にかかっていた。** 目盛りは紙の端から 5mm の所から
   引き(位置の数字は変わりません)、紙の端に重なる 0mm・210mm の目盛りは出しません。段の見出し・
   枠の番号と座標・下の説明文も 5mm より内側へ移しました。説明文の最後の行は台紙の名前だけにして、
   右下の「10段ぶん」の見出しと重ならないようにしました。
   台紙の切れ目を示す点線の枠・段の赤い線・端からの道しるべは、紙の端と重なる位置そのものが
   意味を持つ目印なので、位置を変えていません(縁の分は刷れません)

ラベル台紙そのもの(文字・罫線・バー)の位置は変えていません。
試験: `tests/test_print_margins.py`。統合版の本物の紙面を PDF にして測る道具: `tools/print_edge_check.py`。

## 統合版への組み込み(コイル梱包ツール 1.0.0 に同梱) — 版は 1.5.0 のまま

移植元 `ViVio-Hellon/packing-pena-label-python-web` の v1.5.0 を、コイル梱包ツールの
「ペナラベル」タブとして組み込みました。**計算・入力チェック・状態DB・ラベルと印刷ビューの
紙面は変えていません。** 統合のために変えたところ:

- http.server の代わりに統合アプリ(Flask)の中で動きます。画面と API のクラスはそのまま
- 経路の前に `/pena` が付きます(画面・API・印刷ビュー・フォント)
- API に起動トークンが要ります(同じプロセスに同居する他の2機能と揃えた。画面の JS が付けます)
- 移植元は自動では止まりませんでした。統合版は画面が全部居なくなると止まりますが、
  **印刷ビューを開いた別のタブがあるあいだは止まりません**(移植元の「使っている間は
  止まらない」を守る)
- ログは統合アプリの1つのファイルに入ります
- 配布設定は統合アプリの直下の `配布設定\packing_pena_label\`(梱包明細・資材計算と同じ決まり)。
  配布用フォルダを作ると、3機能の配布設定をまとめて入れます
- 起動・停止・多重起動の判定・配布用フォルダの作成は統合アプリのもの(`Start.vbs` `stop.bat`
  `scripts\make_dist.py`)
- 統合画面で Ctrl+P を押すと、この画面が刷られます(外枠は刷られません)。
  「このまま印刷」「試し刷り」はこれまでどおり、この画面だけを刷ります
