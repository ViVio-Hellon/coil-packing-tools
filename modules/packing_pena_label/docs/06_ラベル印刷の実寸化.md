# ラベル印刷 ― Excel 台紙をどう印刷フォーマットへ持ち込むか

## 0. 結論（先に）

**Excel の行高・列幅は写さない。台紙の実寸を「データ」として外へ出し、mm 絶対配置で描く。**

| | 値 |
|---|---|
| シール台紙 | **縦 30mm × 横 105mm が 10 段 × 2 列 = 20 面**（現場提供の実寸） |
| 実装値 | **105.0 × 29.7 mm** ピッチ、原点 (0, 0) |
| 1 段目 | **ヘッダー帯**（サイズ名・検番・重量・本数/高さ/NW/GW） |
| 2〜9 段目 | ラベル **8 段 × 2 列 = 16 枚** |
| 10 段目 | 余り |
| 寸法定義 | `data/label_stock.json` |
| バーコード | SVG 自前描画（既定）／ Code39 フォント の 2 方式 |

> **なぜ 29.7mm なのか（E-1 の結論）**
>
> A4 の高さは 297mm。`30 × 10 = 300mm` は**物理的に入らない**。
> 一方 `297 ÷ 10 = 29.7mm`、`210 ÷ 2 = 105mm` はちょうど割り切れる。
> 「A4・10段・2列」という前提が成り立つ寸法は **29.7mm しかない**。
> これは市販の「A4 20面」ラベル台紙の標準寸法（105 × 29.7mm）とも一致する。
> 公称 30mm は四捨五入した呼び寸と考えられる。
>
> **1 段だけを定規で測って 29.7 と 30 を見分けるのは無理**（差 0.3mm）。
> そこで `/labels/calibration` が**全段の境目**を引くようにした。
> 10 段ぶんの合計は **297mm と 300mm で 3mm 差**になるので、
> 試し刷りを台紙に重ねれば一番下の段でズレが見える。
> ズレていた場合だけ `labelHeightMm` / `pitchYMm` を直せばよい。

## 1. Excel 台紙の作り（採寸結果）

`1.0mm×53.5mm 丈1.xlsx` を解析した結果。**実寸が判明した今は参考値**だが、
「どういう作りだったか」の記録として残す。

| 項目 | 実測値 |
|---|---|
| 既定列幅 | **1.625**（極細） |
| 既定行高 | **9.75 pt**（`customHeight=1`） |
| 個別指定の列 | C=1.375 / G,H=1.75 / N=1.625 / AM,AN=1.75 だけ |
| 結合セル | **426 個** |
| 余白 | 上下左右・ヘッダー・フッター **すべて 0** |
| 用紙 | A4 縦、**縮小 89%** |
| プリンター | EPSON LP-S180DN（用紙は規定のまま） |

**全列を極細にして結合セルで組む「方眼」方式**。
行高もシール台紙に合わせて手で詰めてある。

### ラベル 1 枚の構成（基準行 `r`）

```
r-1  P.N. | SEALING PLATE |                        ┐
r    L.C. | 検査番号 | コイル番号  |  バーコード(型番)  │ 4行
r+1  P    | 型番                  |  I(r-1):AD(r+2)  │
r+2  Q    | 重量 | kg             |                  ┘
r+3  ┌ バーコード(検番) B(r+3):AD(r+6) ────────────┐ ┐ 4行
r+6  └──────────────────────────────────────────┘ ┘
```

左面 = 列 B〜AD（2〜30）／右面 = 列 AH〜BJ（34〜62）／間の AE〜AG が余白。

### 行方向は厳密に採れた

行高は pt 指定なので換算に曖昧さがない（1pt = 25.4/72 mm）。

| 項目 | 89% 適用後 |
|---|---|
| ラベル高さ | **24.49 mm**（8 行 × 9.75pt） |
| 1 ページ | 8 段 × 左右 2 面 = **16 枚** |
| 全体 | A4 **2 ページ** = 32 枚 |

**ただし段の間隔が一定でない。**

```
29.43 / 29.43 / 28.96 / 28.96 / 28.02 / 28.73 / 28.73 mm
```

最大 1.41mm の開き。2 ページ目の開始位置も 1 ページ目と違う（25.70mm / 6.53mm）。

これについては現場から

> **エクセルシートの段の間隔が一定でないのは、シールの範囲内に入ればいい
> ぐらいの感覚です**

との回答を得た。**つまり歪みは仕様ではなく手調整の跡**であり、
写す必要はない（写せば歪みごと引き継ぐことになる）。
平均 **28.90mm** は実寸 29.7mm と 0.8mm ずれるが、
これは「シールの範囲内」に収まっていた範囲のばらつきと解釈する。

### 列方向は確定できなかった

列幅は「既定フォントの数字の最大幅（MDW）が何文字ぶんか」で保存される。
このシートのフォントは **游ゴシック 11**。
MDW を 7px と置くと 62 列の合計が A4 幅（210mm）に収まらず、
A4 幅に収まると仮定すると MDW が 5.76px という中途半端な値になる。

→ **ファイルだけからは列の mm を確定できない。**
LibreOffice での実測も試みたが、この環境では変換が動かなかった。

**→ 実寸 105mm が判明したため、この問題は解消した。**
`210 ÷ 2 = 105mm` ちょうどで、Excel からの逆算は不要になった。

## 2. 面付けの構造

`data/label_stock.json` の `grid` がすべてを決める。

```
       0mm                105mm               210mm
  0mm  ┌───────────────────────────────────────┐ ┐
       │  ヘッダー帯（用紙幅いっぱい）              │ │ headerRows = 1
       │  サイズ名 / 検番 / 重量 / 本数高さNW GW表  │ │ 29.7mm
 29.7  ├───────────────────┬───────────────────┤ ┘
       │  ラベル 1         │  ラベル 9         │ ┐
 59.4  ├───────────────────┼───────────────────┤ │
       │  ラベル 2         │  ラベル 10        │ │ labelRows = 8
       │        …          │        …          │ │ 8 × 29.7 = 237.6mm
       │  ラベル 8         │  ラベル 16        │ │
267.3  ├───────────────────┴───────────────────┤ ┘
       │  （10段目・余り）                       │
297.0  └───────────────────────────────────────┘
```

- `29.7 × 10 = 297.0mm` = A4 の高さ **ちょうど**
- `105.0 × 2 = 210.0mm` = A4 の幅 **ちょうど**
- 1 ページ **16 枚**。Excel 台紙の「ヘッダー 3 行 + ラベル 8 段」と同じ構造

### ラベルの情報欄（P.N./L.C./P/Q）

Excel は **縮小 89%** で刷っていたため、印刷された情報欄は
**23.5 × 12.24mm**（4 行 × 9.75pt × 0.89）。旧レイアウトの 29 × 12.85mm は
現場が Excel の印刷と透かして比べて **大きい** と確認したので、Excel の大きさに合わせた。
左端はラベル端から **7mm**（刷れない縁を避け、やや中央寄り）。
バーコードは Excel ときれいに重なっていた（現場確認）ので動かしていない。

### ラベルの罫線

実物のラベルと同じ格子を引く。

```
┌──────┬──────────┬────────┐
│ P.N. │ SEALING PLATE     │
├──────┼──────────┬────────┤
│ L.C. │ Z987654  │ -0201  │
├──────┼──────────┴────────┤
│ P    │ BJB7610400QR      │
├──────┼──────────┬────────┤
│ Q    │    22.0  │ kg     │
└──────┴──────────┴────────┘
```

`rules[]` に**線分**（`x1,y1,x2,y2`）で持つ。セルごとに枠線を付けると
隣り合う辺が二重になって太さが変わるため、線分で指定する。
太さは `grid.ruleMm`（既定 0.2mm）、文字と線の間隔は
`grid.cellPadMm`（既定 0.6mm）。

### ヘッダー帯の中身

現場から提示された内容をそのまま入れている。

1 段目は **105mm のシール 2 枚**。真ん中の切れ目（105mm）をまたがないように、
左のシールにサイズ名・検番・重量、右のシールに表を置く。

```
 左のシール（6〜94mm）            │ 右のシール（110〜200mm）
 0.8mm×53.5mm 　丈2               │          本数   高さ    NW     GW
 検番 Z987654  重量丈2  22.0 kg   │ 1梱包目   11   910.0  242.0  279.0
                                  │ 2梱包目   11   910.0  242.0  279.0
```

| 表示 | 出どころ |
|---|---|
| サイズ名 | 選択中のサイズ（`cfg.size_cell_label`） |
| 検番 | 入力された検査番号 |
| 重量丈n | 丈 1 / 丈 2 のどちらか |
| 重量 | 入力された重量 |
| 本数 / 高さ / NW / GW | **風袋計算の結果**（`CalculateMaterials`）を梱包ごとに |

ヘッダーは**ブロック（1 コイル分）の各シート先頭に繰り返す**。
1 コイルで 17 枚以上になっても、2 枚目のシートに同じヘッダーが付く。

> **変更（2026.09.25）**: ヘッダー帯の **範囲囲いの罫線は消す**（現場の求め）。
> それまでは本数・高さ・NW・GW の表と、検番・重量の欄を囲んでいた
> （2026.09 の確定）。`headerRules[]` は空にしてある。
> ラベル本体の P.N./L.C./P/Q の格子は Excel と同じく残す。

### 入力が変わっている間は印刷できない

ヘッダー帯の **本数・高さ・NW・GW** は「計算」でしか書き換わらない（VBA と同じ）。
一方 **検番・重量** は「重量反映」で書き換わるため、
入力を変えて反映だけして刷ると**別々のコイルの値が混ざったラベル**になる。

そのため、計算に使った入力と現在の入力が食い違っている間は

- 印刷ボタンを **無効**にする
- 台紙一覧の印刷リンクを **出さない**
- **ブラウザーの印刷（Ctrl+P）でもシートを出さず**、理由だけを紙に出す

「計算」を押し直せば元どおり印刷できる。**計算結果は変えていない。**
詳しくは `docs/03_不明点と要確認事項.md` の A-6。

## 3. バーコード ― 2 方式から選べる

現場では **K's BarCodeFont Code39** で表示している。
移植では次の 2 方式を用意し、設定 `barcodeMode` で切り替える。

### (a) SVG 自前描画（`barcodeMode = svg`、**既定**）

`services/barcode39.py` が Code 39 のバーを SVG で描く。

- **フォント導入が不要**（ライン PC に入れて回る手間がない）
- 字形差・バージョン差でバー幅が変わらない
- 静止帯（クワイエットゾーン）を確実に確保できる
- 表せない文字（全角など）はエラーで気付ける

### (b) フォント表示（`barcodeMode = font`）

`assets/fonts/` に置いた Code39 の TTF を `/fonts/` で配信し、
`@font-face` で読み込んで **Excel と同じ字形**で出す。

- **現行と字形が完全に一致する**ので、読取機の実績をそのまま引き継げる
- ただし**フォント本体はリポジトリに含めていない**（再配布条件が不明なため）。
  `assets/fonts/README.md` の手順で配置する
- 未配置のまま `font` にすると、印刷画面の先頭に**赤い警告**が出る

> どちらでも VBA が作る**文字列は同一**（`*BJB7606500QR*` / `*W111111-0101 10*`）。
> `*` は Code 39 のスタート/ストップ記号。SVG 描画時は中身を符号化し、
> **バーの先頭と末尾に `*` の模様を必ず付ける**（`_elements`。テストで先頭・末尾の模様を確かめる）。
> 読取機が返すのは `*` を含まない中身（Excel のバーコードフォントと同じ）。
>
> **バーの下の文字も `*` で挟んで出す**（`*BJB7606500QR*`）。現場から
> 「バーコードにする文字列は * で挟む。出荷先の求めと思われる」との指定（2026.09.25）。
> 文字の大きさは 3.0mm（`textSize`、旧 2.2mm）。

| 種類 | 文字列 | 位置 |
|---|---|---|
| 型番 | `*BJB7606500QR*` | ラベル右上 |
| 検査番号 | `*W111111-0101 10*` | ラベル下段（全幅） |

検番バーコードには `-` と半角空白が入るが、どちらも Code 39 の文字集合に含まれる。

### 読み取れる形になっているかの確認

実機の読取機での確認はまだできていない（**E-5**）が、
机上で確かめられることは確かめてある。

**1. 描いたバーを読み戻せること**

符号表で組み立てた結果を同じ符号表で読み直しても循環した検算にしかならないので、
**SVG の矩形の座標と幅**（＝紙に出る形そのもの）から読み直している。

```
*BJB7610400QR*        枠 71.5 / 101.0 / 30.0mm  → すべて元の文字列に一致
*Z987654-0201 22.0*   〃
*W111111-0101 10*     〃
*0123456789*  *ABCDEFGHIJKLMNOPQRSTUVWXYZ*  *-. $/+%*   〃
```

**2. バーの太さと静止帯**

| | 型番（71.5mm枠） | 検番（101mm枠） | 目安 |
|---|---|---|---|
| 細バー | **0.322mm**（12.7mil） | **0.343mm**（13.5mil） | 0.19mm 以上／0.25mm 推奨 |
| 静止帯 | **3.22mm** | **3.43mm** | 細バーの 10 倍 かつ 2.54mm 以上 |

> **静止帯は当初 2.54mm 固定で、規格を満たしていなかった。**
> Code 39 の要求は「細バーの 10 倍 **かつ** 2.54mm 以上」で、
> このラベルでは 3.2〜3.4mm 必要。静止帯不足は読み取れない原因として
> 最も多いものの一つなので、枠幅から計算するように直した。
>
> 静止帯を広げると細バーが細くなり、細バーが細くなると必要な静止帯も狭くなる
> ―― 循環するので解いてある: `静止帯 = 10W ÷ (要素数 + 20)`（下限 2.54mm）。

**3. フォント方式の伸縮**

バーコードフォントは字形の縦横比が固定なので、文字サイズだけで合わせると
**枠の半分ほどしか使えず**、細バーが 0.2mm を切っていた（71.5mm の枠に 37mm）。

TTF の `hmtx` から送り幅を読み、**横方向だけ引き伸ばして**枠幅いっぱいに使う。
横だけの伸縮は**太いバーと細いバーの比を変えない**ので、読取機から見た符号は同じまま
バーだけが太くなる。実測で 71.5mm 枠に 63.8mm（静止帯 3.9mm）まで使えるようになった。

## 4. 使い方

| URL | 用途 |
|---|---|
| `/labels/print?ob=5` | 実寸の印刷ビュー |
| `/labels/print?ob=5&guides=1` | ラベル枠を表示して位置を確認 |
| `/labels/calibration` | **位置合わせ（試し刷り）** |
| `/labels/sheet?ob=5` | 内容確認用の一覧（実寸ではない） |

### 位置合わせの手順

**プリンターごとに 1 回だけ。** 毎回やるものではない。
ずれはプリンター固有の癖（紙送りの位置・刷れない縁）で決まった量なので、
一度入れれば以後の印刷はすべてその位置になる。値は端末に保存され、
同じ機種のプリンターを使う端末へは **配布設定** で配れる（`docs/05_設定ガイド.md`）。

`/labels/calibration` の画面で完結する（設定画面へ行く必要はない）。

1. 「試し刷り」で 1 枚刷る（普通紙に刷って台紙と重ね、透かして見る）
2. 点線の枠がラベルの切れ目から **どっちへ何 mm** ずれているか測る
3. 「印刷が [左] へ [2.5] mm ずれている」「[上] へ [1.5] mm」のように入れて「直す」
   → 入れた量だけ逆向きへ動かして刷るようになる（左へずれている → 右へ動かす）
4. もう一度刷って確認。0.5mm ほど残ったら「少しずつ動かす」の矢印で詰める

画面の上に **いまの状態を言葉で** 出す（例「いまは 右へ 2.5mm・下へ 1.5mm ずらして刷っています」）。
数値（X +2.50mm）ではどっちへ動いているのか分からないため。

**大きさそのものが合わない（下の段ほどずれが大きくなる）とき**だけ、
「大きさそのものが合わないとき」を開き、試し刷りの **青い線**（100.0mm のはず）と
**赤い十字**（紙の端から 20.0mm のはず）を測って入れる。
倍率と位置はこちらで計算して保存する（`app/services/label_align.py`）::

    実測 = P×(補正 + 設計値×現在倍率) + O     P=ブラウザー側の倍率 / O=原点ズレ
    新しい倍率 = 現在倍率 × 100 ÷ 実測（青い線）
    新しい補正 = 現在補正 + 設計mm×現在倍率 − 実測mm×新しい倍率

**試し刷りは補正を掛けた状態で刷る。** 補正の外に目盛りを置くと、
補正を変えても試し刷りの見た目が変わらず「効いていない」と誤解する。

### 印刷画面（プリンターを選ぶ画面）は触らない

**何も変えずに「印刷」でよい。毎回「詳細設定」を開く必要はない。**
現場の Edge / Chrome では、倍率 **「実際のサイズ」**・余白 **「なし」** が最初から選ばれている
（現場確認）。印刷ページが `@page{size:A4; margin:0}` で A4 ちょうど・余白 0mm を指定しており、
はみ出しも無いため（`tools/smoke_all.py` の「印刷時に A4 からはみ出さない」で毎回確かめる）。

- 倍率を「ページに合わせる」などへ **変えてしまった** ときだけ「実際のサイズ」に戻す。
- プリンター側の「用紙に合わせて拡大／縮小」が入っていると縮む。プリンターの設定で切る。

### 刷れない縁（プレビューでは収まっていても刷ると欠ける）

プリンターは **紙の縁 約 4mm に刷れない**。プレビューは紙の端まで描くので気付けない。
旧レイアウトはヘッダー帯の GW 列が 207mm まで、左列ラベルの情報欄が 2mm から始まっており、
**刷ると欠けた**（現場報告）。

→ 文字・罫線・バーコードのバー（白い静止帯は除く）は **紙の端から 5mm 以上内側** に置く
（`grid.safeMarginMm`）。`label_sheet.ink_outside_safe_area()` が用紙上の位置に直して確かめ、
`tests/test_label_print.py` の `TestPrintableArea` で毎回見る（旧レイアウトでは 41 か所見つかる）。


**段ピッチの確認（E-1）**

試し刷りには**全段の境目**が赤い線で入っている。台紙に重ねて
**一番下の段**が合っているか見る。1 段ずつのズレは小さくても、
10 段ぶんでは合計になって見えるため、これで段ピッチが正しいか分かる。

| 段ピッチ | 10 段ぶん | A4(297mm) に | 
|---|---|---|
| **29.7mm**（既定） | 297.0mm | ちょうど収まる |
| 30.0mm | 300.0mm | **3mm はみ出す** |

> プリンター側の「用紙に合わせて拡大／縮小」はオフにすること。
> これが入ると倍率が勝手に変わり、実寸が出ない。

### 設定項目（`/settings` の「ラベル印刷」）

| キー | 内容 |
|---|---|
| `label_stock_file` | 台紙の寸法定義（空欄で同梱の `data/label_stock.json`） |
| `label_stock_id` | 定義ファイルに複数ある場合の選択 |
| `label_offset_x_mm` | 印刷位置の補正 X（mm） |
| `label_offset_y_mm` | 印刷位置の補正 Y（mm） |
| `label_scale_pct` | 印刷倍率（%） |
| `barcode_mode` | `svg`（自前描画）/ `font`（Code39 フォント） |
| `barcode_font_family` | フォント名（既定 `K's BarCodeFont Code39`） |

### 台紙寸法を変えたいとき

`data/label_stock.json` を書き換えるだけで、**コード変更は不要**。

| 変えたいもの | いじる場所 |
|---|---|
| 台紙のピッチ・ラベル寸法 | `grid.pitchXMm` / `pitchYMm` / `labelWidthMm` / `labelHeightMm` |
| ヘッダー帯を使わない | `grid.headerRows` を 0、`labelRows` を 10 |
| 1 ページの枚数 | `grid.cols` / `labelRows` |
| ラベル内の項目配置 | `fields[]`（x/y/w/h はラベル左上からの mm） |
| ヘッダー帯の項目配置 | `headerFields[]`（x/y/w/h は帯の左上からの mm） |

別の台紙を使う場合は `stocks[]` に追加して `label_stock_id` で選ぶ。
