# 設定ガイド ― ファイルパスの変更

> **コイル梱包ツール(統合版)で使うとき**: 使用ポートはコイル梱包ツールの `config/app.json` で
> 決まり、この画面にはありません(`PPL_PORT` も使いません)。配布設定の置き場所は
> コイル梱包ツールのフォルダの `配布設定\packing_pena_label\` です。

VBA では参照先が **コード内の定数**（`PATH_AIM_参照` など）や各所のリテラルに
埋め込まれており、現場ごとに変えるには VBE を開いて該当行を探す必要があった。
移植版では設定として外へ出し、**画面（`/settings`）から変更できる**。

---

## 1. 設定は 2 層

| 層 | 場所 | 誰が編集するか | 優先度 |
|---|---|---|---|
| **同梱の既定** | アプリ本体側 `config/app.json` | 管理者がファイルを直接編集 | 低 |
| **この端末** | `%LOCALAPPDATA%\<AppId>\config\local.json` | **設定画面が書き込む** | 高 |

適用順（後のものが勝つ）:

```
コード内の既定値
  → config/app.json      （同梱の既定）
  → local.json           （この端末だけの上書き）
  → 環境変数              （診断・検証用: PPL_PORT / PPL_AIM_PATH / PPL_PREFER_ACCESS）
```

**なぜ分けるか。** アプリ本体は共有フォルダーへ置かれることがある。
そこへ設定画面から書き戻すと、(1) 書込権限が無くて失敗する、
(2) 他の利用者の設定まで変わってしまう。
そのため **設定画面の保存先は常にローカル領域**にしている。

設定画面では各項目に **どの層で決まっているか**（`既定値` / `同梱の既定` / `この端末` /
`環境変数`）をバッジで表示する。「どこで決まっているのか分からない」を防ぐため。

### このPCに残るもの・全ラインで共有するもの(1.5.6)

設定(パス設定)の **「設定の保存先（このPC／複数のPCで共有）」** に、実際のファイルの場所が出ます。
各カードの見出しの札(「このPCに保存」「全ラインで共有」「アプリのフォルダ」)でも分かります。

| 分け | ファイル | 中身 |
|---|---|---|
| **このPCに保存**(このPCで引き継ぐ) | この端末の設定 `local.json` | パス設定で保存した値・印刷位置の補正と倍率(位置合わせで入れた値) |
| | 状態DB `runtime\state.sqlite3` | 指定サイズの台紙の入力・風袋計算の結果・50までリスト・画面の入力の途中 |
| **全ラインで共有** | 資材マスタ(SQLite) | マスタ管理の書き先。直すと次の計算からほかのPCにも効く |
| | 旧 Access の資材マスタ(参照先フォルダーを入れているとき) | 読むだけ |
| **アプリのフォルダ** | 同梱の既定 `config/app.json`・配布設定 | 全員に配る既定値・書き出した設定 |

「このPCに保存」は、閉じても、新しい版に入れ替えても残り、次に起動したときに引き継ぎます。
ほかのPCへは移りません。資材マスタの**どこを見るか**という設定も「このPCに保存」です。

## 2. 変更できる項目

### 参照先（外部ファイル）

| 項目 | VBA での対応 | 備考 |
|---|---|---|
| **資材マスタの参照先フォルダー** | 定数 `PATH_AIM_参照` | 直下に `梱包資材マスタ.accdb` が必要。空欄だと CSV（検証用）で動作 |
| 共有ログの出力先フォルダー | 定数 `PATH_梱包_日報DebugPrint` | 空欄ならローカルの `logs` のみ |

### マスタの差し替え

| 項目 | 既定 | VBA での対応 |
|---|---|---|
| サイズ構成マスタ（JSON） | 同梱 `data/size_master.json` | `GetSizeConfig` |
| **梱包資材マスタ（SQLite）** | 未設定 | Access からの移行先。**設定すると Access より優先** |
| 資材マスタ CSV（Access の代替） | 同梱 `data/資材重量.csv` | ― |
| 型番マスタ CSV | 同梱 `data/型番.csv` | `型番` シート |

空欄なら同梱のものを使い、**実際に使われるパスを画面に表示**する。

### 資材マスタの取得元の優先順

```
1. SQLite   material_db_file が設定され、ファイルが実在するとき（読取専用で開く）
2. Access   aim_ref_path の直下に 梱包資材マスタ.accdb があり、cscript が使えるとき
3. CSV      上記が使えないとき（検証用）
```

どれを読んだかは画面右上に **SQLite / Access(ACE) / CSV（検証用）** と表示する。
`/settings` の「資材マスタへの接続を試す」で、保存前に確認できる。

### ラベル印刷

| 項目 | 既定 | 意味 |
|---|---|---|
| ラベル台紙の寸法定義（JSON） | 同梱 `data/label_stock.json` | 台紙の面付け。**別の台紙に替えるときはここ** |
| 使う台紙の id | `a4-20men-105x297` | 定義ファイルに複数あるときの選択 |
| バーコードの出し方 | `svg` | `svg`＝自前描画（フォント不要）／ `font`＝Code39 フォント |
| バーコードフォント名 | `K's BarCodeFont Code39` | `font` のときに使う名前 |
| 印刷位置の補正 X（mm） | 0 | 右へずらすなら + |
| 印刷位置の補正 Y（mm） | 0 | 下へずらすなら + |
| 印刷倍率（%） | 100 | `100 × 100 ÷ 実測mm` |

既定の台紙は **105 × 29.7mm が 2 列 × 10 段（A4 ちょうど）**。
1 段目がヘッダー帯、2〜9 段目がラベル 16 枚。

補正値の決め方は `/labels/calibration` の試し刷りによる。
手順は `docs/06_ラベル印刷の実寸化.md` を参照。

> `font` を選ぶ場合は `assets/fonts/` に Code39 の TTF を置くこと。
> 置いていないと印刷画面の先頭に赤い警告が出る（フォントは同梱していない）。

### 出力先

| 項目 | 既定 |
|---|---|
| 帳票の保存先フォルダー | ローカル領域の `work/export` |

### 動作

| 項目 | 既定 | 意味 |
|---|---|---|
| Access を優先して読む | オン | オフで常に CSV（検証時） |
| Access 読取のタイムアウト（秒） | 60 | `cscript` 経由の読取を打ち切るまで |
| 資材マスタの鮮度チェック間隔（秒） | 300 | 0 で毎回。業務中の更新に追従するための設定 |
| 状態DB の接続を閉じるまでの無操作時間（秒） | 120 | 0 で閉じない |

### 起動（変更後に再起動が必要）

| 項目 | 既定 |
|---|---|
| 使用ポート | 8731(単体版のみ。統合版はコイル梱包ツールの config/app.json) |
| 状態DB のロック待ち時間（ミリ秒） | 15000 |

> `アプリID` はローカル領域のフォルダー名・多重起動の判定・`/api/health` の
> 識別子に使うため、**画面からは変更できない**。
> 変更すると保存済みの状態が別の場所を指してしまうため、
> 必要な場合は `config/app.json` を管理者が編集する。

## 3. 画面の使い方

1. ヘッダーの **「設定」** を開く
2. 値を入れる
3. **「資材マスタへの接続を試す」** で、保存せずにその場で読めるか確認できる
   - Access 参照先・cscript が使えるか・CSV 代替・読めた件数・不足資材を表示
4. **「保存する」**
   - 再起動が必要な項目を変更した場合は、その旨を表示する
   - 再起動が不要な項目は **その場で反映**（資材マスタの参照先・サイズ構成マスタ・
     型番マスタ・状態DB のアイドル解放）
5. 元に戻したいときは **「この端末の設定を消して同梱の既定へ戻す」**

### パスが見つからない場合

**保存自体は成功し、警告として表示する。**
共有フォルダーが一時的に落ちている間も設定はできるべきだからである。
画面には赤で「見つかりません」と出るので、復旧後に再確認すればよい。

`資材マスタの参照先フォルダー` だけは、フォルダーの実在に加えて
**直下に `梱包資材マスタ.accdb` があるか**まで確認する。
フォルダーは合っているのにファイル名が違う、という取り違えを拾うため。

## 4. 配布時の手順

### 配布設定（画面で決めた設定を、配った先でそのまま使う）

`ViVio-Hellon/python-web-tools` の「配布設定」と同じ流れ
（`app/services/distribution.py`）。

1. 1 台で起動して設定する（参照先・**印刷位置の補正**など）
2. 設定画面 → **配布設定** の面で、入れる項目を選んで「配布設定を書き出す」（合言葉）
3. コイル梱包ツールのフォルダーの `配布設定\packing_pena_label\` ができる
   （`設定.json` と `はじめに読む.txt`）
4. アプリのフォルダーごと配る
5. 配った先は**起動したときに読み込む**

| 決まり | 内容 |
|---|---|
| 書き出すもの | **この端末で値を入れた項目だけ**（画面で太字）。既定のままの項目は入れない |
| 既定で入れない | 使用ポート（端末で別のアプリと取り合うことがあるため） |
| 起動時の読み込み | その端末に**すでにある項目は読まない**（上書きしない）。無い項目だけ埋める |
| 揃えたいとき | 設定画面の「配布設定を読み込み直す」（合言葉）。すでにある項目も上書き |
| 値が壊れていたら | その項目だけ読まない（起動は止めない） |
| 合言葉 | 書き出す・読み込み直す・消すに必要。起動時の読み込みには不要 |

`配布設定\` は配る人がその場で書き出すもので、ソースではない（`.gitignore` で除外）。

### 配布用フォルダを作る（python-web-tools の make_dist の移植）

設定画面 → **配布設定** の「配布用フォルダを作る」（合言葉）か、
`scripts\make_dist.bat`（`python scripts\make_dist.py`）。中身は `app/services/dist_folder.py`。

| 決まり | 内容 |
|---|---|
| 入るもの | アプリ本体（`app` `config` `data` `assets` `docs` `scripts`・起動/停止の bat/vbs）と、あれば同梱の Python（`runtime`） |
| 入らないもの | `tests` `tools` `.git` `__pycache__`・`*.sqlite3`（マスタの写しなど）・ログ・起動中の印（`instance.lock/json`）・`config/local.json` |
| 配布設定 | 「配布設定を入れる」で、**書き出した 配布設定\ をそのまま入れる**（`--no-settings` で入れない） |
| 配布メモ.txt | 版・中身の指紋・入れた配布設定・配った先ですることを書く（メモ帳で開ける） |
| 既定の置き場所 | アプリの隣に `PackingPenaLabel_v版` |
| 作り直し | 前に作った配布用フォルダ（配布メモ.txt があるもの）**だけ**消して作り直す。打ち間違えた場所は消さない |

python-web-tools と違い、端末ごとの設定・作業状態は `%LOCALAPPDATA%\PackingPenaLabel` にあるので、
**版を入れ替えるときに古いフォルダから写すものは無い**。`data\` は同梱のマスタ・台紙定義なので配る。

確かめたこと: 配布設定を置いたアプリから配布用フォルダを作り、**そのフォルダから何も設定していない端末で起動**して、
配布設定が読み込まれ（ログに「配布設定を読み込みました」）、印刷補正が効き、中身の指紋が元と同じであること。

### 同梱の既定（config/app.json）を直す場合

1. アプリ一式を配置する（共有フォルダーでも可）
2. `config/app.json` の `aim_ref_path` に **資材マスタの参照先**を書く
   ```json
   "aim_ref_path": "\\\\サーバー名\\共有\\AIM参照"
   ```
   （JSON なのでバックスラッシュは 2 つ重ねる）
3. 端末ごとに違う値が必要な場合だけ、その端末の設定画面から変更する

> 同梱の既定を書き換えても、**すでに端末側で上書きしている項目はそのまま**になる。
> 全端末を同梱の既定へ揃えたいときは、各端末で「同梱の既定へ戻す」を実行する。

## 5. ファイルを直接編集する場合

`local.json` の例:

```json
{
  "aim_ref_path": "\\\\サーバー名\\共有\\AIM参照",
  "material_refresh_sec": 0,
  "port": 8732
}
```

- 書き換えたら**再起動**すると確実に反映される
- 壊れた JSON を置いても**起動は止まらない**（無視して同梱の既定で動く）
- 保存のたびに `local.json.bak` を 1 世代残す
- このファイルを削除すると同梱の既定へ戻る

## 6. 設定項目を増やすとき

`app/services/settings.py` の `SETTINGS` に 1 行足すだけで、
**画面・検証・保存・層の表示まで自動的に対応する**。

```python
SettingSpec(
    key="new_key",                 # Config のフィールド名と同じにする
    label="画面に出す名前", kind="dir",   # dir / file / text / bool / int
    group=GROUP_REF,
    help="説明",
    default_hint="空欄のときに使われる値",
    restart=False,                 # 再起動が必要なら True
),
```

`app/config.py` の `Config` に同名のフィールドを足しておくこと
（テスト `test_settings.py::test_every_setting_maps_to_a_config_field` が検出する）。
