# 変更履歴

版は `config/app.json` の `version` ただ1つが出どころです。
帯の右肩のバッジ・設定の「このアプリについて」・`/api/health` は
すべてこの値を読んでいるので、**ここを直せば全部が揃います**。

## 版の上げ方

1. `config/app.json` の `version` を上げる
2. このファイルに1行足す(何を直したか)
3. **統合ツールの版(統合アプリの `config/app.json`)も上げる**(統合版)
4. 起動し直して、帯のバッジが新しい番号になったことを見る

**統合版(コイル梱包ツール)では版が2つあります。** この機能の版(ここ)と、
統合ツールの版(統合アプリの `config/app.json`)です。この機能の中身(画面・計算・
印刷・DB)を変えたら**この機能の版を上げ、統合ツールの版も上げます**(配る単位は
統合ツールのため)。画面の帯の版を押すと、両方の版が並んで出ます。

番号は「メジャー.マイナー.パッチ」の数字3つだけです。
`1.0.0-rc1` のような書き方をすると、設定画面に
「版の書き方が違います」と出ます(起動は止めません ──
止めてしまうと、版を直すための画面にも入れなくなるため)。

| どこを上げるか | いつ |
| --- | --- |
| メジャー | 現場の手順が変わる。操作を覚え直す必要がある |
| マイナー | できることが増える。手順はそのまま |
| パッチ | 直しただけ。見た目も手順も変わらない |

## なぜ版を目立つところに出すのか

現場の端末へはフォルダごと写して配ります。写した日がばらつくので、
端末ごとに違う版が動いていることがあります。
「直したはずの不具合が出る」と言われたときに最初に確かめるのが版で、
**電話越しに答えられないと話が噛み合いません**。
そのため、どの画面にいても帯の右肩に出しています。

置き場所やポートまで要るときは、バッジを押すと
設定の「このアプリについて」へ飛びます。

## 履歴

### 0.2.5

現場の指摘で文字の大きさを直した版(コイル梱包ツール 1.0.6)。

- 帯の **ライン・担当者** の選択の文字を、計算画面の入力欄と同じ 18px にした(小さくて読みにくかった)
- 設定の **取り込み元の置き場所** の欄の文字が 10px だったのを、本文の大きさ(15px)にした。
  区画(`.sec`)に、表の升に使う別の部品の指定(10px・薄い色・はみ出しは切る)が掛かっており、
  入力欄がそれを受け継いでいた(移植元から)。区画ではこの指定を打ち消した

### 0.2.4

統合画面を閉じてすぐ開き直すと断られることがあったのを直した版(コイル梱包ツール 1.0.5)。

- **帳票などの別タブを開いたまま統合画面を閉じ、すぐ開き直すと「すでに別の画面で開いています」と
  断られた**(60秒たつか「この画面で使う」を押すまで)。タブを閉じると「閉じた」と「裏に回った」の
  合図が別々に届き、統合画面の中では「閉じた」が先に届くことがあります。後から届いた「裏に回った」の
  合図で、閉じたタブが受付を取り直していました。**裏に回った合図では受付を取らない**ようにしました
  (裏から前に戻ったときの心拍で取ります)

### 0.2.3

ログの置き場所と、統合画面の中の「このタブを閉じる」を直した版(コイル梱包ツール 1.0.4)。

- **環境変数 `COIL_TOOL_LOG_DIR` を見なくなりました。** 統合版のログは3機能とも統合アプリのログに
  入るので、この変数では「このアプリについて」の表示だけが変わっていました。表示も実際の場所に
  しました。残っていれば起動ログで知らせます(変えるときは `COIL_PACKING_TOOLS_LOG_DIR`)
- 「すでに別の画面で開いています」の「このタブを閉じる」を、統合画面の中では出しません。
  iframe からは閉じられず、そのタブを閉じると梱包明細・ペナラベルまで閉じるためです
  (単体で開いたときは従来どおり)
- (統合アプリの側で直したこと)起動ログに設定ファイルの読み込み失敗と手元の領域をまた残し、
  起動の前に手元の領域に書けるかを確かめます。この機能の Web の試験を、統合アプリに
  `/material` で載せた形でも流します

### 0.2.2

帯の「終了」と「このアプリについて」を統合版に合わせた版(コイル梱包ツール 1.0.3)。

- **帯の「終了」が断られても「終了しました」と出ていた。** 取り込みの途中なら断り、理由を
  出します(統合アプリの「終了」と同じ決まり。取り込みの途中で止めるとDBが中途半端に残る)。
  統合画面の中では「3つの機能とも終わります」と確かめ、止まったら統合画面の外枠も
  「終了しました」を出します
- 「このアプリについて」のポートとアプリのフォルダを、統合アプリのものにしました
  (機能の `config/app.json` のポートは使われないので、「8740 (設定は 8733)」と
  繰り上がったように見えていた)。機能のコードのフォルダは `module_root` に出します
- 説明書(`docs/はじめに読む_起動と使い方.md`)に、統合版の起動・置き場所を書き足しました

### 統合版への組み込み(コイル梱包ツール 1.0.0 に同梱) — 版は 0.2.0 のまま

移植元 `ViVio-Hellon/packing-material-calculation-python-web` の 0.2.0 を、コイル梱包ツールの
「資材計算」タブとして組み込みました。**計算・入力チェック・DB・チェックリストと発注票の紙面は
変えていません。** 統合のために変えたところ:

- 経路の前に `/material` が付きます(画面・API・印刷。印刷は `/material/report/…`)
- ログは統合アプリの1つのファイルに入ります。配布設定は統合アプリの直下の
  `配布設定\packing_material_calculation\`、書き出し先は `export\packing_material_calculation\`
- 帯の「終了」は3機能とも終わらせます(統合画面の「終了」と同じ)
- 自動終了の見張りは統合アプリに1つ。**チェックリスト・発注票を開いた別のタブがあるあいだは
  止まりません**(発注票はサーバが覚えている中身から組むため)
- (直したこと)画面を閉じたときの「裏に回った」合図が「閉じた」合図を取り消して、
  閉じても終わらないことがあったのを直しました(梱包明細と同じ決まりに揃えた)
- 統合画面で Ctrl+P を押すと、この画面が刷られます(外枠は刷られません)

### 0.2.0

現場からの指摘をまとめて直した版。**操作が変わるところがあります。**

使い方が変わったもの:

- **包装仕様No を押すと、番号をコピーして包装仕様書の閲覧システムを
  開きます**(python-web-tools と同じ)。開いた先で Ctrl+V で貼れます

- **担当者は梱包資材マスタの「班員名簿」から**出るようになりました。
  班ごとに分かれています。人の出入りは日報ツール側で直します
- **担当者に出すのは、担当ラインが「機側」の人だけ**になりました。
  機側以外の人は一覧に出ません（名簿に機側の人が1人も居ないときだけ、
  絞らずに全員出します ── 一覧が空だと誰も選べないため）
- **設定が分類ごとの面に分かれました**(取り込み / マスタ管理 /
  ラインと担当者 / 配布設定 / このアプリ)
- **設定に「配布設定」の面を足しました**(python-web-tools と同じ仕組み)。
  1台で決めた置き場所・書き出し先・自動取り込み・発注票の定尺・管理者
  パスワードを、ツールの直下の「配布設定」フォルダに書き出せます。
  ツールのフォルダごと配ると、**配った先が起動したときに読み込みます**
  (その端末にすでにある設定は上書きしません)。書き出す・読み込み直す・
  消すには、設定のいちばん上の認証が要ります。ラインは既定で入れず、
  担当者は入れられません(端末ごと・人ごとに違うため)
- (直したこと)設定画面の長い説明文が**右で切れて読めなかった**のを直しました
  (部品の CSS と名前がぶつかって、折り返さない指定が掛かっていた)
- **置き場所の保存は欄ごと**になりました。まとめて保存するボタンは
  ありません
- **置き場所を変えるにもパスワードが要ります**(マスタを直すのと同じ)。
  認証欄は設定のいちばん上にあります
- **「古い」は日付が変わったら出ます**(前は24時間経過)。朝いちばんに
  1回取り込む運用になります
- **発注票は A4横1枚につき1票**。紙の左半分に出て、真ん中の
  縦の切り取り線で切ると **A5縦** の票になります（右半分は空白）
- **発注票の画面の見本も、紙1枚ずつの姿**になりました（A4横・左半分に票・
  右半分は白紙）。角サイズが2つあれば紙が2枚並び、各紙の上に
  「1枚目 / 全2枚」と出ます。この添え書きは印刷されません。
  前は画面で票を縦に伸ばして並べていたので、1枚の紙に2票あるように見えました
- **印刷物（チェックリスト・発注票）の字・罫線は、すべて紙の端から5mm以上
  内側**に置くようにしました（プリンタは縁の約4mmに刷れないため）。
  印刷ダイアログの余白が「デフォルト」「なし」「最小」のどれでも 6mm 以上
  内側に出ることを測って確かめています。前は「なし」を選ぶと紙の端 0mm まで
  出ていました。ブラウザが余白に入れる日付・URL のヘッダーも出なくなります
- **チェックリストは満杯（15行 × 2段）でも1枚**に収めます（VBA と同じ
  「1ページに合わせる」）。前は30行になると2枚目にはみ出していました
- **発注票の姿を原紙(注文票.xlsx)に合わせました**。見出しの「発注票」は
  枠なし、提出日付と依頼者は右肩の囲み枠、1行目は `ﾘﾌﾟﾗ | 角サイズ`、
  明細は見出し行なしの12行。LotNo と数量のあいだに縦線は入りません
- タブを2枚開くと、2枚目は断られます

直したもの:

- (確かめたこと)VBA で放置されていた発注票の不具合 ── **1行目が空だと
  発注票を出せない**・**資材発注管理を発行せずに発注票を発行すると
  エラー** ── は、**このアプリでは起きません**(試験で固定しました)

- **開いているのに、しばらく見ていないとアプリが勝手に終わっていました。**
  ブラウザは裏に回ったタブ(最小化も含む)のタイマーを間引くので、
  画面からの「生きています」の合図が届かなくなり、90秒で終わって
  いました。PCのスリープから戻ったときも同じでした。
  **開いている間は終わりません。** タブを閉じたときは今までどおり終わります

- **ﾎｲｰﾙで収まるパレットが無いときは、計算を断ります。** 現行VBAは
  知らせたあと計算を続け、積数・台数がマイナスになっていました
  (不明点 Q24)。ほかのパレット種類は VBA と同じく続けます
- **協豊製作所向け(ｺｲﾙ間は間紙入〇)は止まらずに計算します。**
  現行VBAは計算の途中で「型が一致しません」で止まります(不明点 Q23)

- **トータルリプラ本数が、VBA では 0 のところで空欄になっていました。**
  スペーサーがチップ・外装紙・クラフトなどのとき。現行VBAとの照合
  (疑似ロット)で分かりました

- **取り込み元に同じ番号の行が2つあるとき、あとの行で上書きして
  いました**。VBA は最初の1件しか見ないので、先の行を残すようにし、
  飛ばした番号を取り込みの結果に出すようにしました
  (実物のマスタに `1C0118` が2行ありました)

- **暗い地で入力の文字が読めなかった**のを直しました。VBAの色の意味
  (赤=どの規則で決まったか / 水色=1本積み不可)も出ていませんでした
- **知らせ(「積みました」など)が画面の外に出ていた**のを直しました。
  ボタンが効いていないように見えていました
- プロセスの多重起動に開いていた隙間を塞ぎました
- 作業用DBと利用者設定を、利用者ごとのローカル領域へ移しました
  (共有フォルダに本体を置いても混ざりません)

見た目:

- **発注票を、現行VBAで刷った票(写真)と同じ姿にしました。**
  `ﾘﾌﾟﾗ`(半角)・字はすべて細字(Meiryo UI)・種類の行は太線で囲む・
  提出日付は `9/25`・切り取り線は細い実線で、表から少し離して表の
  上から下まで(ハサミの印はなし)。依頼者の欄は原紙では2文字ぶんの
  幅なので、長い名前は字を小さくして収めます

- 計算結果の**積数の欄を、隣の台数と同じ大きさ・左寄せ**にしました
  (等幅の小さな字で右寄せになっていて、そこだけ読みにくかった)

- 自分で打つ4つの欄(LotNo・受注番号・検入数・コイル外径)を大きく
- 計算結果のリプラを「最下部」「コイル間」の枠に分けました。
  最下部は **長 / 短** を列にした表にして、長さと本数が組で読めるように
  しました（最下部リプラの並びの図は画面から外しました）
- 読み取り欄の揃えを左に統一し、幅が伸びすぎないようにしました
- バリ揃え梱包に **−** **＋** のボタンを付けました
- 版(VER)を帯の読める大きさで出すようにしました
