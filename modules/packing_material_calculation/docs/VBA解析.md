# コイル梱包資材計算VBA — 構造解析

移植元の VBA 一式を読み切った結果。**実装前の記録**であり、ここに書いた挙動が
移植の期待値になる。コードの字面と業務上の意図が食い違って見える箇所は
`不明点.md` に分けてある(勝手に直さない)。

## 1. このツールは何か

アルミコイルの梱包に使うパレット・リプラ(再生プラスチック製スペーサー)・
緩衝材の員数を、受注情報と包装仕様マスタから決めるツール。

    LotNo(7桁) → 受注番号(8桁)の候補 → 受注情報の展開 → 検入数・コイル外径を入力
      → パレット種類 → パレットサイズ → 積数・台数 → リプラ員数
      → 資材発注管理チェックリスト(15行)へ蓄積
      → リプラ角サイズ別の発注票(最大3枚 × リプラ/LVS)を起こして倉庫へ

**既存 `python-web-tools` とは扱う製品が違う。** 既存ツールの包装仕様Noは
`1P1xxx`(板・ザラ板の2次元敷き詰め)、こちらは `1C1xxx`(コイル)。
選定・配置アルゴリズムに重複は無い。重複するのは参照データ源と起動基盤。

## 4. 判定ロジック

### 4.1 画面の色は業務情報

| 色 | 意味 |
|---|---|
| 黄 | 入力が要る(検入数・コイル外径) |
| 赤 (`F重量`/`F枚数`/`F高さ`/`F包装仕様`) | **どの規則で決まったか** |
| 水色 (`FM` 枠) | 1本積み不可フラグ |
| 赤字2箇所 (`間リプラ種類`/`最下部リプラ種類`) | 両者の種類が違う |

Web でもこの区別は残す。

### 4.2 `台数計算` — 優先順位つき5段

上から見て最初に当たったものを採用する。**オーダー情報が包装仕様マスタより優先**。

1. **オーダーの梱包単位_重量** → `積数 = RoundDown(梱包単位_重量 ÷ 製品単重)` / `F重量`=赤
2. **オーダーの梱包単位_枚数** → `積数 = 梱包単位_枚数` / `F枚数`=赤 / 枚数範囲が `"1不可"` なら1本不可フラグ
3. **包装仕様の梱包単位_重量** → 重量範囲 `"程度"` は +10% を上限、`"以下"`/`"max"` はその値 → `積数 = RoundDown(上限 ÷ 単重)`
4. **包装仕様の梱包単位_枚数** → 枚数範囲 `"以下"`/`"max"` はその値 / `"1不可"` は1本不可フラグ(吉川工業 1C1252 はここで枚数を採る)
5. **どれも無く 製品単重 > 500kg** → `積数 = 1` (2022.10.14 追加)

オーダー・包装仕様のどちらにもデータが無い(両方 `"データなし"`)場合は
「引当データなし計算ができません」で中断する。

このあと **包装仕様No別の個別規則(§5)で積数を上書き**し、続いて:

#### 1本積み不可の端数処理

```
x = Round(検入数 ÷ 積数, 0)      ← VBA の Round は銀行丸め(偶数丸め)
```

`検入数 − x×積数 = 1`(最後の1台が1本積みになる)かつ1本不可フラグのとき:

- `x = 1` → **台数 = 2、積数 = 検入数 ÷ 2**(2台へ均等分配。2026.1.16 追加)
- `x ≥ 2` → **台数 = x−1**、残りを `Re_積数 = (検入数 − (x−1)×積数) ÷ 2`、`Re_台数 = 2`

該当しなければ `台数 = RoundUp(検入数 ÷ 積数)`。

最後に `If Not x = 1 Then 積数 = StackC` ──
`x = 1` のときだけ、上で入れた均等分配の積数を上書きしない。

#### 高さ制限による再計算

**包装仕様No別規則が効いた場合(`PackFlag`)と、オーダーの枚数指定がある場合
(`Cflag`)は、高さ判定を丸ごとスキップ** (`GoTo PacSkip`)。それ以外:

| 高さ範囲 | 有効高さ | 再計算 |
|---|---|---|
| 以下 / 程度 / max | 梱包総高さ − 210mm (パレット上下分) | 重量で決めた積数の高さ `(リプラ+幅)×積数` が有効高さを超えていたら `積数 = RoundDown(有効高さ ÷ (リプラ+幅))`、台数も取り直す |
| 蓋除き | 梱包総高さ − 80mm (パレット上分のみ) | 同上 |
| パレット除き | 梱包総高さ そのまま | `積数 = RoundDown(梱包総高さ ÷ (リプラ+幅))` |
| (高さ指定なし・重量オーダーあり) | パレットサイズ − (リプラ+幅) | 重量だけだと積みすぎるため、パレット幅から1本分引いた高さを上限にする (2022.07.25) |

リプラサイズが `"可変"` のときは 30mm として計算に入る。
総高さ表示は `積数×(リプラ+幅) + 210`。

### 4.3 `PalletType` / `PalletSize`

`PalletType` は包装仕様マスタの「パレット」列。
「サイズ」列に値があれば `PFlag`(指定パレットフラグ)、
「種類」列に値があれば `特殊Flag` に立てる。

| パレット種類 | サイズ選定条件 |
|---|---|
| スカシ / 全面 | 巾下限 ≤ 外径 ≤ 巾上限 **かつ** 丈下限 ≤ 外径 ≤ 丈上限 |
| 強度UP | 巾のみで判定(丈の上下限を見ない。2024.3.4 暫定・佐藤氏) |
| EXPS / ｸｰﾗｰﾌｨﾝ / その他 | Ｗ ≥ 外径(下限上限の設定が無いため) |

該当した中から **Ｗ が最小のもの**を選び、その「新記号」がパレット名称。
`PFlag` が数値ならそのＷへ強制。`PFlag = "外径指定"`(1C1258)は §5 の段階表。

該当0件のときは「収まるパレットがDB上にありません」で中断。

### 4.4 `リプラ計算`

先に `台数計算` が済んでいる前提。包装仕様から
コイル間スペーサー / リプラサイズ / 下本数 / 緩衝材 / 最下部スペーサー / ｺｲﾙ間は間紙入 を取る。

- 間リプラ種類 ≠ 最下部リプラ種類 → 両方を赤字にする
- コイル間スペーサーが **リプラ / LVS 以外** → `HB枚数 = 台数 × 2` を出して終了
- 1C1188(ｼﾏﾉ): 厚0.8 × 幅260 → リプラサイズ40、それ以外 → 30
- 積数が空なら終了
- リプラサイズ **80** → `リプラ計算 = 積数 × 2 × 台数`、`HB枚数 = 台数`(長さ固定品)

#### 長さ

`MaxVal` = リプラサイズマスタの長さのうち、パレットサイズ以下で最大のもの。

| パレット種類 | 最下部長さ | コイル間長さ | 最下部本数 | 最下部の短 |
|---|---|---|---|---|
| スカシ | MaxVal | MaxVal − 100 | 下本数 | 0 |
| 全面 | パレットサイズ | パレットサイズ − 100 | 下本数 | 0 |
| ｸｰﾗｰﾌｨﾝ | MaxVal | MaxVal − 100 | 下本数 | 0 |
| EXPS | パレットサイズ | パレットサイズ − **350** | **1** | **2** |
| ﾎｲｰﾙ | MaxVal | MaxVal − 100 | 下本数 | 0 |

コイル間長さが 800mm 以上なら、マスタから同じやり方で取り直す
(倉庫でのカットを避けるため)。

#### 本数

```
x       = (積数 − 1) × 2                 ← 最下部を除いたコイル間リプラ
長い本数 = (台数 + Re_台数) × 最下部本数
短い本数 = (台数 + Re_台数) × 最下部の短

検入数 ÷ 台数 が割り切れる、または Re_積数あり:
    コイル間本数 = x × 台数
割り切れない:
    仮台数 = 台数 − 1
    仮    = 検入数 − (仮台数 × 積数) − 1   ← 最下部を除いた端数コイル本数
    コイル間本数 = x × 仮台数 + 仮 × 2

Re_積数あり: コイル間本数 += (Re_積数 − 1) × 2 × Re_台数

戻り値 = コイル間本数 + 長い本数 + 短い本数
HB枚数 = 台数 + Re_台数   (最下部本数が非数値なら ×2)
```

- `ｺｲﾙ間は間紙入 = "〇"`(協豊製作所向け): コイル間のリプラを出さず
  緩衝材を「外装紙」に差し替え、`リプラ計算 = 下本数 × 台数`
- 1C1282: 戻り値に `IMI中間本数` を加算

### 4.5 `UFalmo`(バリ揃え梱包)

上バリ/下バリのスピンで検入数から本数を差し引き、それぞれの台数を出す。

```
上台数 = RoundUp(上本数 ÷ 積数)
下台数 = RoundUp(下本数 ÷ 積数)
台数   = 上台数 + 下台数
```

積数の決め方は本体 `台数計算` の5段と同じ構造だが、
**オーダー重量指定のときだけ `RoundUp`**(本体は `RoundDown`)→ 不明点 Q5。

## 6. 帳票

### 6.1 資材発注管理チェックリスト(15行)

行番号はスピンで 1–15。データ行は 5行目から(`Cells(RowCount+4, 2..14)`)。

|---|---|---|

| B | 依頼日 | `Format(Now,"mm/dd")` |
| C | LotNo | |
| D | 用途名 | |
| E | パレット種類 | スカシ / ｸｰﾗｰﾌｨﾝ は「種類+名称+改行+サイズ」、他は「種類+サイズ」 |
| F | 台数 | 台数 + Re_台数 |
| G | 営業納期 | 出荷日 |
| H | ｺｲﾙ間 | スペーサー種類(コトブキは間リプラ種類) |
| I | ﾘﾌﾟﾗ長さ | **最下部長さ + 改行 + コイル間長さ** |
| J | ﾘﾌﾟﾗ本数 | **長い本数 + 改行 + (コイル間本数 + 短い本数)** |

表題(E1)は LS4 / NS1 の選択で「LS4資材発注管理チェックリスト」等に変わる。
1C1282 と 1C1297 はここへ **2行** 書き込む。

VBA の J列は `.長い本数 & vbLf & val(.本数) + val(.短い本数)` で、
**演算子の優先順位により算術が先**。`(長い本数) 改行 (本数+短い本数)` になる。

### 6.2 発注票

`転記` → `Ripla_Count` → `注文票入力`(ﾘﾌﾟﾗ / LVS の2回)。
改行で2行に分かれているリプラ長さ・本数は `転記` で2レコードへ展開される
(改行が無ければ1レコードのまま。2025年の修正で「改行がある場合のみ2行目を書く」)。
`Ripla_Count` は `サイズ_長さ` をキーに本数を合算する。

原紙の作り:

- `A5:A12` = 倉庫在庫の定尺 `700 / 800 / 900 / 950 / 1000 / 1050 / 1100 / 1150`
- `A13:A16` = 空欄4行。定尺に無い長さはここへ追記し、
  **5件以上で「発注リストにないサイズが多すぎます」で中断**
- `B列` = LotNo(空白区切り・重複除去)、`C列` = 数量、`D列` = 単位「本」
- `A4` = リプラ/LVS、`B4` = 角サイズ、`C3` = 提出日付、`D3` = 依頼者
- `80×80` は長さを持たないので長さ処理を丸ごとスキップ
- サイズは最大3種まで(30×40 / 40×60 / 80×80)。未使用の票は最後に削除

原紙の体裁(`注文票.xlsx` を開いて読み取ったもの。Python 版はこれに合わせた):

| どこ | どうなっているか |
| --- | --- |
| 用紙 | `paperSize=9`(A4)/ `orientation=landscape` / `scale=80`。**字は80%に縮めて刷られる**ので、22pt は紙の上では約17pt |
| 列幅 | A=20.125(長さ) / B=30.875(LotNo) / C=11(数量) / D=11(単位) / E=2.75 |
| 行高 | 1行目=40.5 / 3行目=56.25 / 4行目=43.5 / 5〜16行目=39 |
| 「発注票」 | `B3`・26pt・**罫線なし** |
| 提出日付 / 依頼者 | `C2:D3` の 2×2 の囲み枠。見出しは12pt、中身は16pt / 22pt |
| 種類の行 | `A4` = ﾘﾌﾟﾗ(22pt)、`B4:D4` を結合して角サイズ(30pt) |
| 明細 | 5〜16行目の12行。**見出しの行は無い** |
| 縦の罫線 | A の左右と D の右だけ。**B に右罫線が無く、C には左右とも無い** ── LotNo と数量のあいだに線は入らない |
| 切り取り線 | E列の右罫線。A4横の左半分の端にあたる |

**VBA で放置されていた不具合(現場の話、2026-09-25):**

- 資材発注管理の**1行目が空だと**、2行目以降にデータがあっても発注票を
  出せない(`転記` が表の範囲を行の並びから決めている)
- 資材発注管理を**発行せずに**発注票を発行するとエラーになる

移植はどちらも起きない。発注票はチェックリストを**行番号順にあるだけ**
読んで作り(空の行は飛ばす)、チェックリストを印刷したかどうかとは
関係がない。`tests/test_checklist_and_order.py` の末尾で固定した。

**発注履歴チェック:** 書き込む前に LotNo ごとに履歴を引き、2週間以内に
発注済みなら担当者・登録内容つきで確認。「いいえ」なら作りかけの票を消して中断。
同一実行中に一度「はい」と答えたロットは以後スルーする(`checkedLots`)。
確定した行は履歴へ追記(処理日/担当者/品名/サイズ/長さ/LotNo/数量/単位)。

### 6.3 印刷

チェックリスト・発注票とも A4 横・余白0・水平垂直中央・1ページに収める。

Python 版は `@page` の余白を 0 にし、**紙の中で端から 6mm(チェックリスト)/
8mm(発注票)空ける**(プリンタは縁の約4mmに刷れないので、5mm 未満にはできない
── `printing.SAFE_MARGIN_MM`)。1ページに収めるのはチェックリストだけ縮めて行う
(`Report.fit_one_page`)。
発注票が複数あるとき両面になることがあったため、
**1枚ずつ別ジョブで印刷**する(2025.7.8 の対処)。

## 7. 上流更新との競合回避

`LOT検索` は `PATH_仕掛_参照` と `PATH_梱包_仕掛` を交互にフォールバックする。
併せて次の2つで上流の更新中を避けている。

- `TimeDesignation` — 毎時 59分45秒〜0分45秒 は更新時間帯とみなす
- `FileDesignation` / `FileExistence` — `PLEASE WAIT.txt` が消えるまで待つ(最大約5秒)

取り込み元が sqlite3 になった環境では役割が変わる → `移植計画.md` §運用。
