# コイル梱包資材計算ツール (Python / SQLite版) — VER0.1.0

アルミコイルの梱包に使うパレット・リプラ・緩衝材の員数を、受注情報と
包装仕様マスタから決めて、資材発注チェックリストと倉庫向け発注票を出す
ツール。Excel VBA + Access 版の移植です。

画面は **Flask + HTML/CSS/JS**、業務ロジックは Python、データは SQLite。
追加で入れるのは `Flask` と `waitress` の2つだけで、フロント側の
ビルド工程(npm / webpack)は持ちません。

## 位置づけ

[`python-web-tools`](https://github.com/ViVio-Hellon/python-web-tools)
(梱包資材総合ツール)と同じ基盤の上に乗る別アプリです。

既存が扱うのは `1P1xxx`(板・ザラ板の2次元敷き詰め)、こちらは `1C1xxx`
(コイル)で、**選定・配置アルゴリズムに重複はありません**。共有するのは
参照データ源(梱包資材マスタ / 仕掛台帳)と、起動・DB・帳票の基盤です。

## 移植した業務ロジックの範囲

### 積数と台数 — `stack_service.py`

VBA `台数計算`。**優先順位つきの5段**で、上から見て最初に当たったものを
採ります。オーダー情報が包装仕様マスタより強い。

1. オーダーの梱包単位_重量 → `切り捨て(重量 ÷ 単重)`
2. オーダーの梱包単位_枚数 → その枚数(枚数範囲 `"1不可"` で1本積み不可)
3. 包装仕様の梱包単位_重量 → 重量範囲(`程度`=+10% / `以下` / `max`)で上限を決めて切り捨て
4. 包装仕様の梱包単位_枚数 → 枚数範囲が `以下` / `max` ならその枚数
5. どれも無く単重 > 500kg → 1本積み (2022.10.14)

そのあと **包装仕様No別の規則で上書き**し、**1本積み不可の端数処理**と
**高さ制限による再計算**を通します。

- 1本積み不可: `x = 銀行丸め(検入数 ÷ 積数)` で `検入数 − x×積数 = 1` のとき、
  `x = 1` なら2台へ均等分配 (2026.1.16)、`x ≥ 2` なら1台戻して別枠2台へ
- 高さ: `以下`/`程度`/`max` は −210mm、`蓋除き` は −80mm、`パレット除き` は
  そのまま。高さ指定が無く重量だけで決めたときは、パレット幅から1本分
  引いた高さを上限にする (2022.07.25)
- **包装仕様No別の規則が効いた場合と枚数指定がある場合は、高さ判定を
  丸ごと飛ばす**

> **注意 (`docs/不明点.md` Q13)** 2023.3.27 に足されたガードにより、
> 3〜5段目は通常の操作では到達しません。現行どおりに移植し、テストで
> 固定してあります。

### リプラ員数 — `ripla_service.py`

VBA `リプラ計算`。最下部とコイル間で長さが違い、パレット種類で
どれだけ短くするかが決まります。

| パレット種類 | 最下部長さ | コイル間長さ | 最下部本数 | 最下部の短 |
|---|---|---|---|---|
| スカシ / ｸｰﾗｰﾌｨﾝ / ﾎｲｰﾙ | 定尺の最大 | 最大 − 100 | 下本数 | 0 |
| 全面 | パレットサイズ | サイズ − 100 | 下本数 | 0 |
| EXPS | パレットサイズ | サイズ − **350** | **1** | **2** |

本数は積数と台数から。**検入数が台数で割り切れないとき**は最後の1台を
別に数えます。コイル間が 800mm 以上なら定尺から選び直します(倉庫での
カットを避けるため)。

- コイル間がリプラ / LVS 以外 → `HB枚数 = 台数 × 2` で打ち切り
- 角サイズ 80 → 長さを持たない固定品。`積数 × 2 × 台数`
- `ｺｲﾙ間は間紙入 = "〇"`(協豊製作所向け)→ コイル間を出さず緩衝材を外装紙へ

### パレット選定 — `pallet_service.py`

VBA `PalletType` / `PalletSize`。外径が収まるうち **Ｗ が最小のもの**。

| パレット種類 | 条件 |
|---|---|
| スカシ / 全面 | 巾と丈の両方の上下限 |
| 強度UP | 巾のみ (2024.3.4 の暫定仕様) |
| EXPS / ｸｰﾗｰﾌｨﾝ ほか | Ｗ ≥ 外径 |

包装仕様マスタの「サイズ」列に値があれば、最小選定を上書きします。

### 包装仕様No別の業務規則 — `special_rules.py`

取引先固有の規則 **15件** を1ファイルに集めてあります。VBA では
`PalletType` / `PalletSize` / `台数計算` / `リプラ計算` に散っていました。

`1C1103` `1C1258` `1C1188` `1C1178` `1C1271` `1C1295` `1C1244` `1C1277`
`1C1250` `1C1263` `1C1254` `1C1281` `1C1282` `1C1297` `1C1252`

一覧と中身は [`docs/VBA解析.md`](docs/VBA解析.md) §5。

## マスタ管理 — `master_admin.py`

姉妹ツール [`python-web-tools`](https://github.com/ViVio-Hellon/python-web-tools)
の同名モジュールの移植です。VBA 版はマスタを**黙って読むだけ**で、
中を見る手立ても直す手立ても画面にありませんでした。値が違っていても
現場には「パレットが出ない」としか見えません。

**思想は3つ、そのまま持ってきています。**

1. **書き先は取り込み元ただ1つ。** 手元のDBは総入れ替えで取り込まれる
   ので、手元を直しても次の取り込みで消えます。
   `画面 → 共有ファイルへ書く → その表だけ取り込み直す → 手元が追いつく`
2. **行は取り込み元の言葉で指す。** `パレット` と `リプラサイズ` の `id` は
   取り込みのときに手元で振り直しているので、手元の `id` は取り込み元の
   行を指しません。sqlite の暗黙の `rowid` を `__行` という名前
   (業務の列と衝突しない名前)で持ち回ります
3. **直せない表は隠さず、理由を出す。** 梱包資材マスタは姉妹ツールと
   同じファイルなので、向こうの表も並びます。隠すと画面が壊れて見えます

直せるのは `包装仕様` / `パレット` / `リプラサイズ` の3表
(`master_admin.MANAGED`)。増やすときはこの表と
`import_specs.MASTER_IMPORT_SPECS` を差し替えるだけで、画面側は触りません。

### 移植元から落としたもの

| 落としたもの | なぜ |
|---|---|
| 端末による関門(アクセス権限マスタ) | このツールはアクセス権限マスタを持たない。移植の指示どおり落としました。**管理者パスワードのほうは残してあります**(下記) |
| 取り込み元に表を作る / 作り直す | 直す3表はどれも上流(資材課)の表です。無いのは資材課側の事情で、空の表を作ると**その事情が「0件」に化けて**原因を探せなくなります。作らずに、無いことと置き場所を言います |
| 閾値マスタの別ファイル分岐 | このツールの3表はすべて梱包資材マスタの中。`source_for()` は判断の場所として残してあります |

### 移植で足したもの

**列も取り込み元の言葉で指します。** このツールは取り込みのときに
列名を寄せています(半角カナの `ｺｲﾙ間は間紙入` → 手元では
`コイル間は間紙入`)。移植元は手元と取り込み元で列名が同じだったので
区別していませんでしたが、そのまま持ってくると**手元の名前で書きに行って
「そんな列は無い」と断られ、読むときは空に見えます**。
`Column` が両方の名前を持ち、画面と保存は取り込み元の名前で動きます
(`tests/test_web_master.py` の「列名の寄せ」の節が見張ります)。

**鍵の列は空にできません。** 手元のスキーマは全列に
`NOT NULL DEFAULT ''` を付けてあるので、そのままだと包装仕様NO を空の
まま足せてしまいます。その行は次の取り込みで黙って捨てられる
(`convert_row` が鍵の無い行を落とす)ので、入れた人には「足したはずの
行が消えた」としか見えません。取り込みが鍵と見なす列
(`import_specs.REQUIRED_KEY_COLUMNS`)は、画面でも空にできないことに
しています。

**同じ番号の行が2つあったら、先に出てきた行を使います。**
提出された実物の梱包資材マスタには `包装仕様NO = 1C0118` が2行あり、
片方は重量指定、もう片方は枚数指定でした。VBA は鍵で引いて
`TempHiki(1, ...)` ── **最初の1件しか見ません**。こちらは
`包装仕様NO` を主キーにして `INSERT OR REPLACE` していたので、
**あとの行で上書き**していました(VBA と違う行で計算しうる)。
取り込みで先の行を残し、飛ばした番号は取り込みの結果に出します
(`import_specs.UNIQUE_KEY_COLUMN` / `tests/test_import_duplicates.py`)。

> このときの 1C0118 は、2行の違いが `梱包単位_重量` と `梱包単位_枚数`
> だけで、**いまの判定順ではどちらでも結果が同じ**でした
> (オーダー側の指定が先に決めるため。実際に両方で計算して確かめました)。
> ただし `パレット` や `下本数` が違う重複が来れば結果は変わります。

### 直すにはパスワードが要ります

**見るのは誰でも。直すにはパスワード**(既定 `nisk`)。設定のいちばん上で
入れると、そのアプリが動いている間だけ開きます。
中身を確かめられることと、書き換えられることは別の話なので、
関門は書くほうにだけ置いてあります。

**同じパスワードで2つを守っています** ── 梱包資材マスタを直すことと、
取り込み元の置き場所を変えること。どちらも間違えると全端末・その端末
ぜんぶに効くので、重みが揃っています。

そのため**認証欄はタブの外**(設定のいちばん上)に1つだけ置いています。
どちらかの面の中に入れると、もう片方から使うときに「面を移って、
打って、戻る」になります。1か所しか無いので、状態も1つで済みます。

- **30分さわらなければ閉じます。** 現場の端末は共用で、書き先は共有
  フォルダの元ファイルです。開けっぱなしの画面が残っていると、次に
  座った人が気づかずに直せてしまいます。
  「さわった」に数えるのは**直せるかどうかを実際に確かめたとき**だけ ──
  残り時間を画面に出すだけで延びると、開いたままのタブが永久に閉じません
  (`admin_session.is_open()` と `peek()` の違いがこれです)
- 保存の形は PBKDF2-HMAC-SHA256(20万回)。**設定ファイルに素のまま
  残しません**。忘れたときは `admin_password` の行を消すと既定に戻ります
- 判断の場所は `master_admin.can_edit()` **1か所**。画面・保存・
  取り込み直しが同じ答えを見ます(2か所に持つと、画面は通したのに
  保存で断られる、が起きます)

既定のパスワードがここに書いてあるのは承知の上です。守りたいのは
**うっかり直してしまうこと**で、悪意のある人ではありません
(共有フォルダの元ファイルは、このアプリを通さなくても開けます)。

## 「古い」は日付で見る — `data_sync.stale_reason()`

マスタと仕掛台帳は**取り込んだ時点の写し**です。自動では読み直さない
(計算の途中で足元の値が変わるほうが困る)ので、代わりに「いつの写しか」を
帯に出し、古ければ札を付けて人に押させます。

古いかどうかは **取り込んだ日と今日が違うか** で見ます。

以前は「24時間経ったか」でした。仕掛台帳は日々の台帳なので、
23:50 に取り込んで翌 00:10 に使うと経過は20分 ── 日付はまたいで
いるのに札が出ず、**前日の写しのまま計算できてしまいました**。
同じ日の中は最長でも24時間未満なので、日付で見ても**前より甘くは
なりません**。

札には理由も出します(「取り込んだ日から日付が変わりました」)。
20分前に取り込んだ人が日付をまたいだだけで「古い」と言われると、
壊れたように見えるためです。

## 書くものは利用者ごとのローカル領域へ

README は前から「本体を共有フォルダに置いて複数の端末から使っても
混ざりません」と書いていましたが、**ログだけがローカル領域に移して
あり、作業用DBと利用者設定は本体の隣のまま**でした
(`app_config.py` が「Phase 2 で移す」と書いたまま残っていた)。

共有に置いた運用だと、そのままでは:

- 担当者・ライン・取り込み元の置き場所が**全端末で1つ**になり、あとから
  保存した端末の値で黙って上書きされる
- チェックリストも全端末で1つになり、同じ行番号を2台が使うと先に
  書いたほうが消える
- 共有フォルダ上の SQLite に**書く**ことになる(読むだけなら妥当だが、
  書き先としては SMB のロックが当てにならず勧められない)

いまは3つとも `%LOCALAPPDATA%\CoilMaterialTool\` の下です。

| | 置き場所 |
|---|---|
| 作業用DB (`coil_tool.db`) | `…\CoilMaterialTool\data\` |
| 利用者設定 (`user_config.json`) | `…\CoilMaterialTool\data\` |
| ログ | `…\CoilMaterialTool\logs\` |

旧い場所にファイルが残っていれば、**起動時に1度だけ写します**
(`config.migrate_local()`)。写すのは新しい側がまだ無いときだけで、
旧ファイルは消しません。DBは `sqlite3` の `backup()` で写すので、
WAL にだけ書かれてまだ本体へ落ちていない分も取りこぼしません。

**共有フォルダに書くのは、マスタを直したときだけ**になりました
(それは意図した書き込みで、パスワードで守っています)。

## 配布設定 — `coil_tool/distribution.py`

姉妹ツール python-web-tools の配布設定を移植したもの。1台で決めた設定を
ツールの直下の `配布設定\` に書き出し、フォルダごと配った先が**起動時に
読み込む**。フォルダの形・読み込みの決まりは姉妹ツールと同じにしてある
(両方を配る管理者が同じ手順で扱える)。

    配布設定\
      設定.json          置き場所・書き出し先・自動取り込み・発注票の定尺・
                         管理者パスワード(撹拌した値)・ライン(選んだときだけ)
      はじめに読む.txt   何が入っているか・配った先で何が起きるか

- **その端末にすでにある設定は読まない**(無い項目だけ埋める)。起動のたびに
  見るが、端末で直した値は戻さない。揃え直すのは画面の「読み込み直す」
- **取り込みより先に読む**(`start_app._initialize`)。置き場所が入っている
  ので、先に取り込むと既定の場所を見る。移し替え(`migrate_local`)の後
- この端末で変えていない項目は書き出さない(配った先の既定を空で潰さない)
- **担当者は入れられない**(人ごと)。ラインは選べるが既定で外す(端末ごと)

姉妹ツールとの違いは2つ。**配置図が無い**(このツールは持たない)ことと、
**パスワードは設定のいちばん上の認証で通す**こと ── 書き出すものには
置き場所と管理者パスワードが入り、読み込み直すと置き場所が変わるので、
置き場所を変えるのと同じ関門にした。面ごとにパスワード欄は置かない。

`配布設定/` は `.gitignore` に入れてある(開発機の置き場所が紛れ込まない)。

## 担当者は「班員名簿」から — `coil_tool/staff.py`

VBA `UF_Material` は担当者を **W1〜W7 の7個のボタン**として画面に
直書きしていました。異動のたびにコードを直す必要があり、端末ごとに
写しがずれます(置き場所を `Public Const` に書いていたのと同じ問題)。

名簿は**すでにありました** ── 姉妹ツール
[`vba-daily-report-python-migration`](https://github.com/ViVio-Hellon/vba-daily-report-python-migration)
の人員フォームが、**同じ梱包資材マスタの中の「班員名簿」**を読んで
います(VBA `人員()`)。列は `管理番号 / 苗字 / 班 / 名前 / 読み / 担当ライン`。

このツールも同じ表を読みます。**名簿を二重に持たない** ── 持つと、
異動があったときに片方だけ古くなり、どちらが本当か分からなくなります。

| | |
|---|---|
| 並び | 「読み」で五十音順 → 「班」で安定ソート（班の中では読み順が残る）。姉妹ツールの `group_by_team()` と同じ |
| 班の順 | `A / B / C / D / 昼 / 丸`（画面左から右）。選ぶ画面では `<optgroup>` の見出しになります |
| 書く側 | **日報ツール。** こちらは読むだけで、マスタ管理でも直せません |
| 名簿が無いとき | 内蔵の7名へ落ちます（VBA の W1〜W7 と同じ7人を、**名簿の書き方**に直したもの。苗字のままだと、取り込んだ後に「名簿にありません」へ化けます）。**担当者が無いとチェックリストへ積めない**ので、名簿が読めないだけで仕事を止めません（画面がそう言います） |
| 異動のあと | いま選ばれている人が名簿から消えても、その名前は残して「名簿にありません」と出します。黙って別人に変わるより、出して気づかせる |

**出すのは担当ラインが「機側」の人だけ**です（→ 不明点 Q18 / Q19）。
名簿には機側以外の人も載っていますが、資材を発注するのは機側なので、
担当者の一覧には機側の人しか出しません。

| | |
|---|---|
| 判定 | 担当ラインから空白を取り除いて「機側」を**含むか**。「機側A」「1号機側」も拾います ── 書き方の揺れで落とすと、**その人は依頼者になれません** |
| 機側が居ないとき | **絞らずに全員**出します。担当ラインが埋まっていない端末で一覧が空になると、誰も選べずチェックリストへ積めないためです。絞れなかったことは画面が言います |
| 班 | **班では絞りません。** 知らない班の人も、機側であれば末尾の「班なし」に出ます（姉妹ツールが落とすのは画面の列を割り当てていた都合で、業務の決まりではありません） |
| 選ばれたまま機側から外れた人 | 名前は残し、「担当ラインが機側ではありません」と出します。**「名簿にありません」とは分けて言います** ── 消えたのか、担当ラインが違うのかで次の動きが違うためです |

## 使ってよい画面は1枚だけ — `app/screen.py`

作業状態はプロセスに1つ(VBA の `UF_Material` が1枚しか開かなかったのと
同じ持ち方)。**1つしかないものは、1つの画面からしか触らせません。**
2枚目は**開いた時点で断ります** ── 使えてしまってから「さっきの入力は
消えました」と言うのがいちばん悪いので。

| | どうなるか |
|---|---|
| 1枚目 | 通る。以後、心拍のたびに「まだ自分のものか」を確かめる |
| 2枚目 | **帯も本体も出さずに断る。**「この画面で使う」を押せば取り上げて入れ替わる |
| 取り上げられた側 | 次の心拍(20秒以内)で気づいて使えなくなる。書き込みはその前でもサーバが断る |
| 同じタブの画面移動・読み直し | 通る。符牒は `sessionStorage` なので**タブごとに別で、読み直しでは変わらない** |
| タブを閉じた | 即座に空く(`pagehide` の合図)。開き直しは待たずに通る |
| ブラウザが落ちた | 心拍が3回途切れたら空きとみなす(**表に出ている画面だけ**) |
| 裏に回した・最小化した | **空きにしない。** ブラウザが裏のタブのタイマーを間引くので心拍は途切れるが、開いている。ブラウザごと落ちて裏のまま残ったときは「この画面で使う」で取り上げる |

- **覆うのではなく、出しません。** 覆いをかぶせるだけだと Tab キーで
  後ろの欄に入れてしまいます。帯と本体は `hidden` で出し、通ったときに
  `app.js` が外します
- **サーバ側でも断ります。** 画面の覆いは次の心拍まで掛からないので、
  取り上げられた直後の隙に書けてしまいます。書き込み(POST 等)は
  `X-App-Screen` を見て 409。**読むほうは断りません**(塞いでも守る
  ものが無く、断られた画面はそもそも何も出ていません)
- **誰も画面を持っていなければ通します。** 塞ぎたいのは「2枚目が入力
  できてしまう」であって「1枚も開いていない」ではないので、
  `--no-browser` で立てておく使い方とテストを巻き添えにしません
- **取り上げを用意した理由**は、ブラウザが落ちた・別の端末で開いたまま
  鍵をかけた、のときに**誰も使えないアプリ**になってしまうからです。
  取り上げても「2枚とも使える」にはなりません ── 入れ替わるだけです

プロセスの二重起動(`launch_guard.py`)とは**別の関門**です。あちらは
「Python が2つ立ち上がるか」、こちらは「1つのプロセスに画面が何枚
ぶら下がるか」を見ています。

## 色は tokens.css から取る — 予備値を書かない

`coil.css` の先頭にそう書いてあったのに、実際には**定義されていない
トークン名**が使われ、予備値の直値で動いていました。

```css
.input--need{ background:var(--warn-soft,#fdf6d8); }
                          /* ^^^^^^^^^^^ どこにも無い */
                          /*             ^^^^^^^ 明るい地の色だけ */
```

明るい地では正しく見えるので気づけません。暗い地にすると、字
(`--ink`)は白に変わるのに地は淡い黄のままなので、**打った字が
読めなくなります**。`--danger` `--info` `--ok` `--line` `--flag-*` も
同じ状態でした(予備値の無いものは、宣言ごと無視されていました)。

いまは全部 tokens.css の色に向けてあり、`tests/test_css_tokens.py` が
3つを見張ります。

1. 使っているトークンが**全部定義されている**こと
2. 色に**予備値を書かない**こと ── 予備値は綴り間違いの隠れ蓑になる
3. 明るい地で定義した色は、**暗い地にも定義がある**こと

3 は名前ではなく**値**で見分けます(直に書かれた色だけを対象にし、
寸法・字の並び・`color-mix` で他のトークンから作る色は除く)。

## 版をどこに出しているか

現場の端末へはフォルダごと写して配るので、写した日がばらついて
**端末ごとに違う版が動きます**。「直したはずの不具合が出る」と言われた
ときに最初に確かめるのが版なので、どの画面にいても帯に出します。

| 出ている場所 | 何のために |
|---|---|
| 帯のバッジ(左上・アプリ名のとなり) | どの画面にいても、探さずに読める。押すと設定の「このアプリについて」へ飛ぶ |
| 設定「このアプリについて」 | 版のほかに アプリID・ポート・Python・置き場所。電話で聞かれる一式 |
| 起動待機画面 | 起動が遅いときに見えているのはこれだけ |
| `GET /api/health` | 別の版が同じポートに居ないかを起動側が照合する |
| `start.bat`(診断起動) | 画面が出ないときでもコンソールに出る |

**出どころは `config/app.json` の `version` ただ1つ**で、上の5つは
すべてこれを読みます。上げ方は [`docs/変更履歴.md`](docs/変更履歴.md)。
書き方(数字3つ)が崩れていたら設定画面が言いますが、**起動は止めません** ──
止めると、版を直すための画面にも入れなくなるためです。

## VBA から意図して変えたところ

| VBA | ここ | なぜ |
|---|---|---|
| パスを `Public Const` に直書き | 設定画面 | 置き場所が変わるたびにコードを直していた |
| 計算のたびに共有の .accdb を開く | 一度取り込んで手元の SQLite を引く | 1回の計算で同じファイルを何度も開いていた |

| 発注履歴はブック内の隠しシート | SQLite のテーブル | 端末ごとに履歴が別だった(→ 不明点 Q3) |
| 特殊品はチェックリストの `i` と `i+1` | 1行番号 + 枝番 | 行を選ぶとき1つ飛ばす必要があった(→ Q16) |
| `MsgBox` | HTTP ステータス + `reason` 定数 | 文言から断りの種類を推し量らない |
| 積数0 でゼロ除算エラー | 理由を返して止まる | 落ちると何が悪いか分からない(→ Q6) |
| `CheckHistoryLotNo` の `FindNext` が E列 | LotNo(F列)で統一 | 2件目以降が別の列で判定されていた(→ Q4) |

## VBA の癖をそのまま残したところ

結果を合わせることを優先して、次は**直していません**。
直すと台数や本数が変わるので、業務の判断を待ちます。

- **1C1103 の外径境界が重なっている。** 780〜799 は「全面」と「強度UP」の
  両方に該当し、先勝ちで「全面」。990 超は上書きしない (→ Q1)
- **1C1258「外径指定」に隙間がある。** 700 未満・1330 超・小数は該当なし (→ Q2)
- **UFalmo だけ丸めが逆。** オーダー重量指定からの積数が、本体は切り捨て、
  バリ揃えは切り上げ (→ Q5)
- **高さ超過で先に飛ぶと、リプラ「可変」は 30 ではなく 0 として扱われる。**
  VBA が厚みを2度入れていて、`GoTo` の位置で使う値が変わる
- **重量だけで決めた枝は `Exit Function` で抜ける。** 積数 20・検入数 20 の
  ように `x = 1` になる組で、最後の `If Not x = 1` を通らない
- **`IsNumeric(RiplaC) = False` の枝は通らない。** `RiplaC` は `Long` 宣言で
  常に数値。HB枚数を2倍にする枝は死んでいる

## 移植で直した不具合

- **Python は識別子を NFKC 正規化する。** 半角カナ(`ｺｲﾙ間は間紙入`)や
  全角英字(`Ｗ`)をそのまま属性名にすると、静かに DB の列名とずれます。
  手元側は正規形に統一し、取り込み元の表記は `import_specs` の文字列
  リテラルにだけ残しました。`tests/test_schema_contract.py` が見張ります

- **「多重起動」は2つあり、塞いでいたのは片方だけでした。** プロセスの
  二重起動(下記)は塞いでありましたが、**同じアプリをブラウザのタブで
  2枚開ける**ほうが空いていました。作業状態(`app/session.py`)は
  プロセスに1つなので、2枚開くと2枚とも入力できて**同じ1つの状態を
  奪い合います**。しかも打った値は相手の画面に出ないので、
  上書きされたことに本人が気づけません。

      タブA: LotNo 1234567 を打つ  → 状態 = 1234567
      タブB: LotNo 7654321 を打つ  → 状態 = 7654321
      タブA: 計算Start            → **7654321 で計算される**

  `app/screen.py` で、**使ってよい画面を1枚に絞りました**(下記)。

- **多重起動の防止に隙間がありました。** ロックを見る → ポートを選ぶ →
  待ち受ける → ロックを書く、が別々の手順なので、**その1秒ほどの間に
  もう1つ起動すると両方とも「ロックなし」と見ます**。結果、2つの
  バックエンドが上がり、ロックに書かれた pid は実際に応答している
  プロセスと別のものになります(止めたはずが止まりません)。
  この一連を `launch_guard.startup_gate()` で**1つずつしか通さない**
  ようにしました。順番待ちに入ったほうは待ってからロックを見るので、
  先に上がったほうへ合流します。
  関門そのものはロックとは別のファイル(`<mode>.start`)で、
  POSIX は `fcntl.flock`、Windows は `msvcrt.locking` を使います。
  **関門が取れなくても起動は続けます**(fail-open)── ここで止めると、
  関門の不具合がそのまま「アプリが二度と起動しない」になります。
  `tests/test_launch_guard.py` が、別プロセスからの同時起動で見張ります
