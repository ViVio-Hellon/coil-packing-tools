# 変更履歴

版は `config/app.json` の `version` ただ1つが出どころです。
CSS/JS のURLにこの版が入るので、**上げ忘れなければ必ず取り直されます**
(統合版では中身の指紋も一緒に入るので、上げ忘れても取り直されます)。

**統合版(コイル梱包ツール)では版が2つあります。** この機能の版(ここ)と、
統合ツールの版(統合アプリの `config/app.json`)です。この機能の中身(画面・計算・
印刷・DB)を変えたら**この機能の版を上げ、統合ツールの版も上げます**(配る単位は
統合ツールのため)。画面の帯の版を押すと、両方の版が並んで出ます。

### 履歴から明細票（紙面）を作り直す

画面の上の **「履歴」** に **「探す」** と **「選んだ紙面を開く」** を足しました。

1. 出力日（はじめ・おわり）と、必要ならロット番号（前方一致）・副番（例 `1-10`）で **探す**

これまで出力した明細は、**ロットを切り替えると消えていました**（VBA と同じ
作り）。あとから「このコイルはどの紙に載ったか」を追ったり、何枚出したかを

### 何を残すか

| 表 | 1行 | 主な列 |
|---|---|---|
| 明細履歴 | 紙1枚 | ロット番号・No・出力日時・本数・重量合計・用途名・材質・調質・板厚・板幅・設備コース・受注番号・包装仕様NO・書き足したサイズ/LOTNO・右上の文字・状態（有効/作り直し）・紙面を開いた回数と最後の日時・出力PC・ログインID・版・送信ID |

### どう残すか


- 共有に鍵を置いて **1台ずつ**書きます。1枚ごとの `送信ID` で、送り直しても二重に
  なりません。送っている最中に書き足しがあれば、送れたことにせず送り直します
- **3年**より前は、共有も手元も1日1回整理します

### 見る（CSV）

画面の上の **「履歴」** → 期間（出力日）とロット番号（前方一致）→ **「CSVに書き出す」**。
**ブラウザのダウンロードではありません**（現場の指定）。アプリのフォルダの `export` に

| ファイル | 1行 | 使いどころ |
|---|---|---|
| 明細 | コイル1本（紙の情報つき） | このコイルはどの紙か |
| 集計 | 出力日 × PC | 枚数・本数・重量合計・作り直した枚数 |

- 副番 `1-10` は Excel が日付（1月10日）に読み替えるので `="1-10"` の形で書きます。
  `=` などで始まる打ち込み文字も同じ形にして、式として動かないようにしています

1. 梱包資材マスタの表の ID=1 → あればこれ（**正**）
2. 無ければ（ファイル・表・行が無い、値が空）→ 控えのJSON
3. それも無ければ既定の `NLM.NAGOYA.QA`

- **管理者パスワードはJSONだけ**です。表は値の列が1つで、撹拌した値を入れると

## VER 0.8.0 — 紙面の右上の文字と管理者パスワードを全ラインで共有した（※置き場所は VER 0.9.0 で梱包資材マスタへ）

**印刷は止めません。** そのPCが最後に共有から読んだ値で刷り、**紙面の画面に

> 共有の設定に届かないため、右上の文字はこの端末が2026-09-25 06:17:31に読んだ
> 値で刷ります。ほかのラインで変えていても、まだ反映されていません。

**変えるほうは断ります**（そのPCだけ違う文字になるのを防ぐため）。設定画面の
ボタンも止まり、理由が出ます。ネットワークが戻れば、紙面を前に戻したとき・
次に開いたときに元どおりになります。

読みかけの1本を一緒に待つようにしました。

- 共有に鍵ファイルを置いて **1台ずつ書きます**。右上の文字とパスワードを別の

### 確かめたこと

アプリを2つ立てて（手元のDB・設定は別、共有フォルダだけ同じ）、2台のラインPC

| | 結果 |
|---|---|

でした。**変えていなければ VBA と同じ紙面です。**

### 変え方

「設定」のいちばん下、**「紙面の右上の文字」** の枠で、新しい文字と
管理者パスワードを入れて **「右上の文字を変える」**。元に戻すときは
**「既定に戻す」**。どちらもパスワードが要ります。

- **パスワードが違えば何も変えません**（設定ファイルに1バイトも書かない）。
  理由はダイアログの中に出て、パスワード欄は空に戻ります
- **20文字まで。** 長すぎるものは理由を言って断ります（黙って削らない）。
  空にはできません
- 改行・タブは空白に、見えない制御文字は落とします
- 置き場所の保存（「保存して取り込み」）には、これまでどおりパスワードは
  要りません ── **守る対象を増やすほど、現場はパスワードを紙に貼る**ため

### いつ効くか

**次に開く紙面から、新しい文字で刷られます。** 紙面は開くたびにその場で
組むので、前に出力した明細の刷り直しも新しい文字です。

**開いたままの紙面も差し替わります。** 設定を開く前に紙面のタブを開いて
いた場合、そのまま刷ると古い文字が出てしまうので、

- 変えた瞬間に、アプリの画面から紙面へ知らせて差し替える
- 知らせが届かなかった紙面も、**前に戻したとき**にいまの文字を聞き直す

ようにしました。

確かめたこと（実際の画面の操作で）:

| | 結果 |
|---|---|
| パスワードが違う | 403 で断る。文字は変わらず、次の紙面も元のまま |
| パスワードが合う → すぐ「印刷」 | 開いた紙面が新しい文字。古い文字はどこにも残らない |
| 変える前に開いていた紙面 | 知らせで差し替わる |
| 知らせが届かない紙面（別のウィンドウ） | 前に戻したときに追いつく |
| 既定に戻す | 次の紙面も、開いたままの紙面も元に戻る |

### 長い文字も欄からはみ出さない

右上の欄（E1:F1）は、刷ったときの幅が約43mmです。全角20文字を8ptで
刷ると収まらないので、**刷る前に字を小さくして合わせます**（全角20文字で
約6pt）。短い文字はふだんの8ptのままです。

- 幅は**紙の上の値**で比べます。紙面の画面はウィンドウの幅に合わせて伸び
  縮みするので、画面で測ると「画面では収まるのに紙でははみ出す」になります
- 字の大きさは pt で決めるので、狭い窓で開いても同じ大きさで刷られます
- 念のため、欄の外へは描かないようにしてあります（紙の端から5mmの内側を
  越えない）

### 管理者パスワード

梱包資材総合ツールと**同じ仕組み・同じ既定値**です（同じ現場の人が使う
ので、覚える値を増やさない）。このアプリの VBA にはパスワードが無かった
ので、**Web版で足したもの**です。

- 「設定 → 管理者パスワードを変える」で変えられます（いまのパスワードが要る）
- 変えた値は**撹拌して**持ちます（平文で置かない）。ログにも応答にも出しません
- 忘れたら、設定ファイルの `admin_password` の行を消すと既定に戻ります
  （画面から戻せると、確認の意味がなくなるため）
- **UIガードです。** 押し間違いで変えられないためのもので、本来の意味での
  アクセス制御ではありません

### 端末ごとです

右上の文字も管理者パスワードも、**変えた端末だけに効きます**（設定ファイルは
利用者ごとのローカル領域）。ラインPCそれぞれで変えてください。取り込み元の
共有フォルダは読むだけで書かないので、全ラインで共有する置き場所はありません。

### 試験の設定ファイル

これまで試験は、**本物の設定ファイル**（利用者ごとの領域）を読み書きする
作りでした。今回の試験がそこへ右上の文字やパスワードを書くと、その端末で
次に刷る紙が変わってしまうので、**試験のあいだは使い捨てのフォルダを指す**
ようにしました。

## VER 0.5.1 — 裏に回したりスリープしたりしても終わらないようにした

別に作ったツールで、**ブラウザが裏のタブのタイマーを間引くために心拍が
途切れ、アプリが誤って終わる**ことがありました。このツールでも起きるか
を実機で確かめたところ、**起きていました。**

ブラウザは裏に回ったタブのタイマーを間引きます。Chrome は5分を過ぎると
**1分に1回**まで、Edge のスリープタブは**完全に止めます**。PCのスリープ
ではサーバごと止まります。一方このアプリは、

- 心拍が **50秒** 途切れたら、画面を「居ない」とみなす（空き判定）
- 心拍が **90秒** 途切れたら、プロセスを終える（自動終了）

ので、どちらも超えます。直す前のコードで再現した結果です
（時間を本番の約1/10に縮めて、心拍をネットワークで止めて確かめました）。

| | 起きたこと |
|---|---|
| 裏で心拍が空き判定を超えて途切れる | 前に戻って操作した瞬間に `409 screen_taken`。**他のタブは無いのに**「この画面は引き継がれました」 |
| 裏で心拍が自動終了を超えて途切れる | **プロセスが終わる**（別ツールと同じ） |
| スリープから戻る | **戻った直後にプロセスが終わる**。止まっていた時間をまとめて「心拍なし」と数えるため |

### 直したこと

| | どうしたか |
|---|---|
| **裏に回るとき** | その場で「裏に回った」と伝える（`sendBeacon`。直後に凍結されても届く） |
| **裏にいるあいだ** | 心拍が止まっても**終了しない・空きにしない**。前に戻る合図を待つ |
| **持ち主の心拍** | **どれだけ遅れても受ける。** 断るのは、そのあいだに別のタブが取ったときだけ |
| **前に戻ったとき** | すぐ心拍を送る（タイマーを待たない。実測 4〜5ms）。アプリが生きているか・開き直されていないかも確かめる |
| **スリープから戻ったとき** | 画面は**時計の飛び**で気づいて同じことをする。サーバは**見張りの刻みの飛び**で気づいて、止まっていた時間を数えない |
| **開き直されていたとき** | 「アプリが開き直されています」と出して「読み込み直す」。以前は「引き継がれました」と**事実と違う理由**が出るところだった |

**終わるべきときは今までどおり終わります。**

- 前に居るのに心拍が途切れた（ブラウザが落ちた）→ 90秒で終わる
- タブを閉じた（前でも裏でも）→ 8秒で終わる

### 試験で見つかった取りこぼし

タブを閉じると、ブラウザは「裏に回った」と「閉じた」を**両方**送ります。
届く順は決まっていません。**後から来た「裏に回った」が閉じた合図を
取り消して、閉じたのに終わらなく**なっていました。「裏に回った」は
閉じた合図を取り消さないようにしました。

### 裏のままブラウザが落ちたら

閉じた合図が来ないので、プロセスは終わりません。それでも困りません。
次に `Start.vbs` を押すと、多重起動の判定が生きているプロセスを見つけて
そのままブラウザを開きます。**版が違えば古いほうを終わらせて立て直す**
ので、入れ替えた新しい版が動かない、ということもありません。
止めたいときは `stop.bat`。

### 確かめたこと

実機（Chromium）で12場面・22項目、すべて OK。時間は本番の約1/10。

```
A  裏で空き判定を超えて途切れる        → 前に戻ってそのまま操作できる
B  裏で自動終了を超えて途切れる        → 終わらない・そのまま操作できる
S  スリープ（サーバとページを止める）   → 戻ってすぐ終わらない・操作できる
F  前に戻る                           → すぐ心拍（4〜5ms）
H  裏に回る                           → その場で合図
K  ページの時計が飛ぶ                  → スリープからの戻りに気づく（10秒進んだだけでは騒がない）
C1 前に居て心拍が途切れる              → 今までどおり終わる
C2 裏のまま閉じる                      → 終わる
C3 裏で止まっている画面                → 空きにしない（2枚目は断る）
C4 再読込                              → 終わらない
C5 前で閉じる                          → 今までどおり終わる
R  裏のあいだに開き直された             → 「開き直されています」→ 読み込み直して使える
```

自動終了の見張りには試験が1件もありませんでした（流用元からの持ち込み）。
28件足して 274件です。

### 確かめ方で私が2度まちがえたこと

- ヘッドレスの Chromium は、別のタブを前に出しても元のタブを「見えない」に
  しません。CDP の凍結も受け付けるだけでタイマーは止まりません。
  **凍結したつもりで、心拍は2秒ごとに届いていました**（通ったのは偽物）。
  心拍をネットワークで止める形に改めました
- 検証用にDBを空にして始めたので、ロットが引けず、**「ロットが選ばれて
  いない」の 409 を「締め出された」の 409 と取り違えました。** 断られた
  理由（`code`）まで見るように改めました

## VER 0.4.0 — 印刷の前にサイズ・LOTNOを書き足せるようにした

**VBA は紙がExcelシートだったので、刷る前にセルへ打ち込めました。**
Web版は紙面がHTMLなので、同じことを紙面の上でできるようにしました。
流用元（python-web-tools）の `printing.editable()` と `edit_url` の
仕組みをそのまま使っています。

### どこに出るか

```
A列          B〜C列           D列             E〜F列
種類質別     (空けたまま)
寸法         サイズ   ←書き足し  小ラベル添付(D3)
検番         LOTNO    ←書き足し
```

- **A列の文字の行に揃えました。** A2:A4 は3行を1つに結合して中央寄せ
  なので、「寸法」「検番」の文字は2行目・4行目の真ん中には無く、
  中央に3行固まっています。書き足しも同じ大きさ・同じ行の高さで3行
  組んで中央に置いたので、横に揃います（実測で差 0〜1px）
- **B〜C列に収めました。** D〜F列は現物のラベルを貼る場所で、上から
  貼れば隠れます。「小ラベル添付」は VBA の `Cells(3, 4)`＝**D3 の
  位置**に置き直しました（以前は B〜F の中央。ずれは 0.4mm でした）
- **空なら何も印字しません。** 書き足さなければ VBA の紙面と同じです

### 書き足しの残し方

流用元はメモリに置いて「別のロットを検索するまで」残していますが、
こちらは**タブを閉じるとプロセスが終わる**ので、メモリでは消えます。
`明細出力` の行に `手入力サイズ` / `手入力ロット番号` を足して、そこに
持たせました。ロットを切り替えると明細ごと消えるので、残る長さは
流用元と同じです。

- **古いDBには列を足します**（`db._ADDED_COLUMNS`）。業務の記録の表は
  作り直せないので `ALTER TABLE`。明細は1枚も消しません
- **作り直された明細には書きません。** No指定で上書きすると行が作り
  直されて `管理番号` が変わります。古い紙面を開いたままだと、前の
  明細への書き足しが新しい明細へ紛れ込むので、409 で断ります
- **1枚でも書けなければ1枚も書きません。** まとめて開いた紙面で一部だけ残ると、
  刷った紙と記録が食い違います
- **20文字まで。** 欄の幅は約47mmで、9pt太字なら半角20字ほどです。
  切れて刷られるより、入れる前に理由を出して断ります

### 流用元の仕組みに足したもの

`printing.py` は流用元の写しなので、足したのは次の3つだけです。

- 案内文を帳票ごとに差し替えられるように（`edit_hint`）
- **断られた理由を出す。** 以前は「保存できませんでした」だけで、
  長すぎたのか紙面が古いのかが分からなかった。理由は消さずに残す
- **貼り付けは文字だけ。** 別の画面から写すと太字や色まで付いてきて
  紙に出る一方、保存するのは文字だけなので、刷った紙と記録が食い違う

### 確かめたこと

実機で17項目（打ち込み → 保存 → 開き直して残る → 紙に出る位置 →
用紙1枚 297.0×209.9mm → 印刷では点線も案内も出ない → 空なら何も
出ない）。試験は26件足して 247件。

## VER 0.3.1 — 書き込みの確実さを点検して直した

DB・同時実行まわり19項目を実機で確かめました。**重大なものが1つ**、
直すべきものが3つ見つかりました。

### ★ 書けていないのに「出力しました」と出ていた

`execute_with_retry` は失敗を**戻り値**で返しますが、11か所のうち
**9か所が戻り値を捨てて**いました。ロックに当たると、

```
画面        : 「出力しました。No3を確認してください。」
実際のDB    : 明細出力 0行 / 副番履歴 0行
```

となります（No指定の経路で再現。通常の経路は `next_seq` が例外を
投げるので偶然に助かっていました）。

**`db.write()` を足し、書けなければ例外にしました。** 業務の記録は
すべてこちらを通ります。画面には 503 と理由が出ます。

### 出力が1つのまとまりになっていなかった

DELETE → INSERT → 副番登録 → 連番 → 印刷済フラグ が**別々に確定**
していたので、途中で失敗すると

- 明細は残ったが副番が登録されず、次に同じコイルを出しても警告が出ない
- 連番だけ進んで明細が無い

がありえました。`db.transaction()` で**全部書けるか、1行も書かないか**
にしました（ロット切替の後始末4つ、途中経過の保存2つも同じ）。

### ロックされると無言で90秒以上固まっていた

| | 直す前 | 直した後 |
|---|---|---|
| 1文あたり | 10秒 × 4回 + 待機6秒 = **46秒** | — |
| 1操作あたり | 文の数だけ積み上がり **90秒超** | **13.5秒** |

まとまりごとにやり直すようにし、`busy_timeout` を 4秒へ下げました
（手元DBは端末ごとで、書き込みはプロセス内で1つずつ通しているので、
外から握られること自体が異常です。待っても直りません）。
**取り込み元（共有の上）は別**で、上流が書いている最中に当たるのが
普通なので 10秒のままです。

### 取り込んでも、開いているロットは古いままだった

実測で確認しました。

```
ロットを開く    用途名 = ﾄｳﾖｳﾊｸｼﾞ
台帳が更新される
取り込む
1操作する       用途名 = ﾄｳﾖｳﾊｸｼﾞ   ← 古いまま
ロットを引き直す 用途名 = ヘンコウシタ  ← ここで初めて変わる
```

**黙って読み直すのは駄目です** ── 「修正する」で手入力した前工程
実績数が消えます（LS4LOT に無いロットではこれが常用手段）。
どちらを選ぶかは利用者にしか決められないので、取り込みのあとに
**事実だけ**出すようにしました。

### 手元DBが共有フォルダに置かれても止められなかった

禁止は**コメントだけ**で、環境変数1つで置けてしまいます。
`config.db_path_problem()` を足し、UNCパス／ネットワークドライブなら
**起動時のログとバージョン情報**に理由を出します。起動は止めません
（1台で使っているうちは動くので、落とすと「昨日まで動いていたのに」
になります）。

### 問題が無かったもの

| 見たところ | 結果 |
|---|---|
| Access特有の処理 | 残っていない。`SELECT TOP` はVBAを説明する注釈の中だけ |
| SQL方言 | 全文が素のSQLite。値はすべて `?`、識別子は内部定数のみ |
| DB接続の保持 | 要求ごとに開いて閉じる。40回操作してもDBのfdは**0** |
| 読み取り中に別が書く | WALが効いていて**待たされない**(実測 0.000秒) |
| 連番の同時採番 | 8本同時でも重複なし（条件付き更新） |
| 取り込み元への書き込み | 1バイトも書かない。`-wal`/`-shm` も作らない |
| 長時間放置 | 心拍が続くかぎり終わらない。副番履歴はロット切替で全消去、途中経過は5件で頭打ち |
| セッション切れ | 古いトークンは401「開き直してください」 |
| 日付変更 | 業務判断に日付を使っていない（記録の日時だけ） |

### 複数PCについて

**このアプリは複数PCで1つのDBを共有しません。** 手元DBは端末ごと
（`%LOCALAPPDATA%`）で、共有フォルダ上の台帳は**読むだけ**です。
ライン間で副番履歴と連番を共有したい場合は、ファイルを共有するのでは
なく**サーバを1台に寄せて**ください（書き込みが1プロセスに集まるので、
ロック競合そのものが起きません）。

## VER 0.3.0 — 画面は1枚しか開けないようにした

**タブを2枚開くと、同じ作業状態を奪い合っていました。** 実際に試すと
こうなります。

```
タブA で ロット L7110P0 を開く
タブB で ロット L5160Z0 を開く
タブA で1回操作する
  → タブAの画面が L5160Z0 に化ける   ← ここ
```

作業の状態（開いているロット・条番号・積み上げ）は `session.py` が
**プロセスに1つ**持っています。VBA が `frmCoilPacking` を1枚しか
開かなかったのと同じ持ち方で、そこは変えていません。ところが Web版は
タブを何枚でも開けるので、2枚目が同じものを掴みます。

自分が開いたはずのロットが触った瞬間に変わるので、**現物と紙が食い違う
事故**になります。2枚目には業務の画面を出しません。

### プロセスの多重起動とは別の話です

`launch_guard` が見ているのは「Pythonが2つ走っていないか」で、これは
これで必要ですが、**タブを2枚開くのは止められません**（プロセスは1つの
ままなので）。別の仕掛けが要ります。

### どこで見分けるか

**サーバだけでは再読込（F5）と2枚目を区別できません。** ブラウザは
再読込のとき、**古いページを畳む前に次の要求を送る**からです。
器（HTML）を出すところで断ると、F5 のたびに断ることになります
（最初そう作って、実際にそうなりました）。

見分けはブラウザ側で行い、サーバは**名乗り**を受けて断ります。

| 使うもの | 何を見分けるか |
|---|---|
| `sessionStorage` | タブごとに違い、**再読込では消えない**名前。同じ名前の名乗り直しは通す＝F5 は素通り |
| `BroadcastChannel` | いま他のタブが居ないかを直接きく。**タブの複製**は名前ごと写されるので、名前だけでは見分けられない |
| サーバの名乗り（`/api/screen/claim`） | 上の2つが使えない環境の受け皿 |

**器は誰にでも返してよい**ようにしました ── 業務データは名乗ってからで
ないと触れないからです。

### 本当の歯止めはAPI側です

画面を出す・出さないは見た目の話で、すり抜けることがあります。
**持ち主でない画面の操作は、サーバが 409 で断ります**
（`screen_taken`）。引き継がれた古いタブは、次に操作した時点で畳まれ、
理由が出ます。

除くのは2つだけです。

- `/api/screen/*` … 持ち主を変える口そのもの
- `/report/*` … **帳票は別のタブで開きます**（`window.open`）。
  そのタブは画面を持っていないので、ここで断ると印刷できなくなります。
  盤面は触らずDBから引くだけです（トークンは要ります）

### 開けなくなったときのために

- 心拍が **50秒**とだえたら、その画面は居ないものとして扱います
  （タブが落ちた・強制終了した場合）
- タブを閉じると**すぐ空きます**（閉じる合図に相乗りさせています）
- 「この画面で使う」で明示的に引き継げます。**2枚になるのではなく、
  移ります。** 引き継ぐ側は、開き直す前に前のタブへ知らせます ──
  知らせないと、開き直した先で「まだ他のタブが居る」と見えて
  **いつまでも入れません**（これも実際に踏みました）

## VER 0.1.0 — VBAからの移植

Excel VBA 版（`frmCoilPacking` ＋ 標準3・クラス3モジュール／3,235行）を
Python + Flask へ移しました。既存 `python-web-tools`（梱包資材総合ツール）の
基盤をそのまま流用しています。

### 流用したもの

起動・停止・監視は移植元のものを持ち込み、**手順そのものには手を
入れていません**。

- `Start.vbs` / `start.bat` / `stop.bat` / `start_app.py` / `launch_guard.py`
  / `boot_server.py` / `server.py` / `process_manager.py`
- `source_db.py` — 共有フォルダ上の sqlite3 を3段で開く
  （URI `mode=ro` → 素＋`query_only` → 手元へ写す）
- `printing.py` — Excel を使わず `@page` CSS で紙面を組む
- `sqlite_toolkit.py` / `logging_utils.py` / `app_config.py`
  / `boot_screen.py` / `idle_exit.py`

モードは1つしかないので `meisai/modes.py` に単一モードを置きました。
起動基盤がロック名とポートをモード名で決めているため、受け口だけ残して
あります。

### 取り込みで吸収した差

取り込み元の実データを読んで分かったことが2つあります。**どちらも
変換を挟まないとVBAの判定が成立しません。**

| 列 | 取り込み元 | そのまま引くと | 変換後 |
|---|---|---|---|
| `ｵｰﾀﾞｰ板丈` | TEXT の `'0.0'`（`'0'` ではない） | `= '0'` も `= 0` も **0件** | `to_real` → `= 0` で 7,826行 |
| `当工程設計_縦割数` | 型宣言なしの `'2'` | `= 2` が **0件** | `to_int` → `= 2` で一致 |

### VBAと結果が変わらないようにしたところ

RULE-01〜10（`README.md` 参照）。条数配分は**VBAの手順を書き下した
参照実装**と 0〜299本 × 1〜20丈の全組合せで突き合わせています。

> **実データでは配分の余りが一度も出ません。**
> 前工程実績数 = 縦割数 × 横割数、丈数 = 縦割数 なので必ず割り切れます。
> 余りが出るのは作業者が丈数か前工程実績数を手で直したときだけなので、
> その形も期待値に残してあります（`tests/golden/lot_cases.json`）。

### 実装中に見つけて直したもの

**出力後に積み上げたコイルが未使用へ戻っていた。**
VBA は `ClearGimmickC` しか呼ばず「Cスロットのみ。Bは出力後もそのまま
残す」とコメントしています。**同じコイルを次の梱包へ二重に積ませない**
ための仕掛けなので、落とすと現物と紙が食い違います。

**取り込みの鮮度をパスで引いていた。**
共有に届かない端末で「取り込んであるのに未取込」と出ていました。
実績はテーブル名で引き、到達性（`found`）とは分けて持ちます。
導いた値（`as_of` / `imported`）は `SourceStamp.to_dict()` が1か所で
決めます ── `__dict__` をそのまま渡すと受け取った側が `found` から
組み立て直すことになり、同じ取り違えが再発します。

**`hidden` が効いていなかった。**
`.work{display:grid}` のようにクラスで `display` を指定すると、
ブラウザ既定の `[hidden]{display:none}` に勝ちます。隠したつもりの
カードが出たままになっていたので、`[hidden]{display:none !important}`
を1つ置きました。

**上の帯の区切りが詰まっていた。**
Jinja の `{%- endfor -%}` が全角空白を空白として刈り取るため、
実体参照（`&#12288;`）で書いています。

**説明書の強調が行をまたぐと壊れていた。**
Markdown を1行ずつ組んでいたためです。段落は「空行までの連続した行」
なので、まとめてから組むように直しました（試験が見つけました）。

### 方式を変えたところ

| VBA | Web版 |
|---|---|
| Access(.accdb)＋ADO＋ACE | sqlite3（標準ライブラリのみ） |
| 隠しシート「副番履歴」 | SQLite の表 |
| Excel シート生成＋`PrintOut` | HTML＋`@page` CSS（Ctrl+P） |
| `MsgBox ... vbYesNo` | 確認ダイアログ（`confirm` を受け取る形） |
| 共有フォルダの説明書HTML | アプリ同梱の `docs/説明書.md`（`/docs`） |
| `DebugLog` | `logging_utils`（利用者ごとのローカル領域） |

### 残っているもの

- **VBAの実出力との突合。** 台帳側の期待値は作成済みですが、
  現場の紙（入力と、そのとき出た明細表）と突き合わせていません
- **実機での印刷確認。** 余白と実寸はブラウザの設定に左右されます
