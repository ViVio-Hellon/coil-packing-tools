# コイル梱包明細打ち出しシステム (Python / Web版)

アルミコイルを梱包するときに貼る **梱包明細表** を作るツールです。
Excel VBA 版(`frmCoilPacking`)を、社内「汎用Webアプリ作成 基盤仕様書」に
沿って Python + Flask へ移しました。

## これは何をするものか

1本の母材ロットは、丈(たて)方向に切り分けられ、さらに横方向に条(じょう)へ
割られるので、1ロットから `縦割数 × 横割数` 本のコイルが生まれます。
各コイルは `丈番号-条番号`(例 `2-15`)で識別され、これに Lot番号を冠した
ものが **副番**(例 `L5160Z0-2-15`)です。

作業者は現物を積む順にコイルをクリックし、**その並びをそのまま紙に出します。**

```
ロット番号(7桁)を打つ
  → 仕掛台帳から ロット情報 / 受注番号 / 包装仕様NO を引く
  → 前工程実績数(= 縦割数 × 横割数)を丈へ配分して条番号を作る
  → 丈ごとの重量を入れる
  → 積む順にクリックする
  → 梱包明細表を出す → A4横で印刷し、右半分を切り取る
```

**明細表1枚につき用紙1枚。A4横の左半分に刷り、右半分は空けます。**
現場は右半分を切り取って使っています（用紙のサイズの運用上）。
A4 1枚に2枚並べる運用はしていません。

VBA も同じ紙面でした。`FitToPagesWide/Tall = 1` は**縮めるだけで
引き伸ばさない**ので、1面（A1:F20）は等倍のまま左半分に出ます。

**文字・罫線は紙の端から5mm以上内に置きます（上下左右、切り目の側も）。**
プリンタは紙の縁から約4mmを刷れません。VBA は余白0・等倍でしたが、
そのままだと刷ると左と上が欠けていました（VER 0.6.0）。このぶん明細は
VBA より幅で約7%・高さで約5%小さくなります（比率は実ブックのまま）。
余白は `@page` ではなく紙面の中で取っています ── 印刷ダイアログの
「余白なし」で `@page` の余白は上書きされるためです。

```
行の高さ  23.25 + 42×3 + 18.75 + 28.5×15 = 595.5pt = 210.06mm = A4の高さ
列の幅    10.375 + 12.375 + 12×4 = 70.75                 = A4横の幅の半分
```

## 起動と停止

| ファイル | 用途 |
|---|---|
| `Start.vbs` | **ふだんはこれをダブルクリック。** コンソールを出さずに起動します |
| `start.bat` | 起動しないときの診断用。コンソールに理由が出ます |
| `stop.bat` | 明示的に止めるとき |

`start.bat --check` は実行環境の確認だけをして終わります。

ブラウザのタブを閉じると、少し待ってからバックエンドも終わります
(基盤仕様書 2.8)。**作業の途中経過は操作のたびに保存してある**ので、
開き直せば同じところから続けられます。

**裏に回しても・スリープしても終わりません。** ブラウザは裏のタブの
タイマーを間引く(Chrome は1分に1回、Edge のスリープタブは止める)ので、
画面は裏に回るとき合図を送り、サーバはその間の心拍の途切れを数えません。
スリープからの戻りは、画面は時計の飛び、サーバは見張りの刻みの飛びで
気づきます(`app/static/js/health.js` / `meisai/idle_exit.py`)。

### 画面は1枚だけ

**2枚目のタブには業務の画面を出しません**(`meisai/screen.py` /
`app/static/js/screen.js`)。作業の状態はプロセスに1つしかないので
(`session.py`)、2枚開くと同じ盤面を奪い合い、**先に開いた画面のロットが
触った瞬間に化けます。**

プロセスの多重起動(`launch_guard`)とは別の話です ── タブを2枚開いても
プロセスは1つのままなので、あちらでは止まりません。

再読込(F5)と2枚目は**サーバからは見分けられません**(ブラウザは古い
ページを畳む前に次の要求を送るため)。見分けは `sessionStorage` と
`BroadcastChannel` で行い、サーバは名乗り(`/api/screen/claim`)を断ります。
**本当の歯止めは API 側**で、持ち主でない画面の操作は 409 で断ります。

## データの出どころ

共有フォルダに置かれた sqlite3 ファイルを、**手元のSQLiteへ取り込んでから**
使います。画面と業務ロジックは手元のテーブルしか見ません。

| 取り込み元 | 置き場所 | 手元の表 | 何に使うか |
|---|---|---|---|
| `SIKALOT.sqlite3` | `\\nlmsrvngy03\Read\【New】仕掛\台帳` | 仕掛ロット | ロット情報 |
| `SIKAHIKI.sqlite3` | 同上 | 仕掛引当 | 受注番号 |
| `SIKAODR.sqlite3` | 同上 | 仕掛受注 | 包装仕様NO |
| `LS4LOT.sqlite3` | `\\nlmfangyshrd\…\梱包課\梱包課共有\仕掛` | 仕掛当工程 | **縦割数・横割数** |

置き場所は設定画面と環境変数(`PACKING_DETAILS_LOT_DB_DIR` /
`PACKING_DETAILS_KONPO_DB_DIR`)で差し替えられます。共有に届かない端末では
アプリのフォルダに写しを置いても拾います。

### LS4LOT は代替できません

仕掛ロットにも `BOX設計_縦割数 / 横割数` がありますが、実データで
突き合わせると **532件中340件(64%)が `当工程設計_*` と食い違います。**
前工程実績数と丈数は `LS4LOT` から採ってください。

`LS4LOT` は LS4ラインの現在仕掛だけなので、載っていないロットは
前工程実績数が0になります。その場合は画面の「修正する」で手入力します
(VBA にギミックAがあるのはこのためです)。

## VBA版との主な違い

**業務上の結果・判定・計算・出力内容は同じです。** 変えたのは実現方法だけ。

| VBA | Web版 | なぜ |
|---|---|---|
| Access(.accdb)＋ADO＋ACE | sqlite3(標準ライブラリ) | 上流が sqlite3 化された。ACE も追加ライブラリも不要 |
| `SELECT TOP 1` | `LIMIT 1` | 方言 |
| `ｵｰﾀﾞｰ板丈='0'` | `オーダー板丈 = 0` | **取り込み元の実値は `'0'` ではなく `'0.0'`。** 素で移すと1件も一致しない(下記) |
| 半角カナの列名 | 全角へ正規化 | 取り込み時に対応表で寄せる |
| 隠しシート「副番履歴」 | SQLite の表 | ブックに依存しない |
| Excel シート生成＋`PrintOut` | HTML＋`@page` CSS | Excel が無い端末でも印刷できる |
| A4横の左半分に1面（`FitToPages` は縮めるだけ） | 同じ（左半分に1枚、右半分は空ける） | 現場は右半分を切り取って使う |
| 余白0・等倍（紙の端から罫線） | 紙の端から5mm内に置く（約7%小さい） | プリンタは縁から約4mmを刷れない。刷ると左と上が欠けていた |
| 副番・重量は `MergePut` で `xlCenter` | 同じ（中央） | VER 0.6.0 より前は左・右に寄せていた（誤り） |
| E1:F1 に `"NLM.NAGOYA.QA"` を書き込む（変えるにはコードを直す） | 既定は同じ。**設定画面で変えられる・全ラインで共有**（管理者パスワード要。`qa_mark.py`） | 現場の要望。変えていなければ VBA と同じ紙面 |
| シートを直してから `PrintOut` | 紙面の上で**サイズ・LOTNO**を書き足してから印刷 | 紙がHTMLなのでセルに打てない。流用元の `printing.editable` を使う |
| `MsgBox ... vbYesNo` | 確認ダイアログ | 1往復で返せないので `confirm` を受け取る形に |
| `DebugLog` | `logging_utils` | 利用者ごとのローカル領域へ |

### 取り込みの変換が要る理由

取り込み元は **全列 TEXT**(`LS4LOT` は型宣言すら無い)で、実値はこうです。

```
ｵｰﾀﾞｰ板丈        '0.0'   ← '0' ではない
当工程設計_縦割数  '2'     ← 数値ではない
```

そのため取り込み元を**直接引くと**、VBA の条件は1件も一致しません。

```sql
-- 取り込み元を直接引いた場合(全13,624行中)
WHERE "ｵｰﾀﾞｰ板丈" = '0'    →      0 行
WHERE "ｵｰﾀﾞｰ板丈" = 0      →      0 行
WHERE "ｵｰﾀﾞｰ板丈" = '0.0'  →  7,826 行
```

`import_specs` の対応表で `to_real` / `to_int` を通し、数値の列へ入れることで、
以後は素直に `= 0` と書けます。**この変換が移植の要点です。**

## 運用上の注意

### 書き込みの決まり

**業務の記録はすべて `db.write()` / `db.transaction()` を通します。**
`execute_with_retry` は失敗を戻り値で返すので、捨てると「書けていない
のに成功」になります(実際になっていました。VER 0.3.1)。

- 1操作 = 1トランザクション。**全部書けるか、1行も書かないか**
- 書けなければ `db.WriteError` → 画面に 503 と理由
- ロックを待つのは**まとまりごとに最大13.5秒**。手元DBは端末ごとで
  書き込みはプロセス内で直列化してあるので、外から握られるのは異常
  (待っても直らない)。取り込み元(共有の上)は別で10秒待つ

### 全ラインで共有する設定

**紙面の右上の文字（既定 `NLM.NAGOYA.QA`）と管理者パスワードは、全ラインで
1つ**です。置き場所は**梱包資材マスタのフォルダ**（梱包資材総合ツールと同じ）:

```
\\nlmfangyshrd\各課共有\0130_日軽稲沢\梱包課\AIM\【■】_参照用ファイル\
  梱包資材マスタ.sqlite3   表「梱包明細打ち出し」の ID=1 の行 … 右上の文字の正
  梱包明細打ち出し.json   右上の文字の控え・管理者パスワード（撹拌済み）
```

- **右上の文字は梱包資材マスタの表が正**（VER 0.9.0）。表は現場が Access で作り、
  総合ツールの「表を持ってくる」で足したもの（`CREATE TABLE "梱包明細打ち出し"
  ("ID", "設定文字列")`）。総合ツールのマスタ管理で直しても、次の紙面から効きます
- **表（か ID=1 の行）が無ければ控えのJSON**、それも無ければ既定。JSONは
  このアプリが変えるたびに一緒に書き、マスタのほうが直されていたら合わせます
- マスタへは `設定文字列` の1列を書き換えるだけ（ID=1 が無ければ1行足す）。
  **表を作らない・形を変えない・ほかの表に触らない**。表が無いときはJSONにだけ書きます
- マスタが読めない（掴まれている・壊れている）ときは、控えで刷り、紙面の画面に
  そう出します。**変えるほうは断ります**（JSONにだけ書くと、あとで黙って戻るため）
- **管理者パスワードはJSONだけ。** 表に入れると総合ツールのマスタ管理に出て、
  そこで直せてしまうため
- **梱包資材マスタは DELETE で置いてください**（総合ツールと同じ注意。WAL だと
  共有の上では読めず、書けません）
- 共有に届かないときも印刷は止めません（そのPCが最後に読んだ値で刷り、画面にそう出す）。
  共有が応えないときも、紙面を開くのを **2秒以上待たせません**
- 別の場所を使う場合は、各PCの「設定 → 置き場所・取り込み → 梱包資材マスタのフォルダ（共有）」（管理者パスワード要）
  か環境変数 `PACKING_DETAILS_SHARED_DIR` で。マスタの名前は `PACKING_DETAILS_MASTER_DB`。
  **全ラインで同じ場所を指さないと共有になりません**

### 明細の履歴（全ライン・3年）

`明細出力` はロットを切り替えると消えます（VBA の `DeleteLotSheets` と同じ）。
あとから追う・数えるために、**出力と同じまとまりで消えない履歴にも書きます**
（VER 0.10.0。`meisai/slip_history.py`）。

```
手元のDB(このPC)     明細履歴 / 明細履歴_副番   … 出力と同じまとまりで先に書く
  ↓ 裏で送る(出力・書き足し・紙面を開いたらすぐ。届かなければ5分ごと)
共有 梱包明細履歴.sqlite3  明細履歴 / 明細履歴_副番 / 整理記録   … 全ライン
  (梱包資材マスタと同じフォルダ。このアプリが DELETE で作る)
```

- **共有へ直接書きません。** 手元に先に書くので、ネットワークが切れても失いません。
  送るときは共有に鍵（`梱包明細履歴.sqlite3.lock`）を置いて1台ずつ書きます
- 1枚ごとに一意の `送信ID`。送り直しても二重になりません。送ったあとに変わる値
  （書き足し・紙面を開いた回数・作り直し）は、送り直すと共有も書き換わります
- **3年**より前は、共有も手元も1日1回整理します（`config.HISTORY_KEEP_YEARS`）。
  `VACUUM` はしません（共有の上でファイルを丸ごと作り直すことになるため）
- 画面の「履歴」で**探す**（期間・ロット番号・副番）・**紙面を作り直す**（履歴の中身の
  とおりに明細票を組み直す。読むだけ。`/report/history?ids=…`）・**CSV に書き出す**
- CSV は `export/`（`PACKING_DETAILS_EXPORT_DIR`）に書いて場所を出すだけ。**ブラウザの
  ダウンロードはしない・こちらから Excel やフォルダを開かない**（現場の指定。開くのは
  使う人）。UTF-8 の BOM 付き・CRLF。副番 `1-10` のように Excel が日付や式に読み替える
  値は `="1-10"` で書きます
- **無ければ作ります**（VER 0.12.0。`slip_history.ensure_shared`）。ファイルが無い・空・
  表が無い・表が消えた → 表を作る。手で作った表で列が足りなければ足す（既定値のある列）。
  主キーが無ければ一意の索引を足す。**足せない列（送信ID など）が無い表には触らずに断る**。
  作るときは送りと同じ鍵を取る。そろっていれば読むだけで帰る。共有に届かなければ作らない
- **梱包資材総合ツールのマスタ管理には出ません。** あちらが開くファイルは決まっています
  （梱包資材マスタ.sqlite3 とパレット閾値マスタの2つ）。代わりに、このアプリの
  「マスタ管理（見るだけ）」で見られます（下）

### マスタ管理（見るだけ）

総合ツールのマスタ管理のうち、**「中身を見る」ところだけ**を移しました（VER 0.12.0。
`meisai/master_browse.py`・`app/routes/master.py`・`app/static/js/master.js`。
総合ツールの `master_browse.py` / `views/master.js` が元）。**総合ツールには手を入れていません。**

- 見るファイルは2つ: **梱包資材マスタ**（`shared_settings.master_path()`）と
  **梱包明細履歴**（無ければ作ってから開く）
- 総合ツールと同じ決まり: 表は全部出す／200行ずつ・出さなかった分は数で言う／
  絞り込みはどの列でも／並べ替えは**実在する列だけ**（`ORDER BY` に組み込むため。
  ほかは既定の並びに戻す）／`rowid` を `__行` で持ち回る
- このアプリで足したこと: 共有を待つのは15秒まで（応えないまま残っている読み込みが
  あれば重ねずに断る）／明細履歴は出力日時の新しい順／`%` `_` は文字どおり／
  CSV に書き出す（全行・いまの絞り込みと並べ替えのまま・Excel の行数まで）
- **直すところは移していません。** 誰が直せるか（アクセス権限・管理者パスワード）の
  決まりが総合ツールにあり、ここから書けるとその決まりを通らずにマスタが変わるため。
  読むのは読み取り専用で開いた接続だけ（`source_db.open_read_only`）
- 画面の書き込みの順番待ちに入れません（`/api/master/`。共有を待つことがあるため）

### 設定画面(欄ごとに保存・すぐ開く)

- タブ: 置き場所・取り込み / 紙面の右上の文字 / 管理者パスワード / 配布設定
  (`app/static/js/settings.js`)。**ボタンは欄ごと**(まとめて保存するボタンは無い)
- 仕掛台帳のフォルダ・梱包課共有の仕掛フォルダは「保存して取り込み」で、**その欄の
  取り込み元だけ**取り込む(`/api/import` に `{"only": "lot"|"konpo"}`、
  `data_sync.import_all(only=…)`)
- 梱包資材マスタのフォルダ(共有)は置き場所の面に出してある(管理者パスワード)。
  マスタ管理の「届きません」から「設定で置き場所を変える」でその欄へ飛べる
- **開いてすぐ出す。** `/api/settings` は共有・取り込み元を見に行かない
  (`data_sync.stamps(check=False)`)。届くか・共有の様子は `/api/settings/share` で
  後から埋める(取り込み元を探すのは `REACH_WAIT_SEC` = 5秒まで)
- 取り込みの進み具合は `/api/import/progress`(何を読んでいるか・n/m・経過秒)。
  画面は進み具合の窓を出す(`app/static/js/ui.js`)
- 待っている間は「…（N秒）」を出す(`ui.waiting`)。履歴・マスタ管理も先に開く

### 配布設定(梱包資材総合ツールから移した)

`meisai/distribution.py`。1台で決めた設定を、アプリのフォルダごと配った先で使う。

- 書き出すと `配布設定\設定.json` と `はじめに読む.txt`(置き場所は環境変数
  `PACKING_DETAILS_DISTRIBUTION_DIR` で変えられる)。作ってから入れ替える(書きかけを残さない)
- 起動時(`start_app._initialize`、**取り込みより先**)に、**その端末に無い項目だけ**読む。
  「読み込み直す」は上書き。書き出す・読み込み直す・消すは管理者パスワード
- **空の値は「無い」と同じ**(`distribution.is_set`)。以前の設定画面は空の欄も空のまま
  保存していたので、空を「ある」と見ると配った設定が黙って効かない
- 設定.json の値は形を確かめる(置き場所は空でない文字・自動取り込みは真偽)。違う項目は
  読まずに理由を出す。壊れていれば設定画面に「読めません」
- 書き出し直しは、前のものを `.前` によけてから置き、失敗したら戻す(前の配布設定を壊さない)
- 項目: 仕掛台帳のフォルダ・梱包課共有の仕掛フォルダ・梱包資材マスタのフォルダ・
  起動時の自動取り込み。**管理者パスワードと右上の文字は入れない**(全ラインで共有しているため)
- 総合ツールの `make_dist`(配布用フォルダを作る)は移していない

### 管理者パスワード

**紙面の右上の文字を変えるとき・梱包資材マスタのフォルダ（共有）を差し替えるとき・配布設定を書き出す／読み込み直す／消すときだけ**要ります。
取り込み元の置き場所・自動取り込みには要りません ── 守る対象を増やすほど、
現場はパスワードを紙に貼るようになります（流用元と同じ考え）。

- 既定は梱包資材総合ツールと同じ値（`meisai/config.py` の `ADMIN_PASSWORD`）。
  配るときに決めたければ環境変数 `PACKING_DETAILS_ADMIN_PASSWORD` で上書き
- 画面の「設定 → 管理者パスワード」のタブで変えられます（**全ライン**）。変えた値は
  **PBKDF2 で撹拌して**共有に持ち、ログにも応答にも出しません
- 忘れたら、共有の `梱包明細打ち出し.json` の `admin_password` の行を消すと
  全ラインで既定に戻ります
- **UIガードです。** 押し間違いで変えられないためのもので、本来の意味での
  アクセス制御ではありません（共有フォルダを開ける人はファイルも触れます）

### 手元DBの置き場所

**手元のDB(`%LOCALAPPDATA%\PackingDetails\data\`)は端末ごとです。**
このファイルを共有フォルダに置かないでください。SQLite はネットワーク越しの
ファイル共有だとファイルロックが正しく効かず、複数台から同時に使うと
壊れることがあります。

副番履歴と連番をライン間で共有したい場合は、ファイルを共有するのではなく
**サーバを1台に寄せて**各PCがブラウザで繋ぐ形にしてください(書き込みが
1プロセスに集まるので、ロック競合そのものが起きません)。
