# デスクトップ版(Tauri)の作り

統合 1.1.0 から、ブラウザで開く代わりに**専用の窓(exe)**で動かせるようになりました。
**ポートを使いません。** ブラウザ版(`Start.vbs`)もそのまま残してあり、予備として使えます
(ただし**同時には動きません**。下の「ブラウザ版とのすみ分け」)。

作りは、移行済みの `ViVio-Hellon/python-web-tools`(VER4.0.0)と同じです。

## 何が何をするか(各言語が得意なことをする)

```
コイル梱包ツール.exe(Rust / Tauri)               … src-tauri/
 ├─ 窓(WebView2)・印刷プレビューの窓・終了の確かめ・2つ目の起動の防止
 ├─ CSS・JS・画像を直接返す(Python を通さない)
 ├─ Python を子として起動・見張る(落ちたら理由の画面)
 └─ 画面の要求(app://…)を受けて、Python の標準入力へ渡す
        │ 標準入出力(1件 = 見出し1行 + 本文)
        ▼
bridge.py(Python)                                … ポート無しの入口
 └─ Flask アプリを WSGI として呼ぶだけ(待ち受けない)
        ▼
app.py・common/・modules/(Python)                … 業務の計算・取り込み・画面の組み立て(変わらず)
 └─ Access(.accdb)は今までどおり cscript.exe → VBScript → ADODB → ACE
        ▼
static/js・modules/*/static(JS)                  … 画面の操作(変わらず。窓まわりだけ desktop.js)
```

| 担当 | 理由 |
|---|---|
| **Rust**: 窓・起動・終了・2つ目の起動の防止・Python の見張り・静的ファイル | OS の窓とプロセス・ファイルロックを扱うのが得意。exe 1つで配れる。静的ファイルは Python を通さないぶん速い(実測 4.3ms → 1ms) |
| **Python**: 取り込み・計算・SQLite・Access・画面の組み立て | 実測で重い処理は無い(画面の要求は中央値 2ms、最大 89ms)。VBA と同じ結果を守る試験(統合アプリと3機能で約 1,800件)がこの形で書かれている。書き直す利点が無く、危険だけがある |
| **VBScript**: Access(ACE)の読み書き | 各ラインPCには ACE があるが、Python に追加の部品を入れられない。標準の cscript.exe から ADODB で読む今の形を変えない |
| **JS**: 画面の操作 | 今までどおり。デスクトップ版のときだけ、別窓・アプリの外のリンク・窓を閉じるを外枠に頼む(`static/js/desktop.js`) |

## ポートを使わない仕組み

- 画面は独自の宛先 `app://localhost/`(Windows の WebView2 では `http://app.localhost/`)を読む。
  これは**ネットワークを通らない**(外枠の中で受ける名前)
- 外枠はその要求を Python の標準入力へ渡し、標準出力から応答を受け取る(`src-tauri/src/bridge.rs` と `bridge.py`)。
  CSS・JS・画像は、Python が起動時に知らせる置き場所(Flask の static)から外枠が直接返す
- 起動トークン・Host の確認・画面の取り合いの確認など、アプリ側の守りはそのまま生きている
- 試験で確かめていること:
  - `tests/test_bridge.py`: ソケットを開くと落ちるようにして Python を起動しても、3機能の画面・操作・終了が通る
  - `scripts/desktop_smoke.py`: exe を本当に起動し、exe・Python・WebView の**どのプロセスもポートで待ち受けていない**
    (GitHub Actions の Windows でも流す)
  - `tools/desktop_e2e.py`: 窓を実際に操作する通し試験(開発機の Linux。下の「確かめたこと」)

画面の「ポート」の欄は「なし（デスクトップ版）」と出ます(ペナラベルのフッタ・診断、梱包明細・資材計算の設定画面)。

## 動きの約束

| 場面 | 動き |
|---|---|
| 起動 | 窓がすぐ出て「起動しています」→ 待機画面(取り込みの進み具合)→ 統合画面 |
| もう1つ起動しようとした | 新しく起動せず、開いている窓を前に出す(OS のファイルロック `runtime\desktop.lock` でも止める) |
| 窓の × / 統合画面の「終了」 | どちらも統合画面の「終了」と同じ確かめを出す。「キャンセル」なら続けて使える。画面が固まっていて確かめが出せないときは、3秒で閉じる |
| 印刷プレビュー(11種類) | 別の窓で開く。「印刷する」で印刷の窓、閉じればその窓だけ閉じる。窓は白地のまま(画面の色の切り替えを受けない) |
| 画面の色(自動 / ライト / ダーク) | 開いている別の窓にも届く |
| 資材計算の閲覧システム(アプリの外のリンク) | 既定のブラウザで開く(アプリの窓では開かない) |
| 包装仕様NOのコピー | 今までどおりクリップボードへ |
| Python が見つからない・起動できない | 理由と次にすること(Python の入れ方・pip の打ち方)・ログの場所を窓に出す |
| Python が途中で落ちた | 窓を読み直して理由の画面を出す |
| exe を止めた | 標準入力が閉じるので Python も終わる(取り残さない) |

Python は**同梱しません**。各PCに入っている Python を使います(`python.exe` → `py.exe -3` の順に探す。
`COIL_PACKING_TOOLS_PYTHON` で指定もできる)。必要な部品は **Flask だけ**です
(ブラウザ版で入れてあるものをそのまま使う。waitress はブラウザ版だけが使う)。
Python はコンソールの窓を出さずに起動します。Access を読む cscript.exe も同じです。

## ブラウザ版とのすみ分け

ブラウザ版とデスクトップ版は**同じ手元のDB・作業状態**を使うので、同時には動かしません。

| 動いているもの | 後から起動したもの | 動き |
|---|---|---|
| ブラウザ版 | デスクトップ版 | 窓に「ブラウザ版のコイル梱包ツールが動いています」と出して使わせない(ブラウザの「終了」か stop.bat で止めてから) |
| デスクトップ版 | ブラウザ版 | 「デスクトップ版のコイル梱包ツールが動いています」と出して起動しない |
| 統合前の単体版(3機能を別々に動かしていたころのもの) | デスクトップ版 | 「統合前の単体版が動いています」と出して、止めてからと案内する |

デスクトップ版は動いているあいだ `%LOCALAPPDATA%\CoilPackingTools\runtime\desktop.lock` を握っています。
落ちれば OS が外すので、印が残って起動できなくなることはありません。

## 作り方

**Windows 版は GitHub Actions が作ります**(`.github/workflows/desktop-windows.yml`「デスクトップ版(Windows)」)。
このブランチに push するたびに、Python の試験(統合アプリと3機能)・Rust の試験・exe の作成・
exe を起動しての確認まで流れ、成果物 `CoilPackingTools-windows` に `CoilPackingTools.exe` が入ります。
Actions の画面の「Run workflow」からも流せます。

配るとき:

1. 成果物から `CoilPackingTools.exe` を取ってきて、アプリのフォルダの**直下**に置く
2. `scripts\make_dist.bat` を流す(またはペナラベルの設定画面の「配布用フォルダを作る」)。
   `コイル梱包ツール.exe` の名前で配布フォルダに入る(`--exe` で場所を指定もできる)。
   外枠のソース(`src-tauri`)と `.github` は配らない

手元で作るとき(開発機):

```
cd src-tauri
cargo build --release            # target/release/CoilPackingTools(.exe)
python ../scripts/desktop_smoke.py --exe target/release/CoilPackingTools    # Linux は xvfb-run を前に付ける
python ../tools/desktop_e2e.py --exe target/debug/CoilPackingTools          # 窓の通し試験(Linux)
```

Linux で作るには WebKitGTK が要ります(`libwebkit2gtk-4.1-dev` など)。窓の通し試験には
Xvfb・WebKitWebDriver・tauri-driver(`cargo install tauri-driver`)も要ります(現場の PC には要りません)。

## 置き場所の決まり

- exe は `bridge.py` と同じフォルダに置く(上の階層もたどるので、`src-tauri/target/...` から動かしても見つかる)。
  `COIL_PACKING_TOOLS_ROOT` で指定もできる
- 版は `config/app.json`・`src-tauri/tauri.conf.json`・`src-tauri/Cargo.toml` の3か所。食い違うと試験が落ちる
- アイコンは `scripts/make_desktop_icon.py` で作る(`src-tauri/icons/`)

## 確かめたこと

開発機(Linux・WebKitGTK)で窓を実際に操作して(`tools/desktop_e2e.py`、39項目すべて OK):

- 3機能の一連の流れ(梱包明細のロット読み込み・出力、ペナラベルの重量反映・風袋計算、資材計算のロット・計算)
- **11 の印刷プレビューがすべて別の窓で開き**、「印刷する」が押せて、閉じられる
- 画面の色が別の窓にも届く・印刷の窓は白地のまま・上の帯の「ログ」・包装仕様NOのコピー
- 閲覧システムは窓の中で開かない・画面を離れた合図が Python まで届く
- 「終了」と窓の ×:「キャンセル」なら残る・「OK」なら exe も Python も終わる
- 2つ目の exe は起動せずに終わる(1つ目はそのまま)
- Python が無いとき・ブラウザ版が動いているときは窓に理由が出る。デスクトップ版が動いているとブラウザ版は起動しない
- どのプロセスもポートで待ち受けない・exe を止めると Python も終わる

速さ(開発機の実測): 起動から待機画面まで 0.6〜0.95秒(ブラウザ版 1.1秒)、静的ファイル 1ms(ブラウザ版 4.3ms)。

## 確かめきれていないこと(Windows の実機で見る)

Windows では GitHub Actions が「起動して画面が届く・待ち受けない・止めたら Python も終わる」まで確かめます。
次は**実機で人が見る**必要があります:

- 印刷プレビューの「印刷する」から実際に紙が出ること(WebView2 の印刷の窓)。紙の端から5mm以上内側に収まること
- 窓の × で確かめが出て、「キャンセル」で残ること
- 資材計算の閲覧システムのリンクが既定のブラウザで開くこと
- Ctrl+P(印刷プレビューの窓で)
- 2つ目の起動で、開いている窓が前に出ること
- Access(ACE)の読み込み(cscript.exe がコンソールの窓を出さずに動くこと)
- 起動の速さ。GitHub Actions の Windows では起動から待機画面まで 8〜12秒かかった(窓はすぐ出て
  「起動しています」と出る)。試験の設定で毎回 .py を翻訳し直す(`PYTHONDONTWRITEBYTECODE`)うえ、
  ウイルス対策の検査も入るため。現場の PC は2回目から翻訳済みのもの(手元の領域の `pycache`)を使う
