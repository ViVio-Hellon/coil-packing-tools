# 変更履歴(統合アプリ)

## 版の決まり

版は**統合ツールの版と3機能の版を分けて**持ちます(`common/versions.py`)。混ぜません。

| 種類 | 出どころ | いつ上げるか | 変更履歴 |
|---|---|---|---|
| 統合ツールの版 | `config/app.json` の `version` | **配るたび。** 統合画面・共通部分・起動/停止/配布を変えたとき、または機能の版が1つでも上がったとき | このファイル |
| 梱包明細の版 | `modules/packing_details/config/app.json` | 梱包明細の中身(画面・計算・印刷・DB)を変えたとき | `modules/packing_details/docs/変更履歴.md` |
| ペナラベルの版 | `modules/packing_pena_label/app/config.py` の `APP_VERSION` | ペナラベルの中身を変えたとき | `modules/packing_pena_label/docs/変更履歴.md` |
| 資材計算の版 | `modules/packing_material_calculation/config/app.json` | 資材計算の中身を変えたとき | `modules/packing_material_calculation/docs/変更履歴.md` |
| 移植元の版 | 各機能の `__init__.py` の `PORTED_FROM` | 変えない(取り込んだときの記録) | ― |

- 機能の番号の付け方は、その機能のまま(移植元と同じ「メジャー.マイナー.パッチ」)
- 画面の帯の版(`VER1.0.0`)を押すと、統合ツールと3機能の版・移植元が並んで出ます。
  タブにもそれぞれの機能の版が出ます
- **起動時の入れ替え判定は、統合ツールの版と3機能の版の組で比べます。** 機能の版だけを
  上げて配っても、古いプロセスに合流せずに入れ替わります
- CSS・JS の URL には「版-中身の指紋」が入るので、版を上げ忘れても古いものは使われません
- 配布メモ(`配布メモ.txt`)・起動時のログ・`/api/health` にも、4つの版が分けて出ます

### 1.2.3

**デスクトップ版(ブラウザではない窓)で印刷が変わらないかを点検した**(現場の問い: ブラウザではない窓に

  `window.print()` は WebView2 がそのまま受ける(窓の部品 wry の Windows の印刷も `window.print()` を

  「余白なし」「背景のグラフィック」などは引き継がず、PC ごとに初めて刷るときは既定(余白は既定・
  背景のグラフィックなし)になる。2回目からはその窓で選んだ設定を覚える
- そこで、**初めて刷るときの既定でも、設定済みと同じ紙面になるか**を本物の紙面 10種類(19枚)で
  比べた(`tools/print_edge_check.py` に足した。枚数・紙の大きさと向き・インクの1点ずつ)。

  (余白0なのでヘッダー・フッター(日付や URL)も刷られない)。
  **ペナラベルの全サイズの印刷ビューだけ、小さな字が濃く刷られた**(背景のグラフィックが無いと

  ほかの9種類は1点も違わなかった。紙の端から5mm以上内側もすべて満たす

### 1.2.2

移行後の一通りの再点検(現場の依頼: 別のリポジトリのツールが移行後に不具合だらけだった。こちらも
もう一度一通り試験しなおす)。移行の手本の python-web-tools で移行後に見つかった不具合
(確かめの窓が出ずに「OK」扱い・落としたファイルが空で届く・壊れた作業用DBで起動しない・共有のファイルを
掴んだまま)と同じ種類を探し、現場の PC(日本語の Windows 11・Microsoft Store の Python 3.12)と
GitHub Actions(英語の Windows・python.org の Python)の違いも洗った。

- **手元のDBが壊れていても起動を続ける**(梱包明細 0.13.14・資材計算 0.2.13・ペナラベル 1.5.14)。
  わざと壊して起動すると、ペナラベルの状態DBでは**統合アプリごと起動せず**、梱包明細では画面が 500、
  資材計算では「初期化に失敗しました」のまま使えなかった。壊れていたら横へ退けて(消さずに)作り直す
  (`common/db_recover.py`)。設定ファイル(JSON)は壊れていても起動が続くことを確かめた
- **Microsoft Store の Python で、画面に出す場所を実際に置かれている場所にする。** Store の Python は
  `%LOCALAPPDATA%` の下に作るファイルを自分だけの場所(`…\Packages\PythonSoftwareFoundation.Python.3.12_…
  \LocalCache\Local\…`)に置き換える(CPython の Store 版は 3.11 からレジストリの置き換えだけ止め、
  ファイルの置き換えは続いている)。Python の外(エクスプローラー・ブラウザ・exe)からは見つからないので、
  - ブラウザ版の「起動できませんでした」の画面が**開かなかった**(ブラウザがファイルを見つけられない)→ 開く
  - デスクトップ版の起動できないときの画面・待機画面・上の帯の「ログ」・各機能の設定画面の「保存先」に出す
    場所を、実際の場所にした(`app_config.real_location`)。Python が知らせられないときは exe が Store の
    場所も添える
  - デスクトップ版の Python も「動いている」印(`runtime\\desktop-python.lock`)を握り、ブラウザ版は exe の錠と
    2つを見る。exe と Python とで同じ名前でも別のファイルを見ることがあっても、ブラウザ版とデスクトップ版を
    同時に動かさない
  - Store の Python の版を変える(3.12 → 3.13 など)と置き場所も変わることを README に書いた
- **窓の通し試験を GitHub Actions の Windows でも流す**(`tools/desktop_e2e.py`)。現場と同じ WebView2 の窓を
  Microsoft Edge WebDriver で操作し、確かめの窓(confirm)が本当に出て「キャンセル」で止まること・印刷
  プレビュー11が別の窓で開くこと・窓の × ・2つ目の起動・起動できないときの理由までを確かめる
  (これまで Windows の窓は「起動して画面が届く」までしか自動で見ていなかった)
- 確かめたこと(すべて通った): 統合アプリと3機能の試験を Python 3.10・3.11・3.12・3.13 で /
  アプリを**日本語と空白の入ったフォルダ**(OneDrive のデスクトップのような所)に置いて試験・exe の起動 /
  ブラウザ版の通し試験(3機能の流れ・印刷・交互・複数タブ・保存先・マスタ・後追い・画面の色・説明書・放置)/
  デスクトップ版の窓の通し試験 / 手元のDB・設定ファイルを壊しての起動
- `scripts/desktop_smoke.py`: 1.2.1 で調べ方を変えたのに窓の通し試験の呼び方を直していなかった(ポートの段が
  落ちる)のを直した

### 1.2.1

- **デスクトップ版が日本語の Windows で起動できなかったのを直した**(1.2.0 の実機で
  「起動に失敗: 起動中に思わぬエラー: argument of type 'NoneType' is not iterable」)
  - 原因: 外枠(exe)が Python を **UTF-8 モード(`-X utf8`)** で起動していた。起動時の確かめ
    (統合前の単体版・前回の起動の印が残っていれば、そのプロセスが生きているかを `tasklist` で見る)で、
    日本語の Windows の `tasklist` は「情報: 指定された条件に一致するタスクは実行されていません。」を
    **cp932** で返す。それを UTF-8 として読もうとして読み取りが落ち(`UnicodeDecodeError`)、
    結果が空(None)になって起動の確かめごと止まっていた。英語の Windows(GitHub Actions)では
    この文が出ないので試験をすり抜けていた。ブラウザ版(`Start.vbs`)は UTF-8 モードではないので起きない
  - 直したこと:
    - 外枠は Python を **UTF-8 モードで起動しない**(ブラウザ版と同じ。標準入出力だけ UTF-8 を指定)
    - `tasklist`・`wmic` の出力は**バイトのまま受け取り**、端末のコードページ(cp932)→ UTF-16 の順に
      読み分ける。どう読んでも落ちない
    - `wmic` の無い Windows 11 では PowerShell(`Get-CimInstance`)で代わりに調べる
    - 統合前の単体版が動いているかを見分けられなくても、**起動は止めない**(ログに残して進む)
    - 外枠が Python のエラー出力を読むところも、文字コードが合わなくても読み続ける
  - 試験: `tests/test_windows_console.py`(日本語の `tasklist` の出力を UTF-8 モードの Python で読ませ、
    1.2.0 の作りでは同じ `UnicodeDecodeError` で落ちることを確かめたうえで、直した作りで通る)・
    外枠が Python を UTF-8 モードで起動しないこと(`tests/test_bridge.py`)
- **梱包明細 0.13.13**: 2台がほぼ同時に共有へ書いたとき(右上の文字・管理者パスワード・明細の履歴)、
  まれに「共有フォルダに書けません: [Errno 13] Permission denied: '….lock'」と断られていたのを直した。
  Windows では、ほかの端末が鍵を消している最中に鍵を作ろうとすると「アクセスが拒否されました」になる。
  少し待って取り直す(本当に書けない共有なら2秒で今までどおり断る)。GitHub Actions の Windows で
  同時に書く試験がまれに落ちて見つかった。
  マスタ管理で、共有が応えないときに続けて押すと、まれに前の読み込みに重ねて読みに行っていたのも直した
  (Windows の時計の刻みで「まだ時間内」と読み違えていた)
- ペナラベル 1.5.13 / 資材計算 0.2.12 は変わらない
- exe を起動して確かめる台本(`scripts/desktop_smoke.py`): 「exe を止めても残ったプロセス」を、番号だけでなく
  起動した時刻でも見分ける(Windows は終わったプロセスの番号をすぐ使い回すので、残っていないのに
  残っていると読み違えることがあった)。残ったときはプロセスの名前も出す
