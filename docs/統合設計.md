# 統合設計 ── 3つの Python Web ツールを1つの Flask サーバ・1つの画面へ

対象

| 機能 | 移植元リポジトリ | 統合版の置き場所 | 入口(URL) |
|---|---|---|---|
| 梱包明細 | `ViVio-Hellon/packing-details-python-web` (VER 0.13.1) | `modules/packing_details/` | `/details/…` |
| ペナラベル | `ViVio-Hellon/packing-pena-label-python-web` (v1.5.0) | `modules/packing_pena_label/` | `/pena/…` |
| 資材計算 | `ViVio-Hellon/packing-material-calculation-python-web` (VER 0.2.0) | `modules/packing_material_calculation/` | `/material/…` |

**統合とは、機能を1つにまとめることではない。** 1つの Flask サーバを起動し、
1つのブラウザ画面に「梱包明細」「ペナラベル」「資材計算」のタブを設け、
タブ切替で各機能を独立して使えるようにすること。業務の計算・入力チェック・
DB処理・帳票は**3機能とも移植元のまま**動く。

## 1. 調査で分かったこと(統合の前提)

| 起動基盤 | `start_app.py` `launch_guard.py` `server.py` `boot_server.py` `process_manager.py` | 同名5本だが**別実装**(`InstanceLock` / `ExclusiveHTTPServer` / `loading.html` を file:// で開く) | 梱包明細とほぼ同じ + `startup_gate`(起動の順番待ち) |

### 1.2 そのまま載せると衝突するもの

| 衝突 | 何が起きるか | 統合版の解き方 |
|---|---|---|
| **URL**: `/` `/api/health` `/api/alive` `/api/shutdown` `/api/settings*` `/api/master/*` `/api/screen/*` `/report/*` `/static/*` `/settings` が3つとも根にある | 同じ経路に3つは置けない | 機能ごとに入口(`/details` `/pena` `/material`)を切り、その下に**移植元の経路をそのまま**置く。画面のリンク・JS は入口を受け取って付ける |
| **パッケージ名**: 3つとも `app` | `import app` が1つしか指せない | `modules.<機能>.app` の下に置く(サブパッケージ名は `app` のまま。root の `app.py` とは衝突しない)。`meisai` `coil_tool` も `modules.<機能>.` の下へ |
| **テンプレート名**: 資材計算の `base.html` と統合画面の `base.html` | Flask はテンプレート名を全体で解決する(アプリ側が先勝ち) | 資材計算側を `material_base.html` に改名(4か所の `extends` を直すだけ。画面は変わらない) |
| **CSS / JS**: `.card` `.btn` `.toast` `.hint` `[hidden]`… 同名クラス、`window.APP`、`document` 全体の入力フィルタ、`html,body{overflow:hidden}` | 1つの文書に3つを流し込むと、見た目も動きも壊れる | タブの中身は **iframe**(機能ごとに別の文書)。統合画面の外枠は `static/css/shell.css` `static/js/shell.js` だけを持つ |
| **ポート**: 8733 が2つ | 同時起動できない | 統合アプリは **8740**(候補 8740〜8743)。従来の単体アプリとも重ならない |
| **多重起動の判定**: 3つとも `/api/health` の `app_id` を照合 | 統合アプリの身元が要る | 統合アプリ `nlm.coil-packing-tools`。各機能の `/…/api/health` は各機能の身元を名乗り続ける |
| **自動終了**: 梱包明細・資材計算は「心拍が途切れたら終わる」、ペナラベルは終わらない | 1つのプロセスで矛盾する | 見張りを**プロセスに1つ**にし、3機能の画面と外枠の心拍を全部そこへ届ける。**生き死には画面ごとに持ち**、1枚でも生きていれば終わらない。3機能の別タブ(帳票・印刷ビュー)も自分で心拍を送る(ペナラベルの移植元の「使っている間は止まらない」を守る。§2.7) |
| **停止**: 資材計算の帯に「終了」ボタン(そのプロセスを止める) | 押すと3機能とも終わる | 統合画面の外枠に「終了」を置き(3つとも終わると明記)、資材計算の「終了」もそのまま残す(同じ意味) |
| **配布設定 / 書き出し先**: 3つとも「アプリ直下の `配布設定\`」「`export\`」 | 混ざる | 統合アプリ直下の `配布設定\<機能>\` `export\<機能>\`(鍵が機能ごとに違うので**混ぜない**)。置き場所の決まりは `common/dist_settings.py` の1か所。配布用フォルダを作る処理は3機能ぶんをまとめて入れる(入れないと決めたら、どれも入れない) |
| **Access 接続**: ペナラベルだけ `cscript.exe` + VBScript + ACE | 追加ライブラリ不要のまま | そのまま(`modules/packing_pena_label/app/repositories/vbs/query_accdb.vbs`) |

## 2. 共通機能の比較と、採用したもの

「設定画面を1つにすること」と「設定値を1つにすること」は別 ── 統合版は
**どちらもしていない**(下記 2.5)。共通化したのは「入れ物」の部分だけ。

### 2.1 DB 接続・トランザクション・排他制御

| | 梱包明細 | ペナラベル | 資材計算 | 統合版 |
|---|---|---|---|---|
| 接続 | 要求ごとに開閉(WAL) | プロセスに1本・RLock で直列化・無操作120秒で閉じる(DELETE) | 要求ごとに開閉(WAL) | **各機能のまま**。DB は3つ別ファイルで、統合の対象外(既存の DB 構成を維持) |
| 書き込みの原子性 | `db.transaction()` / `db.write()`(書けなければ `WriteError` → 503) | `Store` の中で `BEGIN`/再試行 | `execute_with_retry`(戻り値で成否) | 各機能のまま。梱包明細の「書く要求を1つずつ通す」`_WRITE_LOCK` は**梱包明細の経路だけ**に効く(3機能をまたいで待たせない) |
| 汎用の SQLite 操作 | `meisai/sqlite_toolkit.py` | ─ | `coil_tool/sqlite_toolkit.py` | **1行も違わなかった**ので `common/sqlite_toolkit.py` に1つ。機能側は取り次ぎ |

### 2.2 ログ・例外処理・エラー表示

| | 梱包明細 | ペナラベル | 資材計算 | 統合版 |
|---|---|---|---|---|
| ログ | 日付で切る `DailyFileHandler` | 容量で切る `RotatingFileHandler` | 日付で切る | **日付で切るほう**(`common/logging_utils.py`)。「13日の不具合は13日のファイル」で追える。**3機能で1つのファイル** `%LOCALAPPDATA%\CoilPackingTools\logs\coil_packing_tools_YYYYMMDD.log`。機能はロガー名で見分ける |
| 断りの形 | `{"error":{"code","message"}}` + HTTP番号 | `{"ok":false,"message"}` | `{"ok":false,"reason"}` + HTTP番号 | **各機能のまま**(画面の JS がその形を見ている) |
| 書けなかったとき | 503 `write_failed` | 500 + 文言 | ─ | 各機能のまま |

### 2.3 設定管理・パス管理

| | 梱包明細 | ペナラベル | 資材計算 | 統合版 |
|---|---|---|---|---|
| アプリ固有値(`config/app.json`) | `app_config.py` | `Config` dataclass(3層) | `app_config.py` | **統合アプリのぶんを `common/app_config.py` に1つ**(ID・表示名・版・ポート・ローカル領域)。3機能の `config/app.json` と `app_config` は**そのまま残す**(各機能の版・表示名の出どころ) |
| 端末ごとの設定値 | `user_config.json` | `local.json` | `user_config.json` | **各機能のまま、別ファイル**(値を1つにしない。鍵も意味も違う) |
| 設定画面 | 梱包明細の中 | ペナラベルの中 | 資材計算の中 | **各機能のタブの中のまま**(画面を1つにしない。項目・パスワードの関門・JS が機能ごと) |

### 2.4 マスタデータの参照・編集

共通にできるものは無い。**各機能のまま。**

### 2.7 印刷・帳票・ファイル出力

3機能とも**移植元のまま**。帳票は別タブで開く(`window.open`)ので iframe の外に出る。
経路に入口が付くだけ(`/details/report/…` `/material/report/…` `/pena/labels/print`)。
CSV は各機能の書き出し先(`export\<機能>\`)へ。**ダウンロードはしない**(現場の指定のまま)。

**統合で起きる印刷の影響と、その手当て**(紙面の中身・各機能のコードは変えない)

| 影響 | 手当て |
|---|---|
| 統合画面のタブを閉じると、開いたままの帳票ごとサーバが止まる。梱包明細の帳票は刷る前に書き足したサイズ・LOTNO をサーバへ保存し、資材計算の発注票はサーバが覚えている中身から組むので、止まると保存・再表示ができない | 統合アプリが3機能の画面の HTML に `static/js/tab_alive.js` を差し込む。**別のタブ(一番上の窓)で開いたときだけ**自分の名乗りで心拍を送る。見張りは画面ごとに数えるので、帳票が開いているあいだは止まらない。統合画面の中(iframe)では何もしない |
| ブラウザの Ctrl+P は一番外の文書(統合画面の外枠)を刷る。iframe は見えている部分しか紙に出ない | 外枠が Ctrl+P を受けて、**いま見せている機能の画面の `print()`** を呼ぶ(機能の画面の中で押しても同じ)。移植元で Ctrl+P を押したときと同じ紙面 |
| ブラウザのメニューからの印刷は止められない | 外枠の `@media print` で見出し・タブを隠し、見せている画面だけを出す(1枚目の分だけ)。README で各画面の印刷ボタンか Ctrl+P を案内 |
| 画面の中の印刷ボタン(ペナラベルの「このまま印刷」「試し刷り」)は iframe の中で `window.print()` を呼ぶ | その画面の文書だけが刷られる(Chrome/Edge は呼んだ枠を刷る)。移植元と同じ紙面。実ブラウザで確認 |
| **ペナラベルの風袋計算・羅列・全サイズが紙の端から刷られ、見切れていた**(移植元のまま)。`app.css` に印刷用の `@page` が 2 つあり、ラベル台紙用の「余白 0」が「余白 8mm」を打ち消していた。印刷ダイアログの「余白なし」でも 0 になる | 距離を紙の中で取る(`.page` の padding 8mm と `box-decoration-break: clone`。ラベル台紙・較正シートは除く)。**ペナラベル 1.5.1** で直した。試し刷りの文字・目盛りも 5mm 内へ |
| ペナラベルの移植元は根の `/favicon.ico` に中身なしで答えていた。`/pena` の下に移ったので、印刷ビューを開くたびに 404 がコンソールに出た | 統合アプリが根で 204 を返す |

### 2.8 起動・停止・多重起動(基盤)

| | 梱包明細 | ペナラベル | 資材計算 | 統合版 |
|---|---|---|---|---|
| 起動の入口 | `Start.vbs` / `start.bat` / `stop.bat` | 同名 | 同名 | **統合アプリに1組**。`run.py` は `start_app.py` と同じ入口 |
| 待機画面 | サーバ自身が出す(`boot_server`) | `loading.html` を file:// で開く(CORS が要る) | 梱包明細と同じ | **サーバが出す**ほう(CORS が要らない・`app_id` を照合できる) |
| 多重起動 | ロック + pid + health + 版の照合 | OS ファイルロック + instance.json + health + **排他 bind** | 梱包明細 + **起動の順番待ち** | **資材計算のもの**(いちばん新しく、同時押しの実測で直してある)+ **ペナラベルの排他 bind**(Windows の `SO_REUSEADDR` はポートを奪える。`server.bind_exclusive`) |
| 停止 | `process_manager`(トークンで正常終了 → pid) | `process_manager`(`--force` は netstat) | 梱包明細と同じ | 梱包明細・資材計算のもの。取り込み中は 409 で知らせ、`--force` で中断 |
| 自動終了 | あり(スリープ検知が両時計) | なし | あり(単調時計) | **梱包明細のもの**(`common/idle_exit.py`)。資材計算の呼び名(`_notice_suspend`)は別名で残し、資材計算の試験もそのまま通る |
| 守り | Host / 同一オリジン / トークン(401) | なし | トークン(403) | **Host と同一オリジンは3機能へ**(`common/security.py`)。トークンはプロセスに1つで、ヘッダの名前は2つとも受ける。**ペナラベルにもトークンを要求**(同じプロセスに同居するので、1つだけ素通しにしない)。断り方(401/403・本文)は各機能のまま |

### 各機能に残したもの(変えていない)

- 業務ロジック・判定条件・帳票仕様(`meisai/*` `coil_tool/*` `app/services/*` の中身)
- DB のスキーマ・置き場所・接続の持ち方、取り込み、マスタ管理
- 設定画面と設定値(項目・鍵・保存先・パスワードの関門)
- 画面(HTML/CSS/JS)の見た目と操作、画面の見張り(2枚目を断る仕組み)
- 断りの形(HTTP番号・本文)

| 機能 | 直したもの | 理由 |

## 4. 統合画面の作り

```
┌ 上の帯: コイル梱包ツール VER1.0.0  [梱包明細 VER0.13.1] [ペナラベル VER1.5.0] [資材計算 VER0.2.0]   接続OK [終了] ┐
│                                                                                                        │
│   <iframe src="/details/meisai?t=…">   ← 見せているタブ                                                │
│   <iframe src="/pena/?t=…"       hidden>                                                                │
│   <iframe src="/material/calc?t=…" hidden>                                                              │
└────────────────────────────────────────────────────────────────────────────────────────────────────────┘
```

- **3つとも最初に開き、タブ切替は隠すだけ(外さない)。** 入力の途中の値・条番号の盤面・
  心拍・画面の見張りが、タブを移しても続く(要件 8)
- **裏に回ったタブでタイマーが間引かれても終わらない**(要件 7)。外枠(`shell.js`)と
  3機能の画面が、裏に回るときに `state: hidden` を `sendBeacon` で送り、見張り
  (`common/idle_exit.py`)は裏の間は心拍の途切れで終わらない。前に戻ったら即座に
  心拍を送り直す。PC のスリープは時計の飛びで気づいて数え直す
- 画面の見張り(2枚目を断る)は**機能ごと**。統合画面を2枚開くと、3つの iframe が
  それぞれ「別の画面で開いています」になる。「この画面で使う」はタブごとに押す
- 「終了」は外枠に1つ(3機能とも終わる、と明記)。資材計算の帯の「終了」も残っており
  同じ意味(注意点として README に書いた)
- 帳票・印刷ビューは `window.open` で**別タブ**に出る(iframe の外)。3機能とも別タブは
  自分の名乗りで心拍を送るので、統合画面のタブを閉じても、開いている間はサーバが終わらない
  (見張りは画面ごとに数える。外枠も開くたびに新しい名乗りで送る)

## 6.5 版

**統合ツールの版と3機能の版を分けて持つ**(`common/versions.py`)。決まりの表は `docs/変更履歴.md`。

| どこに出るか | 中身 |
|---|---|
| 画面の帯 | 統合ツールの版。押すと統合ツール・3機能の版と移植元の一覧 |
| タブ | それぞれの機能の版 |
| 各機能の画面の中 | それぞれの機能の版(移植元のまま) |
| `/api/health` | `version`(統合ツール)・`versions`(4つ)・`version_set`(組を1行に)・`modules[].ported_from` |
| 起動時のログ・配布メモ | 4つの版を分けて1行に |

- **起動時の入れ替え判定は `version_set` で比べる**(`launch_guard._stale_versions`)。移植元の
  判定は統合ツールの版だけだったので、機能の版だけを上げて配ると、古いプロセスに合流して新しい
  中身が動かなかった。組を答えない古いプロセスは統合ツールの版だけで比べる
- 静的ファイルの URL は「その版-中身の指紋」。版を上げ忘れても、長く控えた古い JS/CSS を使わない
- 1.0.0 は初版なので、3機能の版は移植元の版のまま(統合のための手直しは各機能の変更履歴に
  「統合版への組み込み」として書いた)。次に機能を直すときから、その機能の版を上げる
- 1.0.1 でペナラベルの印刷を直したので、ペナラベルを 1.5.1 に、統合ツールを 1.0.1 に上げた
  (移植元の版は 1.5.0 のまま。版の一覧で並べて見える)
