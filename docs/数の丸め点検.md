# 数の丸め・切り捨ての点検(統合 1.2.6)

python-web-tools(梱包資材総合ツール)で、**取り込み・書き込みのときに数を勝手に丸め・切り捨て、
VBA と違う数を DB に書いていた**不具合が見つかりました(VER4.8.3: 注文の丈 2502.5 → 2502、
枚本数 2.9 → 2 など。原因は取り込みの `int()`)。同じ種類がコイル梱包ツールの3機能に無いかを洗いました。

- 調べ方: 取り込み(取り込み元 → 手元 DB)・画面からの入力・計算・保存(手元 DB・共有 DB・Access)・印刷の
  すべての数の変換(`int()`・`round()`・書式・切り捨て・SQL の型・JS の `parseInt` / 入力の制限)を読み、
  VBA(各機能の VBA 解析書・VBA の書き出し・移植のコメント)と比べた
- **3機能とも、問題はすべて統合の前(移植元のリポジトリ)からあったもの**です。統合で増えたものはありません
- 取り込みの経路: 梱包明細・資材計算の取り込み元は sqlite(以前の Access から置き換え済み)。ペナラベルは
  Access(cscript → VBScript → ADODB → ACE)も読みます。VBScript は値を `CStr` で文字にして渡すので、
  そこで小数は落ちません

| 機能 | 何が | VBA | 以前のツール | 影響 |
|---|---|---|---|---|
| 資材計算 0.2.15 | 製品単重・板厚・板幅・外径の書式(`Format(x,"0.00")`) | 有効数字 15 桁で見て四捨五入。106.475 → **106.48**(VBA の書き出しで確認) | 2進の値のまま偶数側へ: **106.47** | 単重は積数に使う → 台数・リプラ本数 → チェックリスト・発注票・発注履歴(境目のときだけ) |
| 資材計算 0.2.15 | 受注の 梱包単位_重量・枚数、コイル外径・内径 | 値のまま(1160.5) | **整数に切り捨て**(1160) | 外径 → パレットの選び方、重量・枚数 → 積数 → 同上。今の受注データは整数のみ |
| ペナラベル 1.5.17 | NW(正味重量) `Format(Val(本数×T1),"0.0")` | `Val` が 15 桁の文字列にしてから読む: 3 × 101.35 → "304.05" → **304.1** | 2進の値(304.0499…)のまま: **304.0** | 状態 DB・ラベル台紙・印刷するラベルの見出しの NW、GW が 1 動くことも。1条重量が小数2桁以上のときだけ |

## 直していないもの(VBA の元のコードが手元に無く、どちらが正しいか決められない・今のデータでは起きない)

業務の判断か、VBA の元のブックでの確認が要るものです。

| 機能 | 何が | 今のツール | 分からないこと・起きる条件 |
|---|---|---|---|
| 資材計算 | **1不可の Re_積数 が x.5 のとき**(積数が偶数) | 3.5 → 3 に切り捨ててリプラ本数を出す(例: 検入数13・枚数6 → 18本。物として正しいのは 20本) | VBA で Re_積数 がテキストボックス(3.5 のまま → 20本)か Long(4 → 22本)か。**切り捨ては x が奇数のときどちらとも合わない**。試験(`test_stack_edges.py`)は切り捨てを前提にしている。1不可の包装仕様(例 1C0132)で起きる。**優先して確かめたい** |
| 資材計算 | `RoundDown`(積数) | 1760 ÷ 70.4 = 24.999999999999996 を 24 にする | Excel は 15 桁で見るので 25 のはず(推定)。重量 ÷ 単重 がちょうど割り切れる組み合わせだけ(例 1056/70.4、1610/64.4) |
| 資材計算 | パレットの Ｗ・リプラ長さ(マスタ) | 整数に切り捨てて帳票・発注履歴へ | マスタは今すべて整数。マスタ管理では小数も入れられる |

| ペナラベル | 羅列計算の高さ | 整数で出す(597・8) | VBA の書式は `0.0_ `(596.9・8.4)。参考値として出す表 |
| ペナラベル | 風袋の各項目(TIP 0.00・SUT など 0.000) | NW と同じ「15 桁の文字列化」を飛ばしている | マスタの質量が小数3桁以上のときだけ。VBA の `Format` の内部の丸め次第。風袋計算の紙だけ |
| 梱包明細 | 取り込みの 縦割数・横割数 | 小数なら切り捨て | 今のデータは 1〜6 の整数のみ |
| 梱包明細 | 板厚・板幅の表示(`0.000`・`0.0`) | ちょうど半分のとき偶数側へ | 表示だけ(104.25 → 104.2、VBA は 104.3) |

## 数の変わらない作り(確かめたもの)

- マスタ管理の書き込み(ペナラベル・資材計算): 打った値を `?` で渡す。2.5 は 2.5 のまま(sqlite の型で丸まらない)。
  資材計算は "940" を "940.0" と書く(数は同じ)
- ペナラベルの入力(重量・高さ・全サイズ): 打ったままの文字で保存
- 資材計算のチェックリスト・発注票・発注履歴: 計算した文字をそのまま保存(丸めるのは計算の側。上の表)
- 梱包明細の記録(明細出力・スナップショット・履歴): 整数の重量をそのまま。紙の `Kg` は小数1桁で出す
