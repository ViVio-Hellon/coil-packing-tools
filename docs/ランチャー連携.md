# ランチャー連携(コイル梱包ツール側の用意)

「ランチャー連携 要件定義」の **3. 各ツール側への依頼** に、コイル梱包ツールとして答えるものです
(統合 1.2.4)。ランチャーは `ViVio-Hellon/python-business-tools-launcher`(業務ツール統合ランチャー)。
ランチャーはここに書いた**ファイルを実行するだけ**で、コイル梱包ツールの中身(exe・VBS・Python・
ブラウザー)を知る必要はありません。

## まとめ(ランチャーに登録するもの)

| | ファイル(アプリのフォルダの直下) | 備考 |
|---|---|---|
| 起動(どちらか1つを PC ごとに選ぶ) | `コイル梱包ツール.exe` … デスクトップ版(専用の窓) | 引数なし |
| | `Start.vbs` … ブラウザ版 | 引数 `--no-browser` を付けると、ツールはブラウザーを開かない(ランチャーが開く) |
| 起動完了の確認 | `launcher_status.bat` | 戻り値 **0 = 使える** / **2 = 起動中** / **1 = 動いていない**。どちらの版でも同じ |
| | (ブラウザ版だけ)`http://127.0.0.1:8740/api/health` | `app_id` が `nlm.coil-packing-tools` で `ready` が true なら使える |
| 終了 | `launcher_stop.bat` | 動いているほうを止める。戻り値 **0 = 止めた(動いていなかった)** / **1 = 止めなかった・止められなかった** |
| | `launcher_stop.bat --force` | 処理中でも中断して止める |

- **アプリの名前(app_id)は1つ**: `nlm.coil-packing-tools`(`config/app.json`)。exe と Start.vbs は同じツールの
  起動方法の違いなので、ランチャーには1つのツールとして登録し、配布先設定で起動ファイルを選ぶ(要件 5)
- ブラウザ版とデスクトップ版は**同時には動きません**(同じ手元のデータを使う)。片方が動いているときに
  もう片方を起動すると、理由を出して起動しません

## 3.1 現在の起動方法

```
コイル梱包ツール(アプリのフォルダ)
├─ コイル梱包ツール.exe   デスクトップ版。exe → Python(bridge.py)→ 窓の中の画面。ポートを使わない
├─ Start.vbs              ブラウザ版。VBS → pythonw(start_app.py)→ 既定のブラウザー。ポート 8740(使えなければ 8741〜)
├─ start.bat              ブラウザ版の診断起動(コンソールに経過を出す)。人が原因を調べるためのもので、ランチャーには登録しない
├─ stop.bat               人が使う停止(失敗したら理由を読ませるため一時停止する)
├─ launcher_stop.bat      ランチャーの終了口(一時停止しない)
└─ launcher_status.bat    ランチャーの起動完了の確認口
```

どちらの版も、Python は各PCに入っているもの(Microsoft Store の Python でもよい)を使います。
Access(.accdb)は今までどおり cscript.exe → VBScript → ADODB → ACE で読みます。

## 3.2 起動方法ごとに正常起動できることの確認

ランチャーと同じ起こし方(作業フォルダ = 起動ファイルの場所・標準入力なし・コンソールなし)で確かめました。

| 起動ファイル | 起動完了まで | 終了口で止まるまで | 終わったときの戻り値 |
|---|---|---|---|
| `コイル梱包ツール.exe` | 約9秒(確認口が 1 → 2 → 0) | 約2秒 | 0 |
| `Start.vbs --no-browser`(start_app.py) | 約1秒 | 約0.5秒 | 0 |

- 試験: `tests/test_bridge.py`(本物の bridge.py を、確認口で「使える」と見てから終了口で止める)・
  `tests/test_launcher_link.py`(処理中は止めない・`--force`・確認口の戻り値)・
  `tests/test_launch_files.py`(Start.vbs が引数を渡す・終了口が一時停止しない・CP932 と CRLF)
- 起動後に異常終了しないこと・3機能が使えることは、ブラウザ版・デスクトップ版の通し試験で確かめています
- **Windows の実機・ランチャーの本体からはまだ試していません**(下の「確かめきれていないこと」)

## 3.3 ランチャーから直接実行できること

- `コイル梱包ツール.exe` … そのまま実行できます。exe は自分の場所からアプリのフォルダを見つけるので、
  作業フォルダに頼りません。2つ目を起動すると、開いている窓を前に出して自分は終わります(戻り値 0)
- `Start.vbs` … `wscript.exe Start.vbs [引数]` で実行できます。**渡された引数はそのまま start_app.py へ渡します**
  (統合 1.2.4 から)。ランチャーが `--no-browser` を渡すと、ツールはブラウザーを開かず、ランチャーが起動完了を
  確かめてから画面を開きます。引数が無ければ今までどおり既定のブラウザーで開きます。
  Python が無いなど起動できないときは、理由を出して戻り値 1 で終わります

## 3.4 ツール内部の処理

exe → Python、VBS → Python → ブラウザー の順番・待ち合わせは、すべてツールの中で行います
(ランチャーに移しません)。

## 3.5 / 3.6 終了方法

`launcher_stop.bat` が、動いているほう(ブラウザ版・デスクトップ版)を止めます。

| 版 | 止め方(ツールの中) |
|---|---|
| ブラウザ版 | ツール自身に終了を頼む(`POST /api/shutdown`)。答えないときだけ、記録した PID が**本当にこのツールか確かめてから**止める |
| デスクトップ版 | ポートが無いので、このPCのローカル領域のファイルで終了を頼む(`common/desktop_control.py`)。ツールは統合画面の「終了」と同じ判断をして、exe も Python も終わる |

- **ほかの Python・exe・VBS は止めません**(名前で一括に止めることはしない)
- **取り込みなど途中で止めると困る処理の最中は止めず、戻り値 1** で終わります(画面の「終了」と同じ)。
  中断してよければ `--force`
- 終了口では「終了します。よろしいですか」の確かめは出しません(頼んだ側が決めている)
- 窓の × ・統合画面の「終了」は今までどおり確かめを出します。ランチャーの「窓を閉じる」(WM_CLOSE)で止めると
  この確かめが窓に出るので、**終了には `launcher_stop.bat` を使ってください**

## 10. 起動完了の確認

`launcher_status.bat` の戻り値で判断してください(0 = 使える / 2 = 起動中 / 1 = 動いていない)。
- 起動ファイルを実行した直後の数秒は、まだ 1(動いていない)を返すことがあります。
  **起動の待ち時間(例: 90秒)のあいだは 1 でも待ち続け**、0 になったら使える、としてください
- デスクトップ版は窓がすぐ出て「起動しています」→ 取り込みの進み具合 → 統合画面、と進みます。
  窓が出たことは起動完了ではありません(確認口が 0 になるまで待つ)
- ブラウザ版は `/api/health` でも分かります(`app_id` の一致と `ready`)。ポートは 8740 が使えなければ
  8741〜に移るので、`/api/health` の `port` を見てください

## ランチャー側へのお願い・気づいたこと(業務ツール統合ランチャー 1.6.4 の作りを読んで)

ランチャーの作りに合わせて、ツール側で変えられるものは変えました(Start.vbs が引数を渡す)。
次はランチャー側の設定・作りの話です。

1. **exe を選んだ PC では、ポートを空にし、画面を「アプリ」にしてください。** `config/app.json` には
   ブラウザ版のポート(8740)が書いてあり、exe を参照で選ぶとこのポートが入ります。すると exe をブラウザー
   の画面のツールとして扱い、`/api/health` を待ち続けます(デスクトップ版はポートを持たない)
2. **終了は `launcher_stop.bat`(止め方: stop.bat)にしてください。** 既定の「窓を閉じる」では、ツールの
   「終了します。よろしいですか」が窓に出て、利用者が押すまで止まりません
3. **終了口・確認口の戻り値を見てください。** 1.6.4 は stop.bat の戻り値を使わず、30秒待ってから次へ進みます。
   処理中で止めなかったとき(戻り値 1)は、利用者に「処理中です。中断しますか」を出して `--force` で
   呼び直すのが要件 11(切り替え)に合います
4. ランチャーを動かす Python と、ツールを動かす Python は同じもの(PATH の `python`)にしてください。
   Microsoft Store の Python は `%LOCALAPPDATA%` の下のファイルを Python ごとの場所に置き換えるため、
   別の Python から見ると、ツールの印(終了用のトークンなど)が見えないことがあります。
   終了口・確認口はツールの Python で動くので、これを使えば影響を受けません

## 確かめきれていないこと

- Windows の実機で、業務ツール統合ランチャーの本体から起動・切り替え・終了すること
- Windows の自動試験(GitHub Actions)は請求の問題で止まっていて、exe はまだ作られていません
